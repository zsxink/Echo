# Echo 总体规划

> 状态：规划中  
> 更新时间：2026-08-28

## 目标

Echo 按“桌面本地体验 → 资料库同步 → Android → iOS”的顺序演进。每一阶段都应交付一个可独立使用、可验证的版本；后续阶段复用既有的 Rust Core、资料库模型和同步协议，而不重写播放器核心。

## 阶段总览

| 阶段 | 主题 | 主要交付 | 完成标志 |
|---|---|---|---|
| 一期 | 完整桌面版播放器 | macOS、Windows、Linux 上可日常使用的本地音乐播放器 | 可稳定导入、管理、搜索和播放本地曲库 |
| 二期 | 资料库同步 | S3 兼容的多设备资料库同步能力 | 两台桌面设备可可靠同步同一资料库 |
| 三期 | Android | Android 原生体验与既有资料库同步 | Android 可完整管理、播放并同步资料库 |
| 四期 | iOS | iOS 原生体验与既有资料库同步 | iOS 可完整管理、播放并同步资料库 |

## 一期：完整桌面版播放器

### 范围

- 支持 macOS、Windows、Linux。
- 选择并扫描本地音乐资料库根目录，解析歌曲标签、封面与歌词；不复制或移动用户原始文件。
- 通过导入按钮将新歌曲复制入资料库，并按默认的 `歌手/歌手 - 歌曲名.扩展名` 规则组织文件。
- 监控资料库目录变化，提供手动重新扫描；资料库根目录不可用时清晰提示并暂停相关操作。
- 安全导入与文件关联：重名且内容相同则不重复导入，重名但内容不同则自动追加编号且绝不覆盖已有文件；文件移动或改名后仍保留歌曲 UUID。
- 支持从系统文件管理器双击音频文件直接播放；资料库外文件以临时播放方式打开，不加入资料库、不计入同步。
- 为一期后的歌曲编辑固化数据规则：仅保存到 Echo 使用覆盖层；写回歌曲文件会更新内嵌元数据并清除对应覆盖层。
- 曲库浏览、搜索、排序、收藏、播放列表与歌单 CRUD。
- 稳定的播放队列、播放控制、进度、音量和快捷键。
- 沉浸式黑胶播放器、歌词显示与无歌词状态。
- 主题、窗口布局和本机偏好设置。

### 不包含

- 资料库同步与可操作的同步入口。
- 全选及批量操作。
- Android 与 iOS 客户端。

### 验收标准

用户可在任一支持的桌面系统中完成“导入或扫描音乐 → 搜索或浏览 → 播放 → 建立歌单 → 下次启动继续使用”的完整日常流程，且不依赖网络或账号；资料库外音乐可由系统双击直接临时播放，不会被加入资料库。

## 二期：资料库同步（S3 兼容）

### 范围

- 接入 S3 兼容对象存储，作为一份资料库的单一远端汇聚点。
- 同步歌曲记录、封面、歌词、覆盖层、收藏状态、歌单、删除墓碑和必要的同步元数据。
- 支持首次全量同步与后续增量同步；播放前确保歌曲文件已在本地。
- 提供同步状态、错误反馈、重试和冲突处理。
- 以全文件 BLAKE3 哈希识别歌曲，以版本号和墓碑传播修改与删除。

### 不包含

- 流式播放或“仅下载元数据、按需拉取歌曲”。
- 多个远端同时双写。
- 平台客户端的独立同步实现；同步规则必须由 Rust Core 统一提供。

### 验收标准

两台桌面设备连接同一远端后，任一设备对资料库、歌单、收藏或删除的修改均能在另一设备可靠可见；冲突、失败和同步进度对用户清晰可见。

## 三期：Android 版本

### 范围

- 以 Flutter 构建 Android 客户端，复用 Rust Core 和二期同步协议。
- 支持曲库、搜索、歌单、收藏、封面、歌词和本地播放。
- 使用 media_kit 提供播放能力，并适配通知栏、锁屏控制与后台播放。
- 支持 S3 兼容资料库的首次同步、增量同步和离线播放。

### 验收标准

Android 用户可连接既有资料库，在移动场景中稳定同步、浏览和播放，并与桌面端保持资料库一致。

## 四期：iOS 版本

### 范围

- 以 Flutter 构建 iOS 客户端，复用 Rust Core 和既有同步协议。
- 对齐 Android 与桌面端的曲库、歌单、收藏、歌词和播放核心体验。
- 适配 iOS 的媒体权限、后台播放、锁屏控制与系统音频会话。
- 支持 S3 兼容资料库的同步和离线播放。

### 验收标准

iOS 用户可连接同一资料库并完成稳定的同步、管理和播放；跨桌面、Android、iOS 的资料库数据保持一致。

## 跨阶段约束

- Rust Core 负责资料库、导入、索引和同步；不依赖 UI 或音频播放器。
- 本地资料库使用 SQLite；跨设备同步传输 JSON 变更记录和媒体文件，不同步 SQLite 数据库文件本身。
- 音频播放保持平台适配：桌面使用 mpv / libmpv，移动端使用 media_kit。
- 同步协议、数据模型与对象格式由二期建立，并作为三、四期的唯一实现依据。
- 每期开始前确认范围、验收标准和回归测试；未完成当前阶段的验收，不进入下一阶段。

## 一期后的待立项功能

- 可配置导入文件名与目录格式。
- 新增文件目录视图，用于按资料库中的实际目录结构浏览歌曲。
- 歌曲编辑：在资料库根目录内移动歌曲，并编辑写回音频文件内嵌的歌词、封面和元数据；移动保持歌曲 UUID 不变，写回后重新扫描并更新哈希。
