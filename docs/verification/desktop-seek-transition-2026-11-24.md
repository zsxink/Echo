# 桌面播放中定位过渡 — 真实输出采集验收

> 变更：`openspec/changes/archive/2026-11-24-smooth-desktop-seek-transition`（issue #102）
> 日期：2026-11-24
> 机器：MacBook Pro（Apple Silicon），macOS 27.2.1（26B131）
> 输出：内建扬声器 `BuiltInSpeakerDevice`，48 kHz，系统输出音量 20%

## 1. 结论

在真实 CoreAudio 输出上用进程 tap 采集 PCM 后，播放中定位的相邻采样跳变由基线的
**0.066–0.223**（占 25% FS 正弦峰值的 26%–84%）降到 **0.022–0.024**（9%–10%），
与同一段连续音的自然斜率 **0.014–0.015**（5.7%–6.0%）同一量级。定位保护确实
作用于实际输出，而不是只体现在属性写入回执上。

这个结果同时否掉了原设计里"每侧约 10 ms"的初始值：libmpv 0.36.0 的独立软增益
`replaygain-fallback` 不是逐采样生效，而是按渲染音频帧（48 kHz 下约 10 ms）落地。
12 ms 的等功率淡变在输出上退化成**一次约 -49 dB 的阶跃**，单次定位的最大跳变反而
达到 0.10（40%），比不修还差。改为 **120 ms 线性幅度**淡变（每步约 1/12 满幅）并把
`replaygain-fallback` 保持在底噪 50 ms 后才提交定位，才得到上表的结果。实现对每个
定位入口一致，代价是单次定位在提交前多约 170 ms 的衰减等待（见 §5）。

本记录是数字采集证据，不是听感验收；它证明跳变幅度与次序，不替代人耳判断。

## 2. 被测对象与环境

| 项 | 值 |
| --- | --- |
| libmpv | 仓库随附 0.36.0 / FFmpeg 6.0，`apps/desktop/src-tauri/vendor/libmpv/macos/libmpv.dylib`，SHA256 `536cc29610c2cb105671fa92a5dfac00a483f534899c5f5884b1cd55ca4d855d` |
| 播放路径 | 生产 `PlayerActor::spawn_mpv` + `MpvBackend`，命令走 `PlayerCommand::LoadTemporary/Seek/Pause/SetMute/Play` |
| 音频输出 | `ao=coreaudio`（默认），内建扬声器，48 kHz 立体声 |
| 采集 | CoreAudio 进程 tap（`AudioHardwareCreateProcessTap`，stereo global tap，`muteBehavior=unmuted`，私有聚合设备，扬声器作为时钟子设备），512 帧/回调，32-bit float WAV |
| 源 | 437 Hz、48 kHz、16-bit、25% 满量程正弦，60 s；换曲用 523 Hz / 20 s，同幅度 |
| 基线 | `main`（94ac49cd）同一 harness、同一 libmpv、同一输出设备 |
| 修复 | 本分支（`FADE=120 ms` 线性幅度、`FLOOR_HOLD=50 ms`） |

tap 取的是送往设备的混音（早于系统音量），因此采集幅度等于源幅度；两次不同系统
音量的探测给出相同峰值，确认这一点。

## 3. 方法

1. 用 tap 工具同步采集默认输出，同时由 harness 拉起真实 `PlayerActor` 播放正弦源。
2. 依次执行：连续 2 s → 5 次分隔 1.5 s 的单次定位（5/12/20/30/45 s）→ 5 次间隔
   150 ms 的连续定位（15/25/35/45/55 s）→ 暂停后定位并恢复 → 静音后定位并取消静音
   → 定位后立即换曲 → 定位到曲尾。
3. 每个事件用壁钟时间戳对齐采集时间轴（误差 <1 个 tap 缓冲，约 11 ms）。
4. 指标：每声道相邻采样差 `max|x[n+1]-x[n]|`，除以该窗口峰值；另记录低于连续音
   3 dB 的持续时间（整段淡变）与低于 30 dB 的持续时间（底噪段）。
5. 同一 harness 在 `main` 上重跑作为修前对照；两文件都包含连续音与静音段。

采集偶尔出现单采样尖刺（例如 12.292 s 处 0.191、紧邻两侧各约 0.035），这是 tap
侧的缓冲拼接伪迹：基线文件同样出现，且事件窗口内不复现。下表按事件窗口取最大值，
不把这个尖刺算作播放器输出。

## 4. 结果

### 4.1 定位跳变（`max adjacent delta` / 该窗口峰值）

| 场景 | 修前 | 修后 |
| --- | --- | --- |
| 连续音（无定位） | 0.0143（5.7%） | 0.0150（6.0%） |
| 单次定位 ×5 | 0.066 / 0.210 / 0.210 / 0.223 / 0.209 | 0.0226 / 0.0239 / 0.0223 / 0.0240 / 0.0231 |
| 连续 5 次定位 | 0.115–0.223 | 0.0219–0.0229 |
| 定位到曲尾（随后结束） | 0.119 | 0.0237 |
| 暂停中定位 | 0（无输出） | 0（无输出，仍未恢复播放） |
| 静音中定位 | 0（无输出） | 0（无输出，取消静音后无残留衰减） |
| 定位后立即换曲 | 0.066（新曲起播） | 0.066（新曲起播，无衰减） |
| 取消静音 | 0.211 | 0.090 |

单次定位的修后最大值 0.0240 是 25% FS 正弦的 9.6%，是连续音自然斜率的 1.6 倍；
修前同场景最差 0.223 是峰值的 84%。快速定位在修后只保留一次淡变，最大跳变不再
随定位次数上升。

### 4.2 过渡时序（修后）

- 淡出：请求后 120 ms 内以约 10 ms 步进降到 -96 dB；随后保持底噪 50 ms 再提交
  定位（覆盖实测约 40 ms 的命令→可听延迟）。
- 淡入：`PLAYBACK_RESTART` 后 120 ms 回到 0 dB。
- 可听衰减窗口（低于连续音 3 dB）：单次定位 0.30–0.32 s；连续定位合并后
  0.26–0.35 s。
- 底噪窗口（低于连续音 30 dB）：0.05–0.07 s。

### 4.3 未改变的行为

暂停中定位保持暂停（采集窗口无输出，恢复后音量正常）；静音中定位无输出，取消
静音后输出立即为满幅；曲目结束时快照为 `Ended`，没有遗留衰减；换曲后新曲从满幅
开始，没有继承旧曲的过渡。取消静音与换曲起播的硬阶跃属于非目标（不为暂停/停止/
换曲单独加淡变）。

## 5. 取舍与限制

- **延迟**：单次定位在淡出与底噪保持上多出约 170 ms 才提交 seek；定位后的快照
  位置也在那时才更新。快速连续定位只保留最后一个目标，不累积这段等待。
- **步进来源**：120 ms 是对帧量化粒度的折中。若要进一步压低单步，只能继续拉长
  淡变或改用逐采样淡变；后者在当前固定 libmpv（lavfi 只编译了 aformat/volume/
  alimiter/equalizer/extrastereo，未包含 afade）中不可用，自写 DSP 超出本变更范围。
- **设备差异**：结论来自一台机器、一个内建输出设备、48 kHz。其他设备/采样率/缓冲
  大小需要重跑同一 harness；命令→可听延迟若显著更大，`FLOOR_HOLD` 需要相应调整。
- **不是听感验收**：本记录只证明采样级跳变与过渡次序；听感结论仍需人耳在真实
  扬声器/耳机上确认。

## 6. 复现要点

- 采集：默认输出上的 `CATapDescription(stereoGlobalTapButExcludeProcesses: [])`，
  `isPrivate=true`、`muteBehavior=.unmuted`；聚合设备加入 tap 与输出设备的 UID
  （设备作时钟），`kAudioAggregateDeviceTapAutoStartKey=true`；IOProc 将 512 帧
  32-bit float 追加到 WAV。
- 驱动：`cargo test -p echo-desktop --test <harness> -- --nocapture --test-threads=1`，
  环境变量给出 vendored `libmpv.dylib`、两个正弦源、采集工具与输出路径。
- 对齐：采集首回调的 Unix ms 与 harness 的 `MARK <unix_ms> <event>` 对齐；窗口
  取事件前 50 ms 到事件后 0.6 s。
- 分析：逐声道相邻差的最大值除以窗口峰值；连续音窗口取首事件前 2 s。
