## Platform

桌面优先的跨平台应用：macOS、Windows、Linux；后续扩展 Android、iOS。

## Users

个人用户在桌面端整理、检索和播放自己的本地音乐；需要在专注工作、通勤准备或居家聆听时快速切换曲目与歌单。

## Product Purpose

Echo 是一个本地优先的音乐播放器：扫描并管理用户指定的本地音乐资料库、展示封面与歌词、维护播放列表和歌单，并通过 S3 或 WebDAV 在个人设备间同步。

## Positioning

不依赖账号或流媒体目录。音乐文件与元数据以本地资料库为中心，远端只承担个人设备间的可替换同步汇聚。

## Operating Context

- 桌面优先：macOS、Windows、Linux（Tauri 2 + React + TypeScript + Vite）。
- 一期日常流程：选择并扫描音乐资料库、通过导入按钮加入新歌曲、搜索与浏览曲库、排序、加入播放列表、沉浸式播放、创建歌单。
- 桌面端支持常驻运行：macOS 提供菜单栏状态项，Windows 与 Linux 提供系统托盘入口；即使主窗口关闭，用户仍可通过该入口查看播放状态、控制播放、显示主窗口或退出应用。
- 二期再接入同步与全选；同步入口在二期前不实现为可操作功能。
- 共享业务逻辑使用 Rust；桌面播放使用 mpv，核心逻辑不负责音频播放。
- 移动端后续使用 Flutter + media_kit，并通过 flutter_rust_bridge 调用 Rust Core。

## Capabilities and Constraints

- 用户选择本地音乐资料库根目录后，Echo 扫描其中的音乐文件，不复制或移动用户的原始文件。每首歌曲在 Echo 内部拥有稳定 UUID，并以“资料库根目录 + 相对路径”定位实际播放文件；歌单和播放队列只引用歌曲 UUID。
- Echo 持续监听资料库根目录的新增、删除、移动和文件修改，并提供手动重新扫描入口。根目录断开、权限失效或不可访问时，保留已有资料库记录但明确标示“资料库不可用”，暂停扫描、导入和涉及该根目录的播放。
- Echo 在本机使用 SQLite 保存资料库记录、索引、歌单、覆盖层和同步状态；音频及 `.lrc` 文件仍保存在用户选择的资料库根目录中。S3 同步传输逻辑变更与媒体文件，不直接同步 SQLite 数据库文件。
- 一期导入按钮默认将用户选中的音频文件**复制**到资料库根目录。Echo 解析歌曲标签后，按 `歌手/歌手 - 歌曲名.扩展名` 组织文件；例如 `周杰伦/周杰伦 - 晴天.flac`。若存在同目录、同基础文件名的 `.lrc` 文件，也一并复制并使用相同的目标基础文件名。标签缺少歌手或歌名时，使用明确的兜底名称。目标位置已有相同内容（BLAKE3 相同）时，不重复导入；文件名相同但内容不同则自动追加编号，如 `周杰伦 - 晴天 (2).flac`，且绝不覆盖已有文件。
- 导入先复制到资料库内的临时文件，完成解析与校验后再原子移动到目标位置，并将 SQLite 更新作为可恢复操作提交；任一步失败均不创建歌曲记录，启动时清理或恢复未完成的导入。
- 封面、歌词与元数据覆盖层不改写原始文件；展示与播放时，覆盖层优先于文件内嵌数据和扫描解析结果。
- 收藏状态属于歌曲资料的一部分，必须与歌曲记录一起跨设备同步；“喜欢的音乐”是该状态的资料库视图。
- 一份资料库只绑定一个远端：S3 或 WebDAV。
- 首次同步全量下载，之后增量同步；播放前保证歌曲文件已在本地。
- 一期的“全部歌曲”排序与原型一致：最近添加、歌曲名称、艺人、播放次数。全选及其批量操作放入二期后另行定义。
- 当前原型不定义歌单手动排序交互；歌单内歌曲按追加顺序。
- 自定义导入文件名与目录格式、文件目录视图、歌曲文件移动及内嵌元数据编辑均不属于一期范围，留待后续版本立项。
- 主题以原型为准：珊瑚玫红（默认）、深钴蓝、松石绿，并记住用户选择。
- 设置提供“关闭主窗口时”的行为选择：退出应用，或保持在后台运行。默认行为应符合所在操作系统的用户习惯；该选择保存在本机偏好中。
- 扫描歌曲时优先解析音频文件内嵌的封面与歌词；若不存在内嵌歌词，再读取与音频文件同目录、同基础文件名的 `.lrc` 文件。歌词展示优先级为：用户编辑的覆盖层歌词、内嵌歌词、同名 `.lrc` 文件。
- 一期后的歌曲编辑提供两种明确模式：“仅保存到 Echo”写入覆盖层；“写回歌曲文件”显式修改内嵌封面、歌词或元数据，并在成功后清除对应字段的覆盖层、重新扫描并更新哈希。外部程序修改文件时，扫描会更新内嵌数据，但仍不覆盖用户尚存的 Echo 覆盖层。歌曲在资料库根目录内移动时，同名 `.lrc` 侧车文件随之移动并重命名；移动后更新相对路径但保留歌曲 UUID，因此歌单与播放队列引用不失效。
- 支持将 Echo 设为已支持音频格式的默认打开应用。用户从系统文件管理器双击资料库外文件时，Echo 创建仅存在于当前会话的临时播放项：可解析内嵌封面、歌词和同名 `.lrc`，但不写入 SQLite、歌单、播放统计或同步队列；已在资料库中的文件仍使用其现有歌曲 UUID 播放。
- 歌词以原型为准：支持沉浸式歌词、当前行随播放进度定位、歌词专注阅读和无歌词空状态。
- 窄屏以原型为准：侧边栏可开合并显示遮罩；主题、排序、歌曲操作菜单与播放队列支持点击外部和 Escape 关闭，沉浸式播放器使用收起按钮或 Escape 关闭。

## Brand Commitments

- 产品名：Echo。
- 桌面原型需兼顾沉浸式黑胶播放体验与高效率曲库管理。
- 当前原型路径：`docs/prototype/echo-desktop-player.html`。

## Technical Direction

- Rust Core 负责资料库、导入、标签解析、索引、同步与冲突裁决；不得依赖 UI 或播放器。
- 桌面 UI 采用 Tauri 2 + React + TypeScript + Vite；用 Tauri commands / events 与 Rust 适配层通信。
- 播放按平台替换：桌面 mpv / libmpv，移动 media_kit；播放队列和设备播放状态不进入 Core。
- S3 与 WebDAV 是同步层的可替换连接器；Core 依赖连接器抽象而非具体协议。

## Product Principles

1. 资料库优先于账号与推荐流。
2. 播放控制始终可达，沉浸模式不牺牲基本操作。
3. 同步状态必须清楚且不打断聆听。
4. 封面与歌曲信息服务于辨识，不替代高效检索。
