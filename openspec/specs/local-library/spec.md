# local-library Specification

## Purpose
为 Echo 提供一个无需账号或网络即可使用的本地音乐资料库，使用户能够选择单一根目录、发现并检索音乐，同时在文件变化、权限变化和应用重启后保持歌曲身份与关联稳定。

## Requirements

### Requirement: 单一资料库根目录与本地持久化

系统 MUST 允许用户选择一个活动资料库根目录，保存稳定的根目录逻辑 ID、歌曲身份与相对路径；同一时刻只有一个活动根。应用数据目录中的 SQLite MUST 仅为可重建投影；受管资料库的 `echo/` MUST 保存可靠提交的对象及必要恢复资料，并与实际媒体共同构成持久事实来源。本机绝对路径、数据库文件与凭据 MUST NOT 进入音乐库对象/恢复载荷或远端共享资料。

本机数据库丢失、清空、损坏或投影属于另一库时，系统 MUST 以新目录提交协议已提交的对象为准重建歌曲、喜欢、歌单及成员顺序、覆盖层和统计投影，并保留原 UUID。读取受支持的旧格式时保持兼容，不要求救援或回填旧库资料，也不自动修复其中的历史身份或关系。恢复不移动或改写用户媒体；新协议所需的控制面恢复、journal 重放及索引更新遵守目录持久协议。

#### Scenario: 选择根目录并建立资料库
- **WHEN** 用户选择一个可读目录作为资料库根目录
- **THEN** 系统读取或建立稳定库身份，再按格式和可写能力恢复/扫描；重启保留 UUID，目录只读时允许浏览/播放可验证媒体并禁用导入、删除、喜欢/歌单及其他用户资料写入

#### Scenario: 安全切换活动根目录
- **WHEN** 已存在可用活动根而用户选择另一目录
- **THEN** 系统先验证并恢复候选目录，建立可用投影后才激活，保留旧库文件与逻辑记录及其独立上下文，重新选择时复用该库稳定身份

#### Scenario: 切换根目录失败
- **WHEN** 候选目录验证、迁移或首次扫描不能建立可用资料库
- **THEN** 系统继续使用此前活动目录及可用视图，恢复旧同步上下文或明确报告可恢复状态，不用失败配置覆盖原配置

#### Scenario: 本机数据库丢失后重新选择同一目录
- **WHEN** 应用数据被清除或系统重装后，用户离线重新选择原完整资料库
- **THEN** 系统从该目录恢复原歌曲标识、喜欢、歌单及成员顺序、覆盖层和统计，不重新导入、不移动改写用户媒体、不依赖同步主机或旧数据库

### Requirement: 扫描、监听与手动重扫

系统 MUST 扫描 `media/` 及其子目录中的一期支持音频格式，解析每个文件并建立或更新记录；运行期间 MUST 监听新增、删除、移动和修改，并在设置页提供可重复执行的手动重新扫描入口。扫描 MUST 忽略资料库根目录中 `media/` 以外的所有内容，包括 `echo/`（及 `echo/tmp/`）；扫描结果 MUST 可报告已发现、已更新、已删除、跳过和失败的数量及错误原因。手动扫描进行期间，入口 MUST 禁止重复触发并明确显示进行中状态；扫描成功后，已挂载的歌曲列表、导航计数、封面和当前歌曲歌词 MUST 能读取本次扫描提交的权威结果。

#### Scenario: 首次扫描发现支持文件

- **WHEN** 用户确认具有 `media/` 的根目录并触发首次扫描
- **THEN** 系统仅递归发现 `media/` 下的支持格式文件，逐文件解析并持久化歌曲记录，扫描完成后可在曲库检索这些歌曲

#### Scenario: 忽略不支持文件

- **WHEN** 根目录包含图片、文档或未列入一期格式矩阵的文件
- **THEN** 系统不创建歌曲记录，不移动或修改该文件，并在扫描结果中将其作为跳过项而非失败歌曲

#### Scenario: 忽略控制面目录

- **WHEN** 根目录包含 `echo/`（包括 `echo/tmp/`）及其任何内容
- **THEN** 系统不将控制面或暂存内容创建为歌曲记录，也不移动或修改其文件

#### Scenario: 不兼容旧资料库布局

- **WHEN** 用户选择的目录只包含旧布局的根目录艺人文件夹且不存在可扫描的 `media/`
- **THEN** 系统明确要求用户建立新的资料库或重新导入媒体，不扫描旧布局、不迁移歌曲 UUID 且不创建旧路径歌曲记录

#### Scenario: 监听外部新增和修改

- **WHEN** 资料库运行中新增支持音频、删除音频、移动音频或修改音频内容
- **THEN** 系统在监听事件稳定后更新对应记录和搜索索引；事件丢失或无法确定变化时，用户可通过设置页的手动重扫得到同样的最终状态

#### Scenario: 从设置页手动重新扫描

- **WHEN** 用户在已配置资料库的设置页点击“重新扫描”
- **THEN** 系统重新检查活动资料库，按钮进入进行中状态并禁止重复点击；扫描完成后歌曲列表、导航计数、封面和当前歌曲歌词反映本次扫描提交的结果，扫描失败时保留既有内容并显示可重试提示

#### Scenario: 没有活动资料库时不能重扫

- **WHEN** 当前没有活动资料库，或资料库扫描已在进行中
- **THEN** 设置页的“重新扫描”入口处于禁用状态，不发起新的扫描请求

### Requirement: 一期格式与内容解析矩阵

系统 MUST 保证支持 MP3 (`.mp3`)、FLAC (`.flac`)、Monkey's Audio (`.ape`)、MP4 音频 (`.m4a` 以及经内容探测确认有音轨的 `.mp4`)、Ogg Vorbis (`.ogg`)、Opus (`.opus`) 和 WAV (`.wav`)，并对无法解析、无音轨或损坏的文件保留可诊断失败结果而不中断整次扫描。系统 MUST 解析并保留内嵌歌词与同目录同基础文件名 `.lrc` 两类候选，展示时选择优先级最高的有效来源。

`.m4a`（MP4 容器内嵌标签）与 `.wav`（PCM，通常无标签）MUST 与其它格式经同一解析管线处理：可读取的内嵌标题、艺人、专辑、时长与参数 MUST 被持久化；无标签或标签空白时，MUST 使用与其它格式一致的兜底语义（导入侧为「未知艺人」/「未命名歌曲」，扫描侧为合理的缺省展示），不得单独对 `.wav` 或 `.m4a` 引入特殊分支。

#### Scenario: 解析内嵌数据
- **WHEN** 支持格式文件包含标题、艺人、专辑、时长、内嵌封面或内嵌歌词
- **THEN** 系统将可读取字段展示并持久化，歌词来源标记为内嵌；同名 `.lrc` 可作为较低优先级候选被解析，但不得覆盖有效内嵌歌词

#### Scenario: 解析同名 LRC 侧车
- **WHEN** 音频没有内嵌歌词且同目录存在与音频基础名相同的 `.lrc`（扩展名大小写不敏感）
- **THEN** 系统读取该歌词并将来源标记为侧车；有文本但无有效时间轴时作为纯文本歌词展示，不存在、无法读取或没有可读文本时显示无歌词状态并保留可诊断原因

#### Scenario: 文件损坏或标签异常
- **WHEN** 文件扩展名受支持但容器损坏、权限不足或标签无法解码
- **THEN** 系统不因该文件中止其他文件扫描，保留文件路径和失败状态，并向用户报告可重试的错误

#### Scenario: m4a 内嵌标签解析
- **WHEN** 扫描或导入一个带内嵌标签的 `.m4a`（MP4/AAC 音频）
- **THEN** 系统读取并持久化其标题、艺人、专辑与音频参数，`format` 判定为 MP4 音频，时长由探测提供；解析结果与其它格式沿同一管线，无 m4a 专属分支

#### Scenario: wav 无标签兜底
- **WHEN** 扫描或导入一个无内嵌标签的 `.wav`
- **THEN** 系统仍建立可用的歌曲记录，`format` 判定为 WAV，缺少的标题/艺人按既有兜底语义展示，歌曲可正常检索与播放，且该行为对 `.wav` 与其它无标签格式一致

### Requirement: 稳定身份、哈希与路径重关联

每首歌曲 MUST 获得稳定 UUID；歌单、收藏和播放队列等关联只能引用 UUID。系统 MUST 计算并缓存全文件 BLAKE3 哈希，以内容相同判定重复，并在原路径消失、新路径哈希相同的情况下更新相对路径而保留 UUID；哈希改变时 MUST 重新解析并更新记录。

#### Scenario: 原地重扫保持身份
- **WHEN** 同一音频文件内容未变且其相对路径未变，用户执行重扫或应用重启
- **THEN** 系统复用原歌曲 UUID，不创建重复记录，已有收藏和关联继续有效

#### Scenario: 移动或改名后重关联
- **WHEN** 原相对路径不再存在，且根目录内另一文件的 BLAKE3 与原记录相同
- **THEN** 系统只更新该 UUID 的相对路径和索引，不创建第二条歌曲，不改变收藏、歌单或队列引用

#### Scenario: 相同内容出现在两个路径
- **WHEN** 扫描发现两个不同路径的文件具有相同 BLAKE3
- **THEN** 系统只保留一个歌曲逻辑记录，以规范路径键最小的可用路径作为确定性主路径并报告其他重复路径；主路径消失时从剩余同 hash 路径中按同一规则提升新主路径并保留 UUID

#### Scenario: 唯一音乐键弱重关联
- **WHEN** 原路径缺失且新文件 hash 已变化，但同一根目录内只有一个缺失记录与一个新文件具有相同标准化艺人、专辑、标题且时长误差不超过 2 秒
- **THEN** 系统可保守地更新原 UUID；若任一侧存在多个候选或匹配有歧义，则不得自动合并，旧记录保持 missing 且新文件获得新 UUID

### Requirement: SQLite 检索与曲库排序

系统 MUST 将歌曲、根目录、覆盖层和必要的删除状态持久化到本机 SQLite，并在单次记录更新中保持关联一致。标题、艺人和专辑搜索 MUST 支持不区分大小写的部分匹配；“全部歌曲” MUST 支持最近添加、歌曲名称、艺人和播放次数四种排序，并对相同值使用稳定的 UUID/路径次序作为确定性次序。

#### Scenario: 搜索并排序
- **WHEN** 用户输入标题、艺人或专辑的一部分并选择任一一期排序方式
- **THEN** 系统仅返回匹配歌曲并按所选规则排序；清空搜索后恢复完整曲库

#### Scenario: 重启后数据可用
- **WHEN** 应用退出后重新启动且资料库根目录可访问
- **THEN** 系统从 SQLite 恢复歌曲、收藏、覆盖层和关联，用户无需重新导入即可搜索和播放

### Requirement: 生效元数据、封面和歌词优先级

系统 MUST 使用 Echo 覆盖层优先于内嵌数据、内嵌数据优先于侧车数据的生效值规则；外部文件变化重新扫描时不得清除已存在的覆盖层。0.1.0 只建立兼容该规则的数据与读取语义，不得提供创建、编辑、清除或写回覆盖层的用户入口。

#### Scenario: 覆盖层优先展示
- **WHEN** 数据迁移或未来兼容数据使同一字段同时存在覆盖值、内嵌值和侧车值
- **THEN** 系统展示用户覆盖值；没有覆盖值时按内嵌优先、侧车其次的顺序展示

#### Scenario: 外部修改不覆盖用户值
- **WHEN** 外部程序修改音频标签或同名 LRC，且 Echo 已有该字段覆盖层
- **THEN** 系统更新底层解析值和哈希，但继续展示原覆盖值且不自动清除；0.1.0 不显示歌曲编辑或写回入口

### Requirement: 资料库不可用与删除恢复

根目录断开、权限失效或不可访问时，系统 MUST 保留已有记录并明确显示“资料库不可用”，暂停扫描、导入和涉及该根目录的播放；恢复访问后 MUST 允许重试扫描。文件被删除时，系统 MUST 将歌曲标记为不可用/已删除而非立即丢失 UUID 和关联，并提供可恢复的删除行为；恢复文件后重扫应恢复可用状态。非 `Available` 的歌曲记录可以继续为删除恢复、歌单关联和诊断提供持久事实，但 MUST NOT 阻塞新导入的重复判断或目标路径选择。

#### Scenario: 根目录不可用
- **WHEN** 根目录不存在、磁盘未挂载或当前用户无读取权限
- **THEN** 系统显示资料库不可用状态，禁止扫描、导入和播放该库文件，保留歌曲记录与歌单成员，并提供重试入口

#### Scenario: 删除歌曲后关联可见
- **WHEN** 用户在文件管理器删除已收录歌曲并触发监听或重扫
- **THEN** 系统将歌曲标记为不可用/已删除，曲库明确显示状态，歌单和队列保留 UUID 但不能播放，不创建新 UUID

#### Scenario: 删除歌曲后可重新导入
- **WHEN** 用户通过 Echo 删除歌曲，删除记录仍处于 `PendingDelete` 或已标记为其他非 `Available` 状态，随后导入相同内容的文件
- **THEN** 导入不把旧记录判定为重复，且以新歌曲记录入库；旧记录继续保留其删除恢复语义

#### Scenario: 文件恢复
- **WHEN** 同一 UUID 的原文件恢复，或根目录内出现与其 BLAKE3 相同的文件并完成重扫
- **THEN** 系统恢复歌曲可用状态并更新相对路径，原有收藏、歌单和队列继续有效

### Requirement: 跨平台路径、隐私与性能约束

系统 MUST 在 macOS、Windows 和 Linux 正确处理各自路径分隔符、大小写规则、Unicode 文件名、符号链接边界和权限错误；内部及跨层引用使用规范化相对路径，绝不把根目录绝对路径写入歌曲关联或用户可同步数据。首次扫描和大曲库重扫 MUST 以受控后台任务执行、可报告进度且不阻塞播放/界面，重复事件 MUST 幂等。

#### Scenario: Unicode 和平台路径
- **WHEN** 根目录或文件名包含中文、日文、emoji、Windows 盘符或 Unix 分隔符
- **THEN** 系统按当前平台规范化并正确保存、检索和播放相对路径，重启后路径不变且不产生重复记录

#### Scenario: 扫描期间继续使用界面
- **WHEN** 根目录包含大量文件并正在首次扫描或重扫
- **THEN** 系统显示可更新进度和错误计数，界面仍可响应，已完成的歌曲可逐步查询，取消或失败不会留下半提交记录

#### Scenario: 不泄露本机路径
- **WHEN** 系统记录诊断日志或导出跨层歌曲数据
- **THEN** 日志和数据仅使用资料库逻辑 ID、相对路径或脱敏错误上下文，不包含完整绝对路径、文件内容或凭据

### Requirement: 导入事实时间真实性与时区呈现
系统 MUST 使用既有歌曲添加时间记录首次成功导入的真实系统时刻，供“最近添加”等读取语义使用；该时间由后端在提交边界生成，不得由 WebView 伪造或在后续扫描、重复导入时重置。持久化值 MUST 表示无歧义的绝对时刻；当该时间出现在界面、诊断或导出结果中时，系统 SHALL 按读取时设备的当前系统时区转换，不得把 UTC 数值直接当作本地墙钟时间。

#### Scenario: 真实导入时间
- **WHEN** 一首新歌成功完成导入并写入资料库
- **THEN** 其既有添加时间字段表示该次提交的真实系统时刻，重启后仍保持不变，且不创建同义的第二套导入时间字段

#### Scenario: 重复或重扫不改写时间
- **WHEN** 已导入歌曲被重复选择导入或被后续扫描重新发现
- **THEN** 系统保留其原始导入时间，不将其移动到最近添加列表的首位

#### Scenario: 当前时区转换
- **WHEN** 系统在一个非 UTC 时区读取或展示已记录的导入时间
- **THEN** 所得到的本地日期和时间与该绝对时刻在设备当前系统时区中的表示一致，切换时区后绝对时刻不变

### Requirement: 扫描与监听先保存资料库身份

扫描、监听和手动重扫 MUST 在发现新歌曲或改变已有歌曲的逻辑路径、哈希或元数据时，先把稳定 UUID、原入库时刻和必要业务字段可靠保存至音乐库，再更新 SQLite 投影；无变化扫描不得新建对象版本或候选。目录提交失败不得将数据库登记计为持久成功。已声明的同步受管版本仅按可信资源声明关联，扫描仍忽略控制面。外部文件缺失/卷不可用是本机可用性状态，不得因此产生最终删除墓碑。

#### Scenario: 首次扫描后重装
- **WHEN** 用户扫描已有 `media/` 音频并成功登记，随即清除应用数据后离线打开相同目录
- **THEN** 原歌曲 UUID、入库时刻和已提交元数据恢复，后续喜欢及成员仍关联原歌曲，不能只凭音频重新铸造身份

#### Scenario: 移动或标签修改后恢复
- **WHEN** 文件被移动或标签被修改，扫描成功保存了该业务变化，之后 SQLite 被移走
- **THEN** 系统恢复保存后的相对路径/哈希/元数据并保留原 UUID、喜欢、成员和原入库时刻

#### Scenario: 控制面写失败
- **WHEN** 扫描可读取新音频但无法把新歌曲身份可靠保存到 `echo/`
- **THEN** 该项显示未保存及原因，不能只在 SQLite 新建持久歌曲并报告扫描入库成功

#### Scenario: 只读库和无变化重扫
- **WHEN** 音乐库只读，或扫描未发现任何业务变化
- **THEN** 只读库只浏览已可验证资料，不创建新 UUID 或用户变更；无变化重扫不增加 revision、播放计数或同步候选

### Requirement: SQLite 投影可替换且不能独占用户数据

SQLite 正常时系统 SHALL 使用其检索与索引能力；损坏、丢失、错误库身份或无法证明的投影领先时 MUST 可从新协议目录已提交事实重建。重建范围不包括从旧 SQLite 救援或回填历史资料；恢复失败不得替换当前可用活动库；只读或部分恢复状态 MUST 可见。Core 与平台边界、顺序迁移及验证 MUST 遵守 `library-durability` LD-10。

#### Scenario: 数据库损坏
- **WHEN** 应用无法打开 SQLite，而音乐库已提交资料完整
- **THEN** 系统隔离损坏数据库并按原 UUID 与关系重建投影，离线可用；不要求用户重新导入或连接同步主机

#### Scenario: 切库恢复失败
- **WHEN** 候选库的升级或重建失败
- **THEN** 原活动库及同步上下文保持或恢复可用，候选库错误单独报告，不能把不完整投影设为当前成功库
