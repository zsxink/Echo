## Context

默认 `verify:perf` 将导入可见性、已保存反馈和歌单时延压在同一 3,000 首 Release 测试；p95 限制是可选配置。50k benchmark 是独立入口，不涉及本变更。

## Goals / Non-Goals

日常保留确定性的行为测试；在独立 GitHub Actions 环境时间测量，不将测量伪报成默认覆盖。不改变审计、coverage 或 50k。

## Decisions

- 默认 Linux workspace 测试覆盖三条场景的行为层：小真实音频导入、受控延迟投影的保存反馈与歌单增删持久性。导入项仅需要行为验证。其余两项保留明确的定时/手动递延状态。
- 单一入口执行 Release 1k 与 10k fixture，分别测收藏、歌单创建/添加/移除的命令时间、目录提交以及实际适用的投影：#152 后收藏成功正常路径为同步，歌单成员等仍为后台；不人为延迟正常收藏。命令 p95 严格小于 50 ms，不对独立异步投影套响应预算。
- 计时输出机器可读 JSON；失败保留诊断，但不以缺失、异常数据或任一规模失败通过。结构门禁反向测试遗漏、默认重新运行及错误递延。
