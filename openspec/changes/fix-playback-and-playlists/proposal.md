## Why

桌面端已有的播放会话、歌单和应用壳规格尚未被实现完整兑现：非沉浸播放栏会把随机模式错误渲染成主题强调色，播放位置未可靠保存，歌单选择器中的创建入口无效，关闭窗口后也不能按后台模式继续播放；部分界面还将产品名写为小写 `echo`。这些问题会直接破坏本地播放器最基本的连续聆听与组织体验。

## What Changes

- 修正非沉浸式常驻播放栏的播放模式视觉：随机播放不使用主题强调色，只有明确的选中/交互状态按既有主题规则显示。
- 使当前歌曲的播放进度与既有队列、音量、静音和播放模式一起持久化，并在下次启动恢复为暂停状态。
- 让“添加到歌单”选择器中的“新建歌单”入口能创建、刷新并选中新歌单，且沿用歌单创建的校验与失败保留行为。
- 完成关闭主窗口后的后台播放、菜单栏/系统托盘控制和退出路径，遵循平台默认关闭偏好。
- 统一桌面可见名称、窗口/托盘文字和打包元数据为 `Echo`。

### Modified Capabilities

- `desktop-playback`: 明确播放模式的非沉浸视觉语义，并确保当前播放位置在本地播放会话中保存和恢复。
- `playlist-management`: 要求歌曲的歌单选择器可从其新建入口完成歌单创建并继续添加流程。
- `desktop-app-shell`: 明确后台播放及其菜单栏/托盘控制的可交付行为，并统一应用可见名称为 `Echo`。

- 桌面 React 播放栏、播放器 store/会话持久化、歌单选择器与命名对话框，以及相应单元/E2E 测试。
- Tauri 桌面运行时、窗口关闭拦截、系统托盘/菜单栏和应用打包配置；不会变更 Rust Core 的资料库领域边界或远端同步协议。
