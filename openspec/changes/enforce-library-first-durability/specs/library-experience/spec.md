# library-experience Delta

## ADDED Requirements

### Requirement: 收藏与批量操作以音乐库持久结果为反馈

单曲收藏切换、批量收藏与取消收藏 MUST 在音乐库可靠提交喜欢 true/false 或类型化墓碑之后才更新可见状态；用户看到的“已保存”反馈 MUST 在目录提交确认后发生，不等待 SQLite 投影。待投影状态可在后台短暂存在，且应通过水位/状态诊断，不得让滞后 SQLite 查询覆盖已保存的界面状态。目录已保存而投影失败 MUST 保留同一操作身份供后台恢复，不得清空用户意图、回退为未收藏或诱导用户再次切换。目录提交本身失败 MUST 视为未保存：乐观更新回退到提交前状态并显示可重试原因。批量操作 MUST 沿现有逐项粒度报告，单项已保存待投影不得计为失败，也不得因其他项失败而回退。收藏与创建歌单从点击到已保存反馈在本变更指定的 macOS 桌面验收环境中 P95 MUST 小于 50 ms，并分别记录实际目录提交和投影延迟。

#### Scenario: 收藏已保存而投影失败
- **WHEN** 用户把歌曲设为喜欢，音乐库已提交而 SQLite 投影暂时失败
- **THEN** 界面显示该喜欢已保存且等待更新，保留同一操作身份，不把按钮回退为未收藏，也不要求用户重新点击

#### Scenario: 正常投影仍在后台时已保存反馈
- **WHEN** 用户收藏歌曲或创建歌单，目录提交已确认但 SQLite 后台投影尚未完成
- **THEN** 界面立即显示已保存结果并按需标示正在更新；点击到已保存反馈的 P95 小于 50 ms，后续投影完成不会再次改变用户意图

#### Scenario: 收藏未保存
- **WHEN** 音乐库控制面不可写或目录提交失败，而 SQLite 仍可写
- **THEN** 界面回退到提交前的收藏状态，显示可重试原因，且不产生仅存在于数据库的喜欢事实

#### Scenario: 批量收藏部分已保存
- **WHEN** 一次批量收藏中部分歌曲已提交到音乐库、部分失败
- **THEN** 已提交项保持喜欢状态并标注等待更新，失败项单独报告原因，成功项不因同批失败被回退

#### Scenario: 已保存待投影不被当作失败重试
- **WHEN** 用户对处于“已保存，等待更新”的收藏执行重试
- **THEN** 系统按原操作身份恢复投影，不创建第二个喜欢事实或新的事件身份
