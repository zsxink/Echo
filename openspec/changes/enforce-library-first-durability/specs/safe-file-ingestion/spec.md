# safe-file-ingestion Delta

## MODIFIED Requirements

### Requirement: 暂存、校验、原子移动与操作日志

导入 MUST 先写入资料库内专属 `echo/tmp/<operation-id>/`，完成大小/可读性、BLAKE3 和必要元数据解析校验后才发布音频及侧车；每个文件 MUST 经同文件系统原子发布且不得覆盖既有无关文件。音频是主资源，系统不得宣称独立音频和侧车能跨文件物理原子提交。

完整音频安全发布并刷盘后，系统 MUST 先在音乐库内可靠提交预留 UUID、原入库时刻、相对路径、哈希、成功资源声明、候选及完整恢复凭据，再在 SQLite 中原子投影歌曲、索引及 outbox。恢复凭据 MUST 独立于 SQLite 且不能仅位于可清理的 tmp。目录提交是业务持久化点；SQLite 失败不能撤销已提交资料或分配第二 UUID。普通导入成功 MUST 等待投影完成；目录已保存而投影失败 MUST 明确为已保存待更新，支持以同 operation ID 重试。

#### Scenario: 校验失败不落库
- **WHEN** 暂存文件复制不完整、哈希不匹配、解析失败到无法建立歌曲或安全发布失败
- **THEN** 不提交歌曲对象或 SQLite 歌曲，不覆盖目标文件，报告原因，保留可恢复凭据并安全处理暂存物

#### Scenario: 导入成功原子可见
- **WHEN** 音频及成功侧车均完整发布，本地对象集合可靠提交，SQLite 投影完成
- **THEN** 用户获得导入成功，歌曲 UUID、路径、哈希与媒体一致，重装后不依赖原 SQLite 恢复，半复制文件不成为可播放歌曲

#### Scenario: 崩溃后恢复
- **WHEN** 应用在暂存、移动、本地提交或 SQLite 投影之间崩溃，随后重启或丢失应用数据
- **THEN** 先恢复目录日志；已提交操作按预留 UUID 补齐投影，未提交操作不冒充成功且可安全恢复/回收，重复恢复无重复歌曲或文件

#### Scenario: 音频发布后侧车失败
- **WHEN** 音频完整发布但侧车失败或进程中断
- **THEN** 可用同一预留歌曲 UUID 保存音频及真实资源状态，侧车可恢复/重试/清理，结果明确歌词未导入，不能把整项伪装为完整成功

#### Scenario: 发布后 watcher 抢先观察
- **WHEN** watcher 在导入对象/数据库投影完成前观察最终音频路径
- **THEN** 它等待活动 claim 或复用预留 UUID，不绕过本地提交铸造第二身份

#### Scenario: 音频成功而对象持久化失败
- **WHEN** 音频已发布但目录对象提交因空间、权限或刷盘错误失败
- **THEN** 不报告导入完成，不在 SQLite 独占保存歌曲；保留音频与稳定操作身份用于安全重试，不能将已发布资源当作无主垃圾直接删除

#### Scenario: 对象成功而数据库投影失败
- **WHEN** 目录提交完成后 SQLite 提交失败
- **THEN** 明确已保存待更新，后续恢复仅重放原操作，不重复复制、不改 added_at、不创建新 UUID；其他文件独立成功结果保持

## ADDED Requirements

### Requirement: 导入持久化边界通过共享核心验证

导入的提交/恢复规则 MUST 位于 Core Application，文件与数据库通过聚焦端口接入，平台仅选择文件和呈现逐项结果；旧 DB-first 材料化入口不得并存。实现及兼容 MUST 遵守工程规范 §3–§5、§8–§9 与 `library-durability` LD-10，保留有界并发、源文件不变、无覆盖与临时播放项不落库的既有语义。

#### Scenario: 导入契约回归
- **WHEN** 改造后的导入准备交付
- **THEN** 导入、watcher 抢占、逐资源失败、各提交边界中断、失去 SQLite 后离线重建及原有并发/重复/命名/临时播放测试均通过，并有跨平台原子发布与权限故障证据
