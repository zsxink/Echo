# lan-library-sync Delta

## ADDED Requirements

### Requirement: 同步接收先提交本地音乐库

首次快照、增量和来源设备 ACK 的对象、喜欢、歌单、成员、覆盖层、统计、别名/墓碑及确认信息 MUST 先作为一致集合可靠保存到接收端音乐库，再提交业务 SQLite 投影及已应用水位。快照必须完整验证后才发布可见集合，不能清空或覆盖本地未确认资料；本地优先合并、冲突裁决与媒体无覆盖规则保持。对象可早于媒体提交，但对应歌曲必须保持不可用；只有所需媒体完整校验、安全发布并持久记录位置后才可播放。整库已同步仍要求目标对象水位、资源、候选和错误全部满足既有完成条件。

#### Scenario: 从设备同步后重装
- **WHEN** 从设备成功接收本次目标资料与资源后失去全部应用数据，并断网打开相同音乐库
- **THEN** 歌曲、喜欢、歌单/成员、资源及原 UUID 可完整离线恢复，不能因来源是 LAN 而依赖旧数据库

#### Scenario: 快照一半失败
- **WHEN** 首次快照在下载、完整性验证或本地提交前失败
- **THEN** 原本地资料与未确认候选保留，不开放半套远端歌单关系；恢复按原会话/快照凭据重试或明确重新建立基线

#### Scenario: 对象先落盘而媒体未就绪
- **WHEN** 远端对象已在音乐库提交并投影，而媒体下载尚未完成
- **THEN** UUID、喜欢及成员保留，媒体标记不可用，同步不能显示全部完成；目录恢复不将缺文件解释为用户最终删除

#### Scenario: 对象落盘失败不跳过
- **WHEN** 接收端可更新 SQLite 但无法可靠写本地音乐库
- **THEN** 该页不推进到已应用完成水位、不报告保存成功，重试相同页无重复副作用

### Requirement: 主机成功确认包含本地权威持久化

主设备 MUST 在完整确认结果及幂等身份已可靠进入本地音乐库、SQLite 账本投影成功且既有资源/控制面/独立安全检查点发布条件成立后，才返回完成 ACK 或向快照和增量公开结果。相同 mutation 重试 MUST 返回同一结果，相同身份不同正文仍须拒绝。目录持久失败不得以 SQLite 账本或安全检查点成功代替；不得绕过连续 published 水位、认证、epoch 或冲突规则。

#### Scenario: ACK 后主机失去数据库
- **WHEN** 主机已经对从设备返回成功 ACK，之后 SQLite 损坏
- **THEN** 已确认的用户业务结果可从主机完整音乐库恢复；旧主机会话是否可继续仍必须通过可信账本与独立检查点验证

#### Scenario: 确认结果已写但 ACK 丢失
- **WHEN** 本地权威提交完成后，在 SQLite 投影、安全检查点或网络响应阶段中断
- **THEN** 未满足完整发布条件前不公开成功；恢复后重复提交返回同一结果，不新增成员、不增加统计、不复用为另一提交

### Requirement: 重装后的本地资料与网络信任分开恢复

系统 MUST 在缺少应用配置、配对凭据或可信账本时仍提供完整音乐库的离线用户数据恢复；不得因便携 binding/版本存在就自动恢复旧主设备权限、监听或续传。无法证明安全续传时必须保留候选与用户资源，并按既有显式恢复新 epoch/重新配对流程处理，不要求重新导入音乐。目录中的逻辑元数据不得包含端点、凭据或本机绝对路径。跨层及兼容验证遵守 `library-durability` LD-10。

#### Scenario: 重装系统后打开资料库
- **WHEN** 用户保留音乐库目录但操作系统重装，安全存储和应用配置均不存在
- **THEN** Echo 离线恢复歌曲、喜欢和歌单；默认不监听、不发现、不连接，说明重新配置同步需求，不伪造旧凭据或把重建失败当作空曲库
