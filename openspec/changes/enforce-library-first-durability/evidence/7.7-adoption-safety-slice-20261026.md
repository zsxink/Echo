# 7.7 adoption safety slice — 2026-10-26

Task 7.7 remains incomplete. This slice closes two paths that could otherwise
re-author retained evidence before an explicit adoption workflow exists.

## Changes

- Replica enrollment checks retained pending state before it seeds the complete
  current catalog. Pending evidence with an unproven legacy scope, a different
  binding, or a different author blocks enrollment with an explicit
  reconciliation error. A historical terminal disposition alone is not a
  verified receipt and cannot unlock enrollment. An original current-author
  unbound event remains eligible for ordinary first enrollment. The failed
  transaction creates neither baseline marker nor new
  queue rows.
- Playback preserves every device bucket in the local portable record, while
  the newly frozen upload candidate contains only the authenticated local
  author's bucket. Retained unconfirmed counts from another author therefore
  remain local evidence and cannot poison or be laundered through a new
  author's event. Existing host merge rules preserve omitted confirmed buckets.

## Remaining acceptance

The current LAN API has mutation submission, commit history, and snapshots but
no old-receipt lookup or authenticated negative receipt proof. A changed current
object value cannot prove that an old event was never accepted: it may have
been accepted and later superseded. Such events must remain unknown/pending.

The stable durable old-to-new mutation mapping, verified accepted/terminal
receipt reconciliation, explicit adoption orchestration, and interruption
matrix are still required before task 7.7 can be completed. These safety checks
are not evidence that adoption is implemented.
