# 7.7 adoption safety slice — 2026-10-26

Task 7.7 remains incomplete. This slice closes two paths that could otherwise
re-author retained evidence before an explicit adoption workflow exists.

## Changes

- Replica enrollment checks retained pending state before it seeds the complete
  current catalog. Pending evidence with an unproven legacy scope, a different
  binding, or a different author blocks enrollment with an explicit
  reconciliation error. A historical terminal disposition alone is not a
  verified receipt and cannot unlock enrollment. An original current-author
  unbound event remains eligible for ordinary first enrollment. The failed
  transaction creates neither baseline marker nor new
  queue rows.
- Playback preserves every device bucket in the local portable record, while
  the newly frozen upload candidate contains only the authenticated local
  author's bucket. Retained unconfirmed counts from another author therefore
  remain local evidence and cannot poison or be laundered through a new
  author's event. Existing host merge rules preserve omitted confirmed buckets.

## Verification

- `cargo test -p echo-core --lib library_durability_new_author_playback` — 1
  passed. The fixture retains local A=7, records one real B playback, retries the
  same session without incrementing again, asserts the frozen candidate omits
  A and contains B=1, and confirms that event against host A=5. Host output is
  A=5/B=1; local counts remain A=7/B=1.
- `cargo test -p echo-core --lib library_durability_replica_baseline` — 1 passed.
  Retained legacy pending state blocks repeated enrollment without changing
  the original queue or creating a baseline marker.
- `cargo test -p echo-core --lib sync_baseline` — 9 passed. Existing initial
  enrollment, host baseline, authorization, rollback, resource, and restart
  idempotence contracts still pass.

## Remaining acceptance

The current LAN API has mutation submission, commit history, and snapshots but
no old-receipt lookup or authenticated negative receipt proof. A changed current
object value cannot prove that an old event was never accepted: it may have
been accepted and later superseded. Such events must remain unknown/pending.

The stable durable old-to-new mutation mapping, verified accepted/terminal
receipt reconciliation, explicit adoption orchestration, and interruption
matrix are still required before task 7.7 can be completed. These safety checks
are not evidence that adoption is implemented.

## 2026-10-27 implementation progress

The directory-first transition is now implemented as typed `AdoptionState`
facts. Reconciliation only treats a strict receipt in the frozen event's old
binding or a verified ledger entry from that same binding as proof. A new
binding's receipt cannot resolve an old event. Unknown intents require an
explicit `keep` choice; their replacement ID is deterministic, and replay
copies the original body, resource declarations, operation and frozen time.
SQLite installs the replacement only for the newly authenticated author and
reuses it after a directory-commit / projection interruption. Authoritative
tombstones and song/member aliases block explicit adoption for review.
Unproven play-stats remain under the old author and do not generate a new
author's event.

New coverage:

- Domain tests cover evidence binding, a lost-ACK accepted receipt, rejection of
  a receipt from the new scope, stable play-stats decisions, and authoritative
  alias conflict refusal.
- `library_durability_adoption_replays_directory_commit_once_after_projection_interruption`
  commits an explicit adoption to the native temporary directory, simulates a
  stop before SQLite projection, then retries twice. It verifies the new author,
  original body and timestamp, and exactly one replacement mutation.
- Existing `library_durability_new_author_playback_preserves_old_pending_bucket_without_claiming_it`
  verifies the A=7 local / A=5 host case: B's event contains B=1 only, the host
  remains A=5/B=1, and the local record retains A=7/B=1.
- On this macOS arm64 host, `cargo test -p echo-core library_durability` passed
  247 tests and its architecture target passed 1; `cargo test -p echo-core sync`
  passed 216 tests and the matching sync-domain target passed 1; the dedicated
  interrupted-projection test passed 1.

The task remains open. End-to-end re-pair across a distinct binding, complete
terminal-rejection evidence, authoritative snapshot conflict resolution UI,
and a transition fault matrix at each persistence boundary still need
acceptance. The tests above do not establish the whole 7.7 scenario.
