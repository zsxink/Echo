# 7.4 Remote resource directory durability (2026-10-26)

Remote resource prepare/save/finalize transitions now use stable operation IDs
through the library durability coordinator. Completion records the fully
verified resource declarations in the library directory and stores a typed
current-location pointer scoped to the library/object, separate from LAN
binding or author trust. A fresh SQLite projection can restore the physical
resource path and preserve the Song UUID while leaving availability missing
until a scan verifies the file. No binding, credential, or upload outbox is
created by this offline projection.

The pointer names the exact completed publication operation. This prevents an
older audio declaration from winning when only an artwork/sidecar set changed.
The directory adapter independently verifies hash and byte length before the
completion marker; a failed final projection keeps the same operation for
retry and cannot replace the prior association.

Five new tests in `sync_resource_publication_directory.rs` cover media and
managed `echo/media/` reconstruction after database loss, refusal/retry of a
completion, SQL failure after directory commit with stable operation reuse,
latest sidecar-only location selection, and wrong owner/library/incomplete
resource rejection. Existing publication tests retain Windows occupied-file
simulation; native Windows file-lock behavior remains part of task 9.3.

Verification: `cargo test -p echo-core sync_resource_publication` — 26 passed,
0 failed. The 7.4-owned Rust files passed scoped `rustfmt --check`. Clippy had
no warnings in the 7.4-owned code; the package-wide run was blocked by a lint
in another worker's lifecycle playback test, which is tracked separately.
