## 缺陷 1：歌单重试丢稳定操作身份

- `LocalLibraryEditPort::create_library_playlist` 改为返回 `Result<PlaylistId, Error>`：目录里已存在同名唯一键（`playlist_name_key`）的已保存创建时，补全该创建并返回其身份，而不是铸造第二个身份（LD-08）。
- `SqliteDatabase::edit_library_playlist`（`infrastructure/sqlite/local_library_edit.rs`）：规划闭包新增 `&LibraryReplay` 基线参数，Create 分支经 `LibraryReplay::playlist_by_name` 命中已保存创建时返回空批次——`plan_library_change` 对空批次提前返回，不产生第二次目录提交。
- 追赶失败归因：新增 `saved_pending_catch_up`，把 `project_commits` 的失败映射为 `saved_pending_projection`，操作身份取目录链上首个 `library_commit_seq >` SQLite 已记录水位的提交（播放记录入口优先按其会话操作身份），重试始终报告已保存操作而非新鲜的未保存失败。
- memory fake 同步实现同一语义（含 `fail_commit` 下重试报同一操作身份）。
- RED→GREEN：`infrastructure/sqlite/tests/lifecycle/playlist_create.rs::library_durability_playlist_create_retry_after_saved_pending_keeps_operation_identity`（修前 RED：重试报新鲜失败且身份不一致；修后 GREEN）。`application/testing/memory_database/local_library_edit/tests.rs::library_durability_memory_create_retry_completes_the_saved_playlist` 覆盖 fake 路径（重试同身份、目录提交恒为 1、投影修复后补全原名）。

## 缺陷 3：保留成员被无条件删除

- `durability_projection/retained.rs::retry`：释放成员旧位置的 DELETE 改为仅在该成员当前可解析（`dependencies::unresolved(...) == None`）时执行——被阻塞的保留成员保住已投影行，重试不得丢弃无法替代的已保存事实。
- RED→GREEN：`lifecycle/playlist_members.rs::library_durability_retained_member_with_blocked_reorder_keeps_projected_row`。构造：两首歌入同一歌单，把首位成员的保留画像手工改为指向仍被次位成员占用的位置（IdentityConflict，不经任何 FK 行删除），`project_library_commits` 两轮后断言两行俱在、位置不变、`projection_status` 如实报告 IdentityConflict。暂存本修复复跑确认旧代码丢行（left: 1 / right: 2）。
