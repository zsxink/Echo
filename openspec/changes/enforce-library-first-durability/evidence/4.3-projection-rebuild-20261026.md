# Task 4.3: disposable projection validation and root replacement

Date: 2026-10-26

## Implemented slice

- Reconstructs a disk-backed candidate SQLite database from verified directory replay, without reading the active projection as source data.
- Rejects a replay whose library identity differs from the manifest; verifies replay head, SQLite `quick_check`, foreign keys, exact typed retained records/state/resources, and no candidate upload mutations/outbox.
- An incremental projection failure can fall back to a rebuild only after the current manifest and directory head match the replay being adopted.
- Replaces root-owned songs, playlists, scan runs, projection watermark, applied operations, and retained evidence within one writer transaction. A failed SQL write rolls the deletion and replay back together.
- Preserves other roots and blocks while local file operations are incomplete. A root with sync context is refused until archive-aware sync projection replacement is implemented.
