## Purpose

为 Echo 桌面端建立离线、播放器全局的音效能力，以统一类型化预设协调音色与空间处理、请求和实际生效状态、本机恢复及三平台验收，确保音效不侵入共享资料库与同步职责。

## ADDED Requirements

### Requirement: 统一预设与一期范围
系统 SHALL 在 macOS、Windows、Linux 提供 `pop`、`rock`、`classical`、`jazz`、`electronic`、`vocal`、`bass`、`warm`、`retro` 九个只读 EQ 预设，以及 ID 为 `surround`、名称为「空间感增强」的只读空间预设。内置与用户曲线 MUST 使用统一的类型化参数通路，同一时刻只启用一个预设或草稿，EQ 与空间处理不得叠加。P0 MUST 不提供可操作的导入导出、混响、响度归一化或设备绑定入口，不宣称恢复音质、环绕声、5.1 或对象音频能力。预设描述 MUST 与实际处理一致，不能将主观调音初值称为通用行业标准曲线，将高频 peaking 称为恢复高频延伸，或将整曲静态 EQ 称为动态去齿音。

空间感预设固定用户 width 为 1.25，不向用户提供 width 编辑。系统可在启用/关闭的内部生命周期中使用 `spatial:m` 在中性 1 与固定目标 1.25 间连续过渡，但必须先用所处分发库的持续 PCM 捕获证明实际输出变化。`af-command` 的返回值不能作为生效证据，`af` 配置描述也不代表运行时实际参数。测量必须在素材仍被处理时发出命令，记录输出样本位置并排除已解码 EOF、加载/seek 重置及预处理缓存的干扰。macOS 的修复证据见 native-gate.md；其他平台须独立验证，不继承 macOS 结论。

#### Scenario: 选择不同类型
- **WHEN** 用户从 EQ 预设切换到空间感增强，再切回 EQ
- **THEN** 每次整体替换处理类型及参数，确认后显示新预设名称，前一种处理被移除

#### Scenario: 内置注册表完整
- **WHEN** 用户离线打开音效列表
- **THEN** 九个 EQ 与一个空间预设均默认可用且不可删除，无账号或会员限制，无「原声」列表项或 P1 可操作入口

#### Scenario: 预设描述与能力一致
- **WHEN** 用户查看古典、人声或其他内置预设说明
- **THEN** 说明表达音色取向，不承诺高频信息恢复、动态去齿音或适合所有同类录音/设备，曲线发布前有匹配响度试听依据

#### Scenario: 运行时改参能力不足时不谎报生效
- **WHEN** 某内置预设的滤波参数需要更新，而后端只能通过 `af-command` 发送
- **THEN** 系统先以持续 PCM 前后测量验证当前运行库的参数路径；输出变化未被证明时不能仅凭命令成功宣称该路径可用，不能改为每次输入重建链来绕过连续性验收；用户 width 始终不可编辑

### Requirement: 请求与生效状态一致
系统 SHALL 由桌面播放适配层提供唯一音效状态；两标签页、播放栏及后台窗口 MUST 从相同状态渲染。状态 MUST 区分选择/草稿、请求启用、revision 和实际的旁路、待应用、已应用、失败、不可用。只有最新请求在当前音频环境被播放器确认时才可显示已生效名称；过期确认不得覆盖关闭、重置或后续请求。应用失败 MUST 回滚上一组确认有效参数；不能确认回滚时旁路音效并允许重试。

服务 MUST 在串行捕获对外快照时分配独立非持久化序号，以避免同 revision/epoch 的旧查询或事件覆盖较新的曲线管理结果及持久化状态；元数据变化不得因此增加音频 revision 或重建音频链。IPC 序号为向后兼容的可选投影，旧快照沿用 revision/epoch 规则。音效屏障实际暂停播放时 MUST 不报告 Playing；不支持环境的旁路过渡 MUST 持续推进至确认完成，失败不得放行首样本。

#### Scenario: 快速输入后重置
- **WHEN** 用户连续拖动后立即关闭、重置或选择其他预设，旧请求随后返回
- **THEN** 最终状态以最新操作为准，过期参数不会重新生效或重新显示名称

#### Scenario: 已启用预设等待应用
- **WHEN** 用户已请求启用某预设，但当前音频环境尚未确认应用
- **THEN** 播放栏显示所选预设名称并标记“待应用”；仅确认后才标记为“已生效”

#### Scenario: 应用失败
- **WHEN** 注入参数应用失败且回滚成功或失败
- **THEN** 成功回滚恢复上次有效状态并提示本次失败；不能确认回滚则安全旁路，保留失败请求供重试，均不得将失败请求显示为已生效

#### Scenario: 暂停与无音轨
- **WHEN** 用户在暂停或无音轨时选择、编辑或保存音效
- **THEN** 不加载文件或自动播放，面板显示待应用状态且播放栏不显示生效名称，下次播放首个输出样本前应用最新参数

### Requirement: 音效本机持久化及恢复隔离
系统 SHALL 原子保存版本化用户曲线、当前选择/草稿、保留参数、请求启用及 preamp 模式/请求值；拖动合并写入，正常退出刷新最终状态。实际保护增益 MUST 按新环境重算，不能恢复为已生效。音效 MUST 仅存放于本机偏好，不能进入 SQLite、资料库 `echo/`、outbox 或同步载荷，不发起网络请求。旧偏好缺少音效字段 MUST 初始化为关闭且不影响其他有效偏好。

#### Scenario: 正常重启与后台
- **WHEN** 用户关闭浮层、切页面/曲目、后台关窗或正常退出重启
- **THEN** 草稿和曲线保留，后台播放继续使用同一音效，重启恢复请求后等待环境确认，不自动开始发声

#### Scenario: 损坏或未来数据
- **WHEN** 恢复遇到损坏数据、未知版本、缺失 ID 或非法参数
- **THEN** 关闭处理并提示恢复失败，不阻断基础播放，不覆盖原数据，可恢复曲线被保留

#### Scenario: 资料库与离线边界
- **WHEN** 断网后切换资料库、清空队列或播放资料库外临时文件
- **THEN** 用户曲线与全局音效保留，临时文件应用同一音效且不写统计或资料库，音效不产生同步或网络载荷

### Requirement: 播放环境变化与兼容
系统 SHALL 以实际滤波器处理采样率与输入声道布局判断能力，不能以源文件元数据替代。EQ MUST 覆盖既有可解码的单声道/立体声文件；空间处理只接受双声道输入，不擅自转换布局。不支持的预设 MUST 标记当前环境不可用并禁选，保留原有效状态；已请求的空间处理遇到不支持输入时暂时旁路并保留请求，恢复支持环境后重新确认。切歌、输出设备切换或音频链重建 MUST 使旧环境确认失效并应用最新请求，保留时长、seek、歌词进度、播放计数、音量/静音和队列语义。

#### Scenario: 空间输入变化
- **WHEN** 空间预设播放双声道后切到单声道，再切回双声道
- **THEN** 单声道时旁路且说明原因，保留请求并不改声道，双声道恢复后重新应用确认

#### Scenario: 切歌与输出重建
- **WHEN** 在 44.1/48/96/22.05 kHz、既有其他受支持采样率及有损/无损/临时文件间切换，或输出设备重建
- **THEN** 使用最新处理环境重新计算和应用参数，不出现旧环境的假生效，不改变传输控制与统计规则

### Requirement: 音频与性能发布门槛
系统 SHALL 在三平台实际分发运行库上通过 P0 能力验证、全部预设响度匹配 A/B、保护压力测试及连续播放测试。可听更新延迟 p95 MUST ≤150 ms，每种开关、EQ→EQ、EQ↔空间、连续拖动场景至少 100 次，测量从参数提交到音频输出，不能以 UI 回执替代；无新增 underrun、爆音或断流。最重 P0 预设的 CPU 平均占用相对旁路 MUST 增加不超过 10 个百分点（单核心满载为 100%），参考机至少 4 核/8 GB/SSD，预热 30 秒并采样 5 分钟，分别记录稳定播放与面板开关。缺少能力或未达标 MUST 阻塞发布，实施前验证失败须先修订方案/范围，不得禁用 P0 项后宣称完整交付。

#### Scenario: 三平台证据完整
- **WHEN** 准备发布 0.2.0
- **THEN** 每平台提供 CPU 型号、系统、运行库/包版本、素材、采样率、延迟分布与断流记录，P0 全通过才可发布

#### Scenario: 预设听感与空间折叠
- **WHEN** 对所有 EQ 预设与中性/相近预设，以及空间拓宽与旁路进行匹配响度 A/B
- **THEN** 按 design 的 BS.1770 响度度量记录匹配误差、符合频响意图的可辨识差异、限幅介入与无新增可闻失真；空间双声道差异可辨且单声道折叠无明显人声抵消

### Requirement: 音效架构及交付契约
系统 MUST 将音效规则与播放状态置于桌面播放层，UI 通过类型化命令/事件访问，Core 保持无 UI/播放器依赖，基础设施通过聚焦端口注入。新增 IPC 与本机状态 MUST 有序列化、兼容与故障测试，遵守 CODE_STANDARDS §2–4、§6、§8–9。

#### Scenario: 架构及接口验证
- **WHEN** 实现完成并进入集成验证
- **THEN** `cargo test --workspace`、`cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`pnpm --dir apps/desktop typecheck` 与 `pnpm verify:governance` 通过，生成 IPC 与声明一致，Core 无新增音效依赖
