# Echo 音效与均衡器产品需求文档（PRD）

> 文档状态：复核修订稿，待产品与技术评审  
> 目标版本：一期后首个听感增强版本 0.2.0（2026-10-02 已确认规划目标，发布日期按验收确定）  
> 目标平台：macOS、Windows、Linux  
> 变更标识：`introduce-audio-effects-equalizer`  
> 更新日期：2026-10-02

## 1. 产品摘要

本次变更为 Echo 引入**音效体系**与**均衡器**：一套统一的「预设」抽象，既承载内置的常用音效，也承载用户手动调节并保存的自定义曲线，P0 聚焦预设试听与曲线编辑，外部曲线数据（如 AutoEq）的导入导出列入 P1。

核心设计判断是：**均衡器不是音效的兄弟，而是音效的子类。** 均衡器、声道拓宽和响度处理的参数及处理算法不同，但共用预设管理、应用状态和持久化机制；因此本次采用一个「预设 + 类型化参数包」模型。P0 同一时刻只启用一个预设，不提供多效果叠加。UI 由播放栏打开「音效」浮层，浮层顶部以「音效」和「均衡器」两个标签页切换预设选择与曲线编辑。

本次变更**不引入账号、不引入网络依赖、不引入服务端音频处理**，全部能力在本地播放链路内完成。

## 2. 背景与问题

当前 0.1.x 尚无应用级音效与均衡器控制；这不代表操作系统或输出设备没有其他处理。这在以下场景中构成实际缺口：

1. **设备差异无法补偿。** 用户耳机/音箱的频响缺陷（低频轰头、齿音刺耳、中频凹陷）在播放器层面完全无处修正。这是发烧友与普通用户共同的痛点，也是第三方工具（AutoEq）存在的原因。
2. **内容差异缺少调节工具。** 不同专辑存在音色与响度差异。P0 用 EQ 提供主观音色调节；曲目间响度归一化属于 P1，不能通过 EQ 预设替代。
3. **缺少低成本的主观调节入口。** 多数用户不具备调整多段频响的能力，需要「一键可听出差别」的预设；少数用户则需要精细控制。二者必须是同一个系统的两个视图，而不是两个割裂功能。

本次以「找到合适听感 → 试听 → 微调 → 保存 → 下次继续使用」为主要闭环，竞品笔记仅作交互参考（见第 4 章）。

## 3. 目标与非目标

### 3.1 目标

- 提供一组**开箱即用、听感差异明显**的内置音效预设，覆盖主流音乐类型与人声场景。
- 提供**可手动调节并保存**的均衡器，且自定义结果可被持久化、重命名、复用。
- 建立**统一预设模型**：内置预设与自定义预设走同一条数据通路，UI 层不存在「音效走一套、均衡器走另一套」的分叉。
- P1 提供**导入/导出**能力，使 Echo 可接入现有外部曲线生态（AutoEq 等），并让用户能分享自己的曲线。
- 全链路**离线、本机、无账号**；音效参数不进入资料库同步范围。

### 3.2 非目标

- 不做「超清母带」等音质等级承诺，不以 EQ 或空间感处理宣称恢复文件中不存在的信息。
- 不做内容侧多声道重混、对象音频渲染或相关格式认证；本次声道拓宽只承诺立体声空间感变化。
- 不做 AI 人声/伴奏分离。
- 不做 per-track（单曲级）音效绑定。一期内音效是**播放器全局状态**。
- 不做音效参数跨设备同步。

## 4. 竞品参考：网易云音乐与 QQ 音乐

> 原稿中的竞品数量、设备覆盖数量及功能别名来自未附链接的二手笔记，本次无法核验，不保留为事实表。后续如需竞品对照，应记录官方来源、客户端平台、版本及截图日期；不作为 Echo 的实现规格。

### 4.1 可保留的产品参考

以网易云音乐和 QQ 音乐的音效入口作为设计调研对象，重点验证：预设是否易于试听、启用状态是否独立于选中态、用户曲线如何保存，以及设备补偿如何与主观音色调节区分。以上是调研问题，不代表已确认两家当前版本的行为。

### 4.2 Echo 的建模结论

音色调节、空间感增强、响度归一化需要不同参数，不能把所有音效编码为 EQ 曲线。Echo 以统一预设容器管理类型化载荷；P0 的 EQ 与空间预设互斥，后续混合处理需另行定义组合、重置及编辑语义。

### 4.3 与 Echo 定位的取舍

- **不复制付费墙。** Echo 无账号体系，全部内置预设默认可用，不做会员分级。
- **精选预设。** 每个预设必须有明确频响意图和试听证据（见第 5 章），重合明显的初值应调整。
- **不复制 AI 音质增强。** 见 3.2 非目标。
- **设备补偿列入 P1。** 通过外部曲线导入与按输出设备应用预设实现；P0 切换输出设备仍保留全局预设，不承诺识别耳机型号。

## 5. 内置音效清单

### 5.1 术语约定

| 术语 | 定义 |
|---|---|
| 音效 | 所有对播放音频做实时变换的处理集合。是本次能力的**上位概念**。 |
| 预设（Preset） | 一组命名的、可整体启用的效果参数包。承载内置预设与用户自定义预设。 |
| 均衡器（EQ） | 对音频各频段增益做调整的处理，是音效的一个**子类**。 |
| 预设载荷（payload） | 预设内部的实际参数，按类型分为 EqCurve / Spatial / Loudness 等变体。 |
| 音色类预设 | 载荷为一条 EQ 曲线的预设。 |
| 空间类预设 | 载荷为声道拓宽 / 混响参数的预设。 |
| 用户曲线 | 用户在均衡器中手动调节后保存的结果。 |

### 5.2 音色类内置预设（载荷：EqCurve）

频段基准：10 段，中心频率按 1 倍频程间隔（不等于数字滤波器的实际带宽），中心频率 `31.25 / 62.5 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k` Hz，增益范围 `±12 dB`。

| ID | 名称 | 频响意图 |
|---|---|---|
| `pop` | 流行 | 低频微提、中低频略收、4kHz 附近提亮 |
| `rock` | 摇滚 | 低频与高频双端提升，中频微凹 |
| `classical` | 古典 | 全段近中性，局部高频轻微提亮，不承诺恢复高频延伸 |
| `jazz` | 爵士 | 中低频温暖、高频清亮 |
| `electronic` | 电子 | 低频强提升、高频提升、中频收敛 |
| `vocal` | 清澈人声 | 突出人声存在感、低频收敛、部分高频轻微柔化；不是动态去齿音 |
| `bass` | 超重低音 | 60–120Hz 强提升，高频略减 |
| `warm` | 温暖轻柔 | 低频微提、高频柔化、整体不刺激 |
| `retro` | 华丽复古 | 中低频凸起、高频衰减 |

预设名称描述主观音色取向，适用于完整歌曲，不保证适合所有同类型录音或设备；人声轨混音资料仅为频段参考，不暗示内容分离。具体曲线和空间宽度是参考专业原理的 Echo 调音候选，不称行业标准或厂商推荐配方；资料来源与边界见附录 A 和 design。

**具体增益值不在本 PRD 固化**，由 design 阶段给出初值，并以「同一曲目 A/B 可辨识差异、且不产生可闻失真」为验收口径（见 15 章 V3）。

### 5.3 空间类内置预设（载荷：Spatial）

| ID | 名称 | 处理意图 | 优先级 |
|---|---|---|---|
| `surround` | 空间感增强 | 适度拓宽立体声宽度 | P0 |
| `live` | 现场律动 | 轻度短混响，模拟小型现场 | P1 |

> ⚠️ 约束：本次仅处理立体声宽度，不提供多声道声场重建。P0 拓宽预设的名称统一为「空间感增强」（保留内部 ID `surround`），**不得出现「环绕声」「5.1」「空间音频」等暗示内容侧重混的措辞**（见 15 章 V7）。

### 5.4 响度类（载荷：Loudness）

| ID | 名称 | 处理意图 | 优先级 |
|---|---|---|---|
| `volume-level` | 音量均衡 | 抹平不同曲目/专辑的响度差异 | P1 |

音量均衡为 P1 独立类型，不与 EQ 隐式叠加；目标响度、峰值上限、已有 ReplayGain 标签及无标签曲目的策略由后续 design 明确。

**保护项**：只要音效处理启用，削波保护必须随处理链生效且不可关闭（见 13.2）；音效关闭时旁路本次新增处理，不改写原文件。

### 5.5 明确不做的内置音效

| 不做的项 | 理由 |
|---|---|
| 超清母带 / 臻品母带 | 不以音效宣称恢复源文件中不存在的信息 |
| 沉浸环绕声 / 臻品全景声 / Audio Vivid | 本次不提供多声道重混、对象音频渲染或相关格式认证 |
| AI 声源分离（人声/伴奏分离） | 需随包分发模型，与安装体积和启动开销冲突 |
| 迷幻电音 / 纯净 ACG 等口味化命名 | 与已有 EQ 预设听感重合，不增加信息量 |
| 按会员等级锁定的音效 | Echo 无账号体系 |

## 6. 均衡器

### 6.1 形态

- **推子视图**：10 段等间距垂直推子，标注中心频率；提供「重置」和保存自定义音效的入口。「启用」开关放在浮层顶部标签栏，在两个标签页中保持可见。
- **增益范围**：`-12 dB` 至 `+12 dB`，步进 `0.5 dB`。
- **频率响应曲线**：推子上方展示按实际滤波器类型、带宽与当前处理采样率计算的 EQ 合成响应，包含实际前置增益；不得以连接推子值的折线冒充实际响应。不表示设备实测频响、空间处理或动态限幅响应。无音轨时使用明确标注的参考采样率。
- **前置增益（preamp）**：提供「自动 / 手动」模式；手动请求范围 `-12 dB` 至 `0 dB`，步进 `0.5 dB`。实际前置增益不得高于安全上限，手动模式不能解除保护。界面显示请求值、实际值及保护介入原因；自动保护需要时可衰减至低于 `-12 dB`，不受手动滑块范围限制（见 13.2）。
- **带宽**：P0 为固定频点与固定带宽的图示均衡器，不提供 Q 或滤波器类型编辑。design 必须给出带宽/Q、滤波器类型和三平台一致的计算规则；1 倍频程的中心频率间隔不等于已确定滤波器带宽。

### 6.2 与预设的关系（关键交互规则）

1. **单一真相源。** 当前预设/草稿、参数、用户请求的启用状态与实际应用状态由桌面播放适配层统一管理，两个标签页从同一状态渲染；播放器确认成功后才能显示「已生效」。
2. **选择 EQ 预设时**，整体替换当前参数（含 preamp 模式），同步推子并请求启用。选择空间预设时移除 EQ，推子展示中性值并说明「当前为仅空间处理；调节均衡器将替换它」。仅切换标签页不改变音效。
3. **编辑任一 EQ 参数时**（推子、preamp 模式或手动值），生成独立「自定义」草稿、清除原预设选中态并请求启用；原预设保持不变。从空间预设开始编辑时转为纯 EQ，空间处理同时移除，不暗中叠加。
4. **保存为预设**：保存当前 EQ 草稿的快照（曲线和 preamp 模式/请求值），保存成功后以新 ID 作为当前选择，保留启用/关闭状态。默认新增，不覆盖已有项；「自定义」草稿不占 50 项额度。空间预设未转为 EQ 时禁用保存曲线入口并给出原因。
5. **无选择且无草稿时**：开关置灰不可操作；首次有效编辑生成并启用草稿。初始状态为中性曲线、自动 preamp、处理关闭。
6. **关闭音效时**：旁路本次新增处理并清除当前已保存预设的选中态；其参数仍保留在均衡器中作为未选中状态。无已选预设且无自定义草稿时，启用开关禁用。若关闭的是「自定义」草稿，则保留草稿及参数，开关可再次启用。播放栏仅在实际应用成功且启用时显示名称。
7. **重置时**：不论当前类型或启用状态，恢复 10 段 `0 dB`、自动 preamp（实际 `0 dB`），清除当前选择/草稿并旁路所有本次新增处理；不删除已保存曲线。列表不提供「原声」项。
8. **草稿离开与恢复**：关闭浮层、切换页面或曲目不丢失草稿；正常退出后恢复草稿及启用状态。选择其他预设或重置会替换草稿，不弹确认；明确保存才能生成「我的音效」条目。
9. **暂停或无音轨时编辑**：允许选择、编辑与保存参数；暂停不被改为播放，无音轨不自动加载文件。参数在下次播放首个输出样本前应用，面板显示待应用状态。

### 6.3 外部曲线导入时的频段适配（P1）

- 外部参数 EQ 的频点、Q 和滤波器类型共同决定响应；禁止只按最近中心频率归并增益或静默丢弃范围外滤波器。
- 非 Echo 10 段曲线须按原始合成响应拟合为固定 10 段曲线。提交前展示原始与适配响应对照、输入滤波器数量、支持/不支持的类型、拟合误差与增益限制影响。
- 拟合误差度量、允许阈值、参考采样率与超限拒绝策略须在 P1 design 固化；未达可接受误差或存在不支持参数时，拒绝保存转换结果，不作保真承诺。
- 用户明确接受近似转换并完成命名后才保存；取消预览不改变列表或当前音效。
- 原始文本和转换结果分别保存与导出（见第 8 章）。任意段数参数 EQ 的保真直通仍为 P1 独立扩展，须定义只读/高级编辑语义，不强行投影成可无损编辑的 10 个推子。

## 7. 自定义音效

- 用户可在均衡器中保存当前状态为命名的用户曲线。
- 名称规则沿用歌单：1–40 个用户感知字符（Unicode grapheme cluster），去首尾空白后非空，同名按 Unicode 标准化 + 不区分大小写判重。
- 内置 ID 与用户 ID 使用独立命名空间；名称在全部用户/导入项中判重，并拒绝与内置显示名称重名。名称只作为文本展示，归一化算法由 design 与歌单约定对齐。
- 支持重命名与删除；删除仅移除该自定义项，不影响任何内置预设，也不影响其他音效状态。删除当前项时清除当前选择并关闭音效处理。
- 用户曲线数量上限 `50`（包含导入项），达到上限时拒绝新增并提示清理；重命名不受额度影响。保存为新项是 P0 的唯一曲线写入方式，更新已有曲线需另行定义覆盖确认。
- 重命名当前项立即更新显示名称，不重建音频链；删除未选中项不改变播放。若已编辑成草稿，删除其来源预设不删除草稿。
- 保存、重命名与删除必须在持久化成功后报告成功；写入失败保留原列表与当前状态、输入名称和草稿，提供重试反馈。
- 用户曲线可作为「预设」出现在音效列表中，与内置预设视觉同级但标记来源。

## 8. 导入与导出（全部为 P1）

### 8.1 格式与导出边界

- **Echo 原生格式**：带 `schemaVersion` 的 UTF-8 JSON，包含名称、类型、10 段曲线和 preamp 模式/请求值；保证 Echo → Echo 参数往返一致。具体扩展名与字段规则由 P1 design 固化。
- **AutoEq 兼容目标**：优先支持其 Equalizer APO 参数 EQ 文本（例如 `Preamp:` 与 `Filter … ON PK Fc … Hz Gain … dB Q …`），逐一确认 PK/低架/高架等类型的支持范围。GraphicEQ、卷积 WAV 不在首轮导入承诺内，不能宣称支持全部 AutoEq 输出。
- `equalizer=f=...:t=q:w=...:g=...` 是 **FFmpeg equalizer 滤镜语法**，不是 AutoEq 通用交换格式。P1 若提供该格式，应标为高级兼容导出，保留带宽及前置衰减；不导入任意可执行滤镜链（官方依据见附录 A）。
- 默认导出当前已保存的用户曲线（含近似转换后的参数），不导出内置预设、启用状态或设备路径。导入项另提供「导出原始文件」；原始文本始终是最初输入，不代表编辑后的曲线。
- 从导入项编辑后保存的新曲线不继承「原始文件」身份，避免将原输入误认为修改后的结果。

### 8.2 导入流程与校验

1. 粘贴或选择本地文本文件 → 格式识别 → 完整校验 → 如需转换则预览差异 → 命名 → 保存。默认不启用、不替换当前草稿；用户随后显式选择。
2. 输入限制：UTF-8 文本最大 `256 KiB`，最多 `32` 个滤波器；频率 `20–20000 Hz`、增益 `±12 dB`、Q `0.1–20`、输入 preamp `-60–0 dB`，全部数值必须有限。P1 若扩大范围须重新评审性能与保护边界。超出手动 preamp UI 范围的合法值必须在预览中提示，并由明确转换规则处理，不能静默截断。
3. 不支持的版本、格式、滤波器类型、未知执行指令、数值非法或转换不达标均拒绝整次导入，定位具体行/字段；不做部分接受、不执行输入文本或其引用文件。
4. 名称冲突与数量上限遵循第 7 章；允许修改名称重试，不自动覆盖已有曲线。
5. 失败、取消及存储错误不改变当前列表、草稿、选中项与实际生效状态。全部解析与转换离线完成，不拉取耳机数据库。

## 9. 数据与持久化

### 9.1 存储位置与同步边界

- **内置预设**：随应用代码分发，只读，不可删除。
- **用户曲线与当前生效状态**：存放于本机偏好（desktop local state），**不进入 SQLite 资料库、不参与任何跨设备同步**。
  - 理由：音效与具体输出设备（耳机、声卡）强相关，跨设备同步会产生「在 A 机器上为某副耳机调的曲线被同步到 B 机器」的错误语义。
- 持久化内容包括用户曲线、当前选择/草稿、请求启用状态及 preamp 模式/请求值；实际保护增益随采样率重新计算，不盲目复用。切换资料库仍保留音效全局状态，清空播放队列不删除曲线。
- 使用版本化本机存储并保证单次写入原子性；正常退出刷新最新草稿，拖动过程合并写入，不对每个音频更新同步落盘。旧数据迁移不得丢弃有效用户曲线。
- 启动遇到损坏数据、未知版本、缺失预设 ID 或非法参数时关闭处理并反馈恢复失败；保留可恢复的原数据，不覆盖为默认值。恢复成功也须在播放器确认后标记生效。

### 9.2 数据模型要点（细节由 design 固化）

```text
Preset { id, name, source: Builtin | User | Imported, payload }
Payload = EqCurve { gainsDb[10], preampMode: Auto | Manual, requestedPreampDb }
        | Spatial { width, mix }              // P0，不伪造 EQ 曲线
        | Loudness { target }                 // P1，参数待定义
EffectsState { schemaVersion, selection: None | PresetId | Draft,
               draft?, requestedEnabled, revision }
AppliedState { revision, status: Bypassed | Pending | Applied | Failed | Unavailable,
               effectivePreampDb, activeBands, reason? } // 运行态，不直接恢复为已生效
ImportedPreset { originalFormat, originalText, conversionSummary } // P1
```

- 固定频点、滤波器类型与带宽由版本化注册表定义，不允许用户曲线携带任意滤镜命令。载荷变体只声明扩展方向，不代表 P0 已实现响度处理。
- 高频快速编辑以最新 revision 为准；过期确认不得覆盖后来的选择、关闭或重置。UI 请求与播放适配层实际状态应可区分。
- 核心资料库与同步层不依赖上述模型；音效属于桌面播放适配层与本机状态。

## 11. 界面与交互要求

### 11.1 入口

- 主界面播放栏的「音频与队列区」提供音效入口，与现有音量控制同区。
- 音效面板以浮层形式打开，遵循既有浮层规则（Escape 关闭、点击外部关闭）。作为非模态浮层，键盘可到达全部控件，Tab 离开面板后关闭，不锁住主界面焦点；保存/删除若打开模态对话框，焦点约束仅作用于该对话框。
- 面板宽度在「音效」与「均衡器」标签页间保持一致；窄屏按可用宽度收缩，内容在面板内滚动。

### 11.2 信息架构

音效浮层顶部提供两个同级标签页，不新增第三个一级入口：

- **音效**：内置预设与用户曲线按来源分区展示。选中可用预设会立即请求应用并启用音效，确认后显示生效；关闭时清除已保存预设的选中态并隐藏播放栏名称。若当前为自定义草稿，关闭后保留草稿但不显示为已保存预设；无选择且无草稿时开关禁用，有草稿时可重新启用。
- **均衡器**：10 段推子、频率响应曲线、preamp 自动/手动切换与请求值、实际值、「重置」与「保存音效」。编辑区与音效页保持相同面板宽度，必要时在面板内滚动。
- 「启用」滑动开关固定在顶部标签栏右侧，在两个标签页间切换时位置不变。

### 11.3 实时性与反馈

- 正在播放时，拖动推子在拖动过程中实时生效，不得要求松手后才生效；暂停/无音轨遵循 6.2 的待应用规则。
- 调节过程不得产生爆音、卡顿或短暂的静音。
- 实际应用成功且启用时，播放栏音效按钮下方显示当前预设名或「自定义」；关闭、无选择/草稿、待应用、失败或不可用时不显示生效名称，面板给出具体状态。

### 11.4 无障碍

- 竖向推子支持上下方向键调节，步进 `0.5 dB`；Home/End 到达最小/最大值，Tab 在控件间移动。读屏名称包含频率、增益值与单位。标签页支持左右方向键切换，并正确关联 tabpanel。
- 面板内所有控件有名称、焦点可见、状态通过语义属性表达。
- 不使用「仅靠颜色」表达启用态。
- 选预设、保存或错误使用礼貌播报，不打断播放；拖动时合并播报，避免每帧读出数值。

### 11.5 注意事项（原型迭代中确认）

- **浮层必须互斥。** 音效面板和播放队列面板不能同时打开；从任一浮层打开另一个时，先关闭当前浮层。
- **音效按钮是开关式入口。** 面板已打开时再次点击播放栏音效按钮应关闭面板。点击面板及其控件以外的区域也应关闭面板；点击面板内部（包括切换标签、调节控件和保存曲线）不得误关。
- **关闭外部点击时保留操作焦点。** 通过点击其他控件关闭浮层后，不要把焦点强行移回音效按钮；通过 Escape 或面板关闭按钮关闭时可将焦点还给触发按钮。
- **两个标签页共用同一尺寸。** 均衡器内容不得通过扩大面板宽度来容纳控件，应在原面板宽度内排布，并在内容超高时滚动。
- **防止均衡器控件重叠。** 曲线图、频率标签、竖向推子、增益数值、前置增益和保存区域必须在布局中分别占位。竖向滑块应有明确的高度占位，不能仅靠旋转短控件产生视觉长度；曲线卡片与推子之间、推子与数值之间需留出可辨识间距。
- **压缩无信息的留白。** 不在标题或曲线旁加入重复说明；避免标题栏过高、重复的关闭/返回入口和无用途的分隔区。
- **启用状态与预设选择分开表达。** 无选择且无草稿时启用滑钮禁用；选择预设或编辑生成草稿后请求启用；关闭已保存预设时清除其选中态，关闭自定义草稿时保留草稿。滑钮在两个标签页保持固定位置。
- **选中态使用主题色。** 当前选中的预设通过主题色边框、浅色底和文字权重共同突出；关闭已保存预设后恢复未选中样式，不只依赖颜色区分状态。
- **不恢复“原声”列表项。** 中性曲线通过「重置」恢复，不作为可选预设；重置清除当前选择并禁用启用滑钮。

## 12. 状态与异常

| 状态 | 用户可见行为 |
|---|---|
| 无选择且无草稿 | 顶部「启用」开关置灰且禁用；播放栏不显示音效名称。 |
| 自定义草稿 | 无已保存预设选中态，但开关可用；实际启用时播放栏显示「自定义」，关闭仍保留参数。 |
| 关闭已保存预设 | 清除预设选中态并保留曲线参数；没有自定义草稿时启用开关禁用，播放栏不显示音效名称。 |
| 关闭自定义草稿 | 保留未保存曲线但不显示预设选中态；启用开关仍可重新打开。 |
| 执行均衡器重置 | 恢复全频段 0 dB 中性曲线并清除预设选择，音效开关转为禁用；不显示「原声」预设。 |
| 导入参数非法（P1） | 拒绝整次导入，列出具体非法项，当前音效状态不变。 |
| 导入需频段适配（P1） | 展示原始/适配响应与误差摘要；确认后才保存，不静默丢弃参数。 |
| 用户曲线达到数量上限 | 拒绝新增并提示清理入口。 |
| 当前用户曲线被删除 | 清除当前选择并关闭音效处理。 |
| 需要削波保护 | 限制实际前置增益并启用峰值保护，明示实际值；用户不能关闭保护。 |
| 播放链路不支持某项处理 | 该预设标记「当前环境不可用」，禁用选择；原有效状态保持。P0 能力缺失仍属发布阻塞（见 14 章）。 |
| 应用参数失败 | 回滚到上一组已确认有效参数；若无法确认回滚则旁路本次音效，提示失败并提供重试，不显示已生效。 |
| 偏好写入或恢复失败 | 保留可恢复的数据，显示未保存/恢复失败；不得提示成功或阻断基础播放。 |
| 无音轨 / 暂停 / 后台运行 | 可保存待应用状态；不自动开始播放。后台关窗不中断音效，恢复窗口读取同一状态。 |
| 播放中切换预设 | 无爆音、无中断；切换延迟满足 13.1。 |

## 13. 非功能需求

### 13.1 性能与测量口径

- 预设切换及拖动参数更新的可听生效延迟 p95 ≤ `150 ms`，从提交有效参数到输出新处理的音频计算；UI 确认回执不能代替音频生效测量。连续拖动合并更新且最终值必须送达，旧请求不得重新生效。
- 稳态拖动优先采用原地更新，具体滤镜/API 由 design 验证；不得为每个 input 事件重建整条链。类型切换、采样率变化可重新配置，但仍须满足连续播放与延迟要求。
- 参数、preamp、启用/关闭及类型切换需平滑过渡，无可闻爆音、卡顿或新增音频断流。
- CPU 门槛定义为：开启最重 P0 预设后，进程 CPU 平均占用相对旁路基线增加不超过 **10 个百分点**（单逻辑核心满载记为 100%），不使用「基线的 10%」作为相对比例。每平台固定参考机至少 4 核、8 GB RAM、SSD，记录 CPU 型号、系统、运行库、素材与采样率；预热 30 秒后采样 5 分钟。
- 延迟测试每场景至少 100 次，覆盖开关、EQ → EQ、EQ ↔ 空间及连续拖动；无新增 underrun。稳定播放与面板开关分别测量。门槛为待实测的产品预算，未达标须在实现前调整方案或显式复核目标。

### 13.2 音频正确性（关键约束）

- **保护不可由手动 preamp 绕过。** 安全上限须基于当前采样率下整条处理链的增益风险与安全余量；多个 EQ 滤波器可能叠加，不能以最大单段增益作为完整保护证明。实际 preamp 为请求值与安全上限中更低者，自动模式直接采用安全值。
- 处理内部保留足够浮点余量，避免先发生内部削波再衰减；空间拓宽也须纳入保护。输出前提供不可关闭的峰值保护或经验证的等效方案。算法、峰值检测口径、余量与延迟由 design 固化；在规定压力素材下输出不得超过 `0 dBFS`，无非有限值、无非预期硬削波；不得仅凭听感声明安全。P0 峰值验收为 sample-peak；候选 -1 dBFS 样本阈值不等于 -1 dBTP 的 true-peak 保证，不宣称 DAC 重建峰值完全受限或 BS.1770 true-peak 限幅合规。测试记录 true-peak 作为边界诊断，增加测量不意味着加入响度归一化或 true-peak 处理功能。
- 保护提示须说明提升频段可能使整体变轻，不能自动提高主音量补偿。试听审查按 ITU-R BS.1770-5 测量同一片段并制作离线匹配响度对照，记录工具与误差，避免把更响误认为更好；不在产品内加入自动响度补偿。
- 音效处理不得改变时长、seek 与播放计数规则。必要的处理延迟应由播放链路补偿，不引入新增歌词/进度错位。
- 音效请求不得覆盖音量/静音状态或队列/播放模式；音量保持原语义，音效关闭时旁路新增链。对源文件已存在的失真不承诺修复。
- 处理链顺序、平滑过渡、数值精度与保护位置由 design 固化并可复现；保护、关闭和重置优先于过期参数更新。

### 13.3 兼容性

- 三平台（macOS、Windows、Linux）行为一致；预设与用户曲线在三平台可迁移（属本机数据，不做自动同步）。
- 临时播放项（资料库外文件）同样应用当前音效状态。
- 以滤波器实际处理采样率判断 Nyquist：超出有效范围的频段旁路并禁用编辑，明确标记不可用；保存参数保持不变，恢复有效采样率后重新应用。边界附近的安全范围由 design 固化，不能依赖未验证的 mpv 默认行为。
- EQ 处理目标覆盖既有可解码的单声道/立体声文件；空间预设仅适用于双声道处理输入，单声道或不支持的声道布局明确标记不可用，不擅自转换声道。曲目切换若使空间处理不可用则暂时旁路、保留请求并提示，恢复支持的输入后重新确认应用。
- 覆盖常规采样率 44.1/48/96 kHz、低采样率 22.05 kHz 与既有支持的其他采样率；覆盖有损、无损与临时播放文件。切换设备、音频输出重建或曲目采样率变化后重新验证并应用最新状态。

## 14. 技术边界与待验证假设

以下为本 PRD 依赖但**尚未在本仓库实测**的技术前提，必须在 design 阶段验证后才能进入实现：

| 编号 | 待验证假设 | 验证方式 |
|---|---|---|
| T1 | 当前 libmpv 构建可用参数均衡滤镜（FFmpeg `equalizer` 等候选滤镜，经 mpv `lavfi` 接入），且多段串联开销可接受 | 用真实 libmpv 跑 10 段滤镜链，测音频正确性与 CPU |
| T2 | 支持命名滤镜 + 运行时原地改参（具名 `lavfi` 滤镜与 `af-command`，语法及内部 target 需验证），从而避免拖动推子重建滤镜链 | 实测拖参数过程是否爆音；测试运行库版本 |
| T3 | 支持立体声拓宽类滤镜（如 `extrastereo`），听感可接受且单声道折叠后无明显人声抵消 | 听感实测 + 双声道相位检查 |
| T4 | 混响类滤镜（如 `aecho`）能否达到「现场 / 浴室」类预设可接受的质量 | 听感实测；不达标则本类预设降级或移除 |
| T5 | 滤镜链在 `loadfile` 切换曲目时的存活语义（是否需要每曲重新下发） | 播放链路实测；这是「切换歌曲后音效是否仍生效」的关键 |
| T6 | 前置衰减与既有音量/静音控制不互相覆盖（0.1.x 已记录过音量与静音必须独立的问题） | 交互实测 |

> 官方文档只能证明候选 API 与滤镜存在，不能证明随应用分发的 libmpv/FFmpeg 构建可用（见附录 A）。T1/T2/T3/T5/T6 是 P0 实现前置验证项；T4 仅约束 P1。须记录三平台实际包的版本、滤镜可用性与结果。若空间预设或原地更新无法达标，必须先修订 P0 范围/方案再实施，不能以禁用该 P0 项代替发布验收。

### 14.1 评审必须收敛的决策

2026-10-02 规划决策已收敛：用户确认保留完整 P0（9 个 EQ＋空间感增强＋自定义曲线），按 0.2.0 规划；P1 单独立项且不阻塞 P0。固定 Q/滤波器、曲线初值、响应误差、保护算法、素材与测量口径已落入 `design.md`。三平台包能力/参考机/听感/性能证据仍未实测，列为 `tasks.md` 第1组实施前阻塞门槛；失败必须先修订方案/范围，不得静默禁用 P0 项。下列原开放项分别由该决策、design 或后续 P1 change 承接。

- 已决策：目标版本为 `0.2.0`；发布日期依验收确定，路线图登记属于实施任务。
- 已决策：固定 peaking、Q=√2、实际响应误差与整链 preamp/sample-peak 保护及素材口径，见 design；数值与实际滤波一致性仍须 Gate 证明。
- 实施前门槛：三平台实际运行库、固定参考机和延迟/CPU/听感/空间折叠证据必须补齐，通过后方可功能实施；不能写作已验证。
- 已决策：P1 单独 change 决定排期、格式和拟合误差阈值；不在本次 P0 任务内，未完成 P1 不阻塞 P0 发布。

## 15. 验收矩阵

P0 项全部通过才允许发布；P1 验收只在对应能力纳入交付时执行，P0 不显示可操作的导入/导出、音量均衡或设备绑定入口。听感测试使用固定素材（人声、低频、打击乐、古典），按相近响度进行 A/B，对所有预设记录审查结果；客观保护测试额外使用接近满幅的正弦、扫频、宽带信号及双声道反相压力素材。测试素材合法来源、测量工具、误差容限与判定记录由 design/测试计划固化。

| 编号 | 优先级 | 验收路径 | 通过条件 |
|---|---|---|---|
| V1 | P0 | 启用任一内置 EQ 预设 | 听感可辨识、无新增失真/爆音；播放器确认后常驻播放栏显示名称。 |
| V2 | P0 | 拖动推子与 preamp 编辑 | 实时生效；响应图基于实际滤波器/处理采样率/实际 preamp；最终参数与已应用值一致。 |
| V3 | P0 | 9 个 EQ 预设听感审查 | 与中性曲线及意图相近的其他预设进行响度匹配 A/B；记录频响意图、可辨识差异及无可闻新增失真。 |
| V4 | P0 | 预设 → 编辑 → 保存 → 重选 | 编辑频段或 preamp 转草稿、原预设不变；保存新项后名称、曲线、preamp 模式/请求值正确；关闭状态下保存不自动启用。 |
| V5 | P0 | 开关、重置、空状态 | 无选择/草稿时禁用；关闭已保存预设会清除选中态但保留参数，关闭自定义草稿会保留草稿；重置清除当前选择与草稿、恢复自动 preamp 并旁路全部新增处理；不删除用户曲线，无「原声」项。 |
| V6 | P0 | 最大增益与保护压力测试 | 覆盖单段、多相邻段、全部 +12 dB、手动请求 0 dB 及空间拓宽；输出 ≤0 dBFS，无非有限值与非预期硬削波，保护介入可见。 |
| V7 | P0 | 空间预设与类型切换 | 名称为「空间感增强」；双声道有可辨识差异、单声道折叠无明显人声抵消；与 EQ 互斥，改 EQ 后空间处理移除，不作多声道/对象音频承诺。 |
| V8 | P0 | 用户曲线管理 | 1/40/41 个感知字符、空白、Unicode/大小写重名、内置重名、49/50/51 项边界正确；重命名不改播放，删除当前项旁路，删除草稿来源不丢草稿。 |
| V9 | P1 | 非法与超限导入 | 不支持格式/指令/类型、非有限值、文件大小/段数越界整次拒绝并定位问题；状态与列表不变。 |
| V10 | P0 | 播放中切预设、切曲、seek | 音效持续有效、无新增中断/爆音；满足 13.1 延迟，进度/时长/歌词/统计规则不变。 |
| V11 | P0 | 重启、关闭浮层与后台关窗 | 已保存项、草稿、启用请求与 preamp 模式恢复正确；关闭浮层不丢草稿，后台继续处理；损坏数据不盲目启用或覆盖原数据。 |
| V12 | P0 | 三平台与性能 | 实际分发的 libmpv/FFmpeg 验证 P0 能力，按 13.1 记录 CPU/延迟/断流，音效行为一致。 |
| V13 | P0 | 临时文件、资料库切换 | 资料库外文件应用同一音效；切换资料库保留曲线与全局状态，临时项不写统计/资料库。 |
| V14 | P0 | 数据与离线边界 | 断网完整执行 P0；音效本身不发起网络请求，数据仅在本机偏好，不进入 SQLite、echo/ 控制面、outbox 或同步载荷。 |
| V15 | P0 | 浮层互斥、关闭与键盘 | 重复点击、外部点击、Escape、Tab 离开符合约定；音效与播放队列互斥；内部操作不误关，焦点归还与标签/推子读屏正确。 |
| V16 | P0 | 快速输入与故障注入 | 连续拖动后立即关闭/重置/选其他预设，最终状态不被旧确认覆盖；注入应用失败回滚或旁路，注入写入失败不报保存成功且可重试。 |
| V17 | P0 | 暂停、无音轨、静音/音量 | 编辑不自动播放；下次首个输出样本即应用；开关/保护不改用户音量与静音状态。 |
| V18 | P0 | 采样率、声道与输出重建 | 44.1/48/96/22.05 kHz 及既有支持采样率切换正确；不可用频段旁路且参数保留，空间输入不支持时明确反馈，支持恢复后重新应用。 |
| V19 | P1 | 导入预览与导出往返 | 近似转换显式接受、误差满足已定阈值；取消无副作用；Echo 原生格式往返一致，转换结果与原始文件可分别导出，编辑另存不冒充原文件。 |

## 附录 A：证据与参考来源

| 来源 | 用途与边界 |
|---|---|
| [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/) | RBJ peaking 系数、Q/BW 定义与数字带宽修正；边界：不推荐某音乐类型的精确曲线，也不证明随包滤镜与计算一致 |
| [RaneNote 170](https://www.ranecommercial.com/legacy/note170.html) | 带通滤波器 BW/Q 的关系，1 octave对应Q≈1.414；边界：不直接证明数字 peaking 所有频段严格一倍频程或ISO/IEC合规 |
| [iZotope 母带 EQ 指南](https://www.izotope.com/community/blog/how-to-eq-your-master) | 按素材克制调节、匹配增益A/B减少响度偏差；边界：不提供 Echo 九条预设或通用播放器genre配方 |
| [iZotope 人声 EQ 指南](https://www.izotope.com/community/blog/how-to-eq-vocals) | 存在感约1.5–5kHz、齿音常见5–8kHz，静态削减可能暗淡；边界：独立人声轨教学不能等同整曲人声增强或动态去齿音 |
| [iZotope M/S 指南](https://www.izotope.com/community/blog/what-is-midside-processing) | 拓宽的取舍、中央元素及mono兼容性检查；边界：不为width=1.25背书，不保证所有歌曲拓宽后更好 |
| [ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770/en) | 节目响度及true-peak测量算法；边界：不规定此应用的genre曲线、sample limiter时间常数或输出目标 |
| [FabFilter true-peak手册](https://www.fabfilter.com/help/pro-l/using/truepeaklimiting) | sample/true-peak区别，过采样与重建峰值风险；边界：该产品的true-peak保证不能移植给FFmpeg alimiter |
| [AutoEq 官方仓库](https://github.com/jaakkopasanen/AutoEq) 与 [结果导出实现](https://github.com/jaakkopasanen/AutoEq/blob/master/autoeq/frequency_response.py) | 核实 AutoEq 可生成多种 EQ 配置，不能把 FFmpeg 串等同全部 AutoEq 格式；P1 应以具体结果样本建立解析验收。 |
| [FFmpeg equalizer 文档](https://ffmpeg.org/ffmpeg-filters.html#equalizer) | 核实频率、带宽/Q、增益与运行时命令；多个滤波器串联的实际响应需计算。 |
| [FFmpeg extrastereo 文档](https://ffmpeg.org/ffmpeg-filters.html#extrastereo) | 候选声道拓宽处理，需验证其内部 clipping 设置与增益风险，不能仅依赖后置衰减。 |
| [mpv stable 手册](https://mpv.io/manual/stable/)（Audio Filters、af-command） | 核实 lavfi 与运行时命令的 API 方向；不代表 Echo 打包的版本支持所有滤镜/命令。 |
| `crates/echo-desktop/src/player/actor.rs` | 现有 libmpv actor、loadfile 与连续属性订阅；尚无应用级 EQ/滤镜控制路径，也未观察当前处理采样率或输出设备。 |

| `docs/PRODUCT.md`、`docs/ROADMAP.md` | Core/播放适配层边界与路线图事实；音效尚需正式立项。 |
