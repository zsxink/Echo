## Why

一期虽不提供可操作的多端同步，但导入文件当前直接落在资料库根目录，且未来同步所需的歌曲身份、收藏和歌单关联没有一份可携带的资料库布局契约。若在二期才改变目录或从每台设备的 SQLite 反推同步数据，将造成文件迁移、UUID 重建及跨设备状态丢失风险。

## What Changes

- 将 Echo 管理导入的音频与同名歌词固定存放到资料库根目录的 `media/` 下，使用 `media/<歌手>/<歌手> - <歌曲名>.<原扩展名>` 的相对路径。
- 为资料库定义可见的 `echo/` 控制面目录与版本化对象记录；歌曲、收藏、歌单、歌单成员和墓碑均以稳定 UUID 表达，临时文件收纳于不同步的 `echo/tmp/`。
- 明确可同步载荷、资料库文件与本机 SQLite/凭据/缓存的边界；所有歌曲定位继续只使用资料库逻辑 ID 和规范化相对路径。
- 固化新设备通过设置连接同一同步资料、恢复对象记录、扫描媒体并重建本机索引的恢复语义；尚未到二期时不新增远端连接或同步 UI。
- **BREAKING**：导入目标相对路径从 `<歌手>/<歌手> - <歌曲名>` 改为 `media/<歌手>/<歌手> - <歌曲名>`；既有资料库不提供扫描兼容或 UUID 迁移，用户须重新建立资料库或重新导入媒体。

## Capabilities

### New Capabilities

- `portable-library-layout`: 定义可携带的资料库目录、对象文档及新设备恢复契约。

### Modified Capabilities

- `safe-file-ingestion`: 将受 Echo 管理的导入目标固定到 `media/`，并隔离不可同步的暂存目录。
- `local-library`: 将受管理媒体和可见控制面目录作为资料库的唯一受支持布局。
- `sync-foundation`: 扩充可同步对象形状、设备写入顺序与不含本机路径的可携带载荷要求。
- `playlist-management`: 将歌单成员建模为稳定成员对象，以支持跨设备恢复、删除传播和确定性顺序。

## Impact

- 影响 `echo-core` 的导入路径规划、扫描忽略规则、SQLite 迁移、Repository/同步 outbox 载荷、操作日志恢复及测试夹具。
- 二期 S3/WebDAV 连接器将消费该目录与对象协议，但本 change 不实现网络连接、认证或同步界面。
- 需要同步更新 `docs/DESIGN.md`、`docs/ROADMAP.md` 中仍使用根目录艺人文件夹的示例和一期目标说明。
- 设计遵守 Core 与 UI/播放器隔离、SQLite 不上传、文件系统与数据库通过操作日志恢复的既有规范。
