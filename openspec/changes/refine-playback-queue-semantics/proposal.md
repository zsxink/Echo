## Why

播放队列面板当前缺少可辨识的歌曲信息，且核心的待播顺序与三种播放模式的上一首、下一首和“下一首播放”之间尚未形成完整且可验证的契约。先固化队列状态与导航规则，才能在后续 UI 调整中稳定呈现正确的队列。

## What Changes

- 明确播放队列的规范化投影：当前播放项始终置顶，待播项按实际下一首顺序排列，并携带歌曲标题、艺人、封面和时长等展示信息。
- 定义列表循环、随机播放与单曲循环下的上一首、下一首、自然结束和队列耗尽行为；单曲循环下手动“下一首”按列表循环推进。
- 定义“下一首播放”的连续插入点：多次操作保持用户操作顺序，新增项进入尚未播放的下一首区段，不替换当前歌曲。
- 明确从任意曲库视图或歌单开始播放会丢弃当前播放队列及手动插入项，并仅以桌面端解析的该视图完整歌曲集合重建队列，禁止以分页或前端传入的部分歌曲替代。
- 规划播放队列面板的后续呈现：默认最多显示 8 首，超出区域内滚动，同时保持当前项可见且置顶；本 change 只建立实现计划，不直接改 UI。
- 以普通模式为尺寸基准，统一普通模式与沉浸模式下播放队列面板及歌曲行的尺寸。
- 补充平台层队列状态机、Tauri 快照/命令 DTO、React 队列面板和回归测试的实现与验证任务。

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `desktop-playback`: 补全队列投影、模式相关导航和连续“下一首播放”插入的用户可见行为。

## Impact

- 受影响的桌面平台层包括 `crates/echo-desktop/src/player/queue.rs`、`coordinator.rs` 和会话持久化；播放队列仍严格留在桌面层，不进入 `echo-core`。
- Tauri `queue_command`、播放器快照 DTO 及其 React 消费方可能需要同步演进，需保持类型化边界并覆盖恢复兼容性。
- 后续 UI 工作涉及 `apps/desktop/src/features/player/QueuePanel.tsx`、沉浸模式布局、相关样式和测试；图片所示的列表行不再使用占位歌曲信息。
