# NativeSyncProvisioner state ownership

`NativeSyncProvisioner::new` in `apps/desktop/src-tauri/src/sync_provisioner.rs` is side-effect-free: it stores injected capabilities and initializes in-memory coordination state. The composition root owns construction. This map records current ownership before any extraction; it does not imply that every field should become a separate collaborator.

| State                                                                   | Created / owner                           | Consumers and lifecycle                                                                                   | Sharing / extraction decision                                                                                                                                        |
| ----------------------------------------------------------------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `database: Arc<SqliteDatabase>`                                         | Injected; shared database adapter         | Binding/configuration, mutation, checkpoint and authorization operations; released with remaining `Arc`s  | Database/transaction owner remains SQLite adapter; never split into another connection owner.                                                                        |
| `private_resources: PathBuf`                                            | Injected; provisioner retains path        | Derives per-binding resource cache directory                                                              | Path is configuration, not a lifecycle collaborator.                                                                                                                 |
| `publication: RemoteResourcePublishDeps`                                | Injected bundle with shared collaborators | Remote resource publication                                                                               | Its filesystem/hasher/journal retain their own owners; do not duplicate them.                                                                                        |
| `scan_deps: Arc<ScanDeps>`                                              | Injected shared capability                | Scan repository/adapters used by sync operations                                                          | No provisioner reset; collaborators retain external ownership.                                                                                                       |
| `scan_supervisor: ScanSupervisor`                                       | Injected clone over shared state          | Coordinates scans and sync/scan interactions                                                              | Active registrations have supervisor lifecycle; do not extract without distinct consumer boundary.                                                                   |
| `gate: Mutex<()>`                                                       | Provisioner-owned                         | Serializes provisioning and lifecycle operations; lock releases at scope exit                             | Shares consistency boundary with provisioner operations.                                                                                                             |
| `pending_catalog_changed: Arc<AtomicBool>`                              | Provisioner-owned shared flag             | Preserves catalog-change result across failed/cancelled cycles; consumed/cleared on successful completion | Must outlive one cycle; not a cycle-local field.                                                                                                                     |
| `host_seen_checkpoint: Mutex<Option<CommitCheckpoint>>`                 | Provisioner-owned cache                   | Remembers observed host checkpoint                                                                        | Instance-scoped; no independently owned persistence.                                                                                                                 |
| `local_wakes: Mutex<Option<LocalWakeChannel>>`                          | Provisioner-owned optional listener       | Listener sender keeps writer actor registration alive; drain handles pending local wake hints             | Drop/replacement disconnects listener. Kept distinct from runtime loop wake channel.                                                                                 |
| `uploaded_resources: Mutex<HashSet<(SyncBinding, String)>>`             | Provisioner-owned cache                   | Avoids repeated preparation for acknowledged resources; peer cleanup prunes binding entries               | Binding/session scoped and cleared on peer completion; not durable persistence.                                                                                      |
| `resource_stores: Mutex<HashMap<SyncBinding, Weak<FileResourceStore>>>` | Provisioner-owned weak registry           | Reuses a live binding store; prunes dead weak entries; detach/worker operations clear cache               | Active operations own strong `Arc`s. Host and workers must share the same store to coordinate cleanup and transfers. Do not split this registry from that lifecycle. |
| `transfer_telemetry: Mutex<Arc<Mutex<TransferTelemetry>>>`              | Provisioner-owned replaceable telemetry   | Cycle operations clone current telemetry and update progress                                              | Nested synchronization allows in-flight observers to retain a cycle snapshot; reset behavior must remain unchanged.                                                  |

Provisioning and detach paths are serialized with `gate`; runtime transitions are separately serialized by the runtime transition mutex. Credential/checkpoint durable stores and filesystem caches are not owned solely by this struct. Current evidence supports keeping the shared caches/coordination in `NativeSyncProvisioner`; extraction is justified only if a concrete independent lifecycle, narrow consumer and test boundary emerges.
