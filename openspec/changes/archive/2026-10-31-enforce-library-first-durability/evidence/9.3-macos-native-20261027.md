# 9.3 macOS temporary-library validation — 2026-10-27

Environment: macOS 27.0.1 (26A434), arm64; Rust 1.98.1, Cargo 1.98.1.
All cases use repository tests that create disposable temporary directories or
temporary databases. No real library or user application database was touched.

## Results

| Area | Executed case | Result |
| --- | --- | --- |
| Reinstall-style / directory-only recovery | `library_durability_readonly_volume_and_unmaterialized_commit_can_be_browsed` | pass; read path remains available without write access and before materialization |
| Concurrent process lock | `library_durability_cross_process_writer_exclusion_and_reader_access` | pass; child process is exercised, a competing writer is excluded, readers remain available |
| Symlink safety | `library_durability_symlink_unknown_format_and_invalid_resource_fail_before_marker` | pass; unsafe path does not publish a commit marker |
| Unicode and case-equivalent resource names | `case_and_unicode_equivalent_resource_destinations_cannot_claim_two_files`; `foreign_case_or_unicode_spelling_is_never_published_as_a_second_file` | both pass |
| Disk-full / permission failure behavior | `disk_full_or_permission_loss_aborts_staging_copy_before_publication` | pass; deterministic injected filesystem failure aborts before publication |

Commands were run individually from the repository root with `cargo test -p
echo-core <test-name>`; every named test ran 1/1 and exited 0. Temporary test
fixtures are cleaned up by the test harness.

## Limits and platform scope

At the user's direction, Windows and Linux native validation is skipped. macOS
tests cover the repository's native filesystem/process behavior, but this is
not a physical-volume detach test or a real ENOSPC test. Volume removal,
physical media failure, and filesystem exhaustion remain unverified. The disk
full case is a deterministic injected failure. Cross-platform file-handle
occupation behavior is not claimed. No OS reinstall was performed; the
directory-only recovery test exercises the portable recovery boundary without
deleting application data.
