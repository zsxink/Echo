3. **LD-07c 不得引用 LD-07a/LD-07b 的用例。** `library_durability_mark_published_legacy_unseeded_ledger_keeps_full_rescue`
   是"老账本全量救援"，不涉及 ACK 丢失 + 新 binding；`library_durability_rejects_foreign_directory_batch_chain_and_checkpoint`
   只验拒绝外来链，不验"至多一个映射事件"。
4. **LD-09c 不得引用 `walker_*` 或 `library_durability_scan_preserves_record_when_media_disappears`。**
   前者只验"不进控制面枚举"，后者验"媒体消失保留记录"，都不涉及"仅剩媒体、favorites/playlists
   明确不可恢复"的标签语义。本行如实记为 `无`。
5. **LD-03a 不得引用 `a_wiped_database_is_rebuilt_from_the_records_at_real_scale`。** 该用例只重建
   本地目录记录（87 曲 / 11 收藏），无 LAN 接收对象参与。
6. **命令形态陷阱（会产出假通过/假失败）**：`pnpm verify:scenario -- <id>` 恒 exit 1
   （`run-scenario.mjs` 把 `--` 当未知 id），单场景验证须 `node scripts/verify/run-scenario.mjs <id>`；
   `pnpm --filter @echo/desktop test -- --run <file>` 里的多余 `--` 同样吞掉过滤器，实测
   跑了全部 49 文件 / 445 条（exit 0，看似"通过"但根本没命中目标用例）。本表前端命令一律用
   实测命中的形态 `pnpm --filter @echo/desktop test <file>`（实测 `savedPendingFeedback.test.tsx`
   7 条、`libraryPersistence.test.ts` 4 条）。
7. **`cargo test -p echo-sync` 必须带 `--all-features`。** 不带时 `tests/discovery_network.rs`
   因 `discovery` 特性未开而编译失败（`crates/echo-sync/src/lib.rs:11-12`），那是特性开关，
   不是回归；带全特性后该目标 3 条全 `#[ignore]`。

## 三、明确不在短 CI 范围

- **LD-10a 的原生部分**：需 macOS/Windows/Linux 三平台原生运行记录与治理门实测输出。
- **LD-08b、LD-09a/LD-09b 的平台语义部分**：目录 rename/sync、只读卷、长路径/Unicode
  需三平台原生。
- **LD-03a 的 LAN 真实传输**：依赖真实网络与 `echo-sync --all-features`；`discovery_network`
  3 条在带特性时仍全 `#[ignore]`。
- **513 规模用例**：`513 real host publications exceed the governance time budget` 与
  `real LAN host rate limit makes 513 uploads take several minutes` 按任务口径不计入通过。
- **完整 workspace 全量作为交付门槛**：治理门确实跑 `cargo test --workspace --all-targets --all-features`
  （`scripts/verify/ci-governance.mjs:15`），所以全量 workspace 测试在门内是被执行的；
  但按 9.5 原文与 `acceptance-matrix.md` 的 Evidence boundary，它属整体发布门槛，
  本 change 不以它作为交付依据。上表各行的 `cargo test -p <crate>` 是**定位单条用例**的命令形态。

## 四、无法在本机验证项

## 五、未闭合规格张力（上报，不在本索引内消化）

1. **LD-05a 与 `relink` 实现方向相反。** LD-05 要求"不得因路径、墙钟或音乐键自动合并或改写关系"，
   而 `RelinkPlanner::resolve`（`crates/echo-core/src/application/relink.rs:107-170`）第 2、3 步
   正是 hash 与 music-key 驱动的 `Relink`，`relink_plans_cover_path_hash_and_music_key_rules`
   （:391）把它断言为期望行为。二者不可能同时为真，需产品/规格决策。
2. **9.6 已上报的两项**：`resolve_host_sync_conflict`（`sync_conflicts.rs:139-189`）是生产可达的
   DB-first 用户事实写入；`ensure_*_sync_baseline` 的豁免在 LD-01 文字中无书面记载。
   详见 [9.6 DB-first 残留复核](9.6-db-first-residue-review-20261027.md)。
3. **7.7 / 9.1 阻塞使 LD-07c 与"主机 + 两从"综合场景无自动化证据**：`StateKind::Adoption`
   无生产编排、无 LAN 旧 receipt 查询/负 receipt、无生产 override 写入口、fixture 仅主机 + 单从。
