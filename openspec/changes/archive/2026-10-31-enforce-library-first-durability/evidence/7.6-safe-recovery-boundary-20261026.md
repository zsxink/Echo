# 7.6 Safe LAN recovery boundary (2026-10-26)

`docs/lan-sync-recovery.md` now explains that ACK proves only its exact mutation
and published checkpoint; resource transfer completion and `mediaReady` do not
prove that every object, resource version, pending edit, or backup reached each
peer. A restored library is usable offline from its directory without loading
credentials or automatically starting networking. The old epoch remains fenced
until its independently stored trust ledger and checkpoint validate; pairing or
hosting requires an explicit user action.

The implementation preserves this boundary:

- `RetryLibraryOperation::catch_up` is directory replay and projection only; it
  does not provision a session or start networking.
- `NativeSyncProvisioner::recover_saved_sync_state` consumes retained sync facts
  only after the caller supplies a checkpoint whose live credentials were
  verified. The context itself is not serializable and SQL rechecks the active
  binding/author.
- Startup refuses restored/forked history before repair; an unconfigured runtime
  stays offline; retry restore without a binding does not provision.

Verification (each command had one matching test):

- `cargo test -p echo-app --bin Echo startup_refuses_restored_or_forked_history_before_repair` — 1 passed.
- `cargo test -p echo-app --bin Echo unconfigured_runtime_stays_offline_and_stop_is_idempotent` — 1 passed.
- `cargo test -p echo-app --bin Echo restore_does_not_provision_without_a_binding` — 1 passed.

No LAN resource wire field was added. Version behavior is recorded in the
[7.8 compatibility evidence](7.8-version-compatibility-20261026.md).
