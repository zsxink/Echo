# 7.5 Resource retention and lifecycle evidence (2026-10-26)

SQLite resource holds now include resources referenced by directory-replayed
records, terminal retained candidate facts, host epoch archives (mutations,
confirmed commits, and snapshot resource references), current/archive
conflicts, and the current catalog. Archive lookups are scoped to the local
library root. A rebuild still replaces holds in one transaction, so malformed
source evidence leaves the prior holds intact; the resource reclamation path
continues to require successful hold reconstruction.

Two new tests exercise the missing links:

- A real 34-commit directory is compacted, projected into a fresh database,
  switched to another root, and rebuilt repeatedly. Directory resource/state
  declarations remain available and the replay does not create a sync outbox
  echo.
- Host epoch rotation retains confirmed-only resources and a rejected
  candidate's resource version through archive reconstruction.

Verification:

- `cargo test -p echo-core --lib resource_retention` — 4 passed.
- `cargo test -p echo-sync --all-features --lib lifecycle_reference_map_keeps_resumable_and_referenced_bytes_only` — 1 passed.
- The two owned Rust files passed `rustfmt --check` and `git diff --check`.

This is the resource-reference retention contract, not the full host-plus-two
replica restoration scenario in 9.1 or multi-platform native exercise in 9.3.
