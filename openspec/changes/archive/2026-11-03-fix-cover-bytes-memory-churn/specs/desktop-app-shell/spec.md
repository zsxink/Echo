# Spec Delta

## ADDED Requirements

### Requirement: 封面字节必须以受控载荷传递

桌面应用 SHALL 通过 Tauri command 传递封面字节时使用 base64 字符串载荷，MUST NOT 以 JSON 数字数组逐字节摊平传输；载荷 MUST 在 Tauri command 边界解码为原始字节后，再进入既有的封面校验与持久化路径。歌单封面与艺人封面 MUST 使用同一编码。

封面编辑的对外语义 MUST 保持不变：设置封面、替换封面、恢复自动封面与不修改已保存封面 MUST 与既有行为一致。前端 MUST 保留选图体积上限校验，并 MUST 通过选图控件限定可选的图片类型（JPEG、PNG、WebP）；后端 MUST 保留等价的体积上限与类型白名单校验；任一层拒绝时 MUST 明确说明原因，并保留已保存封面与已输入的名称。

解码 MUST 在分配解码缓冲之前按编码长度预检上限，MUST NOT 为超限载荷分配内存。载荷无法解码时 MUST 报告可识别的输入错误，MUST NOT 以空封面或破损图像覆盖已保存封面。

#### Scenario: 选封面载荷不摊平字节

- **WHEN** 用户在编辑歌单对话框选择一张封面图片并确认保存
- **THEN** 传给后端的封面载荷是 base64 字符串而非逐字节数字数组，界面状态中不保留逐字节数组

#### Scenario: 解码后字节与所选图片一致

- **WHEN** 后端收到 base64 封面载荷并解码
- **THEN** 解码结果与用户所选图片的字节完全一致

#### Scenario: 歌单与艺人封面使用同一编码

- **WHEN** 客户端为歌单或为艺人提交封面
- **THEN** 两个命令的封面载荷都使用 base64 编码，后端共用同一条解码路径

#### Scenario: 超过上限的封面被拒绝

- **WHEN** 用户选择的封面图片超过 5 MB
- **THEN** 前端在选图阶段拒绝并说明原因，已保存封面与名称输入保持不变

#### Scenario: 不受支持的封面类型被拒绝

- **WHEN** 提交的封面载荷不是 JPEG、PNG 或 WebP
- **THEN** 系统拒绝该封面并说明原因，不以破损图像替换已保存封面

#### Scenario: 载荷损坏时不覆盖已保存封面

- **WHEN** 提交的封面载荷无法解码为合法字节
- **THEN** 系统报告可识别的输入错误并保留已保存封面，不写入空或破损封面

### Requirement: 封面预览的临时资源必须被回收

编辑歌单对话框产生的封面预览临时资源 MUST 在被替换或对话框卸载时被释放，MUST NOT 随每次选图在渲染进程中持续累积。预览 MUST 继续展示用户当前所选或已保存的封面；预览所依据的图片 MUST NOT 以逐字节数组形式保留在界面状态中。

#### Scenario: 重新选图释放旧预览资源

- **WHEN** 用户在编辑歌单对话框选择一张封面图片后再次选择另一张
- **THEN** 第一张图片的预览资源被释放，界面只保留当前所选图片的预览

#### Scenario: 关闭对话框释放预览资源

- **WHEN** 用户关闭编辑歌单对话框
- **THEN** 该对话框产生的封面预览资源全部被释放，已保存封面保持不变

#### Scenario: 预览展示用户所选封面

- **WHEN** 用户在编辑歌单对话框选择一张封面图片
- **THEN** 预览显示该图片，且界面状态中不保留该图片的逐字节数组
