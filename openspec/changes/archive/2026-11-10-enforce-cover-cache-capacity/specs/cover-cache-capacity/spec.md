# Spec Delta

## Purpose

定义封面缓存在容量超限时的可执行回收语义：把可重建的缩略图作为唯一回收对象，在不破坏被引用原图与既有封面读取契约的前提下让缓存占用回到上限内，并为被淘汰的缩略图保留按需重建能力。

## ADDED Requirements

### Requirement: 容量超限时必须回收可重建缩略图

封面缓存的容量占用 MUST 按缓存目录内全部文件的字节数计算，且 MUST 包含按需生成的两档缩略图。除「原图自身超限时必须保留缩略图并如实报告」定义的不可达标情形外，当被引用条目使总占用超过容量上限时，回收 SHALL 只删除已落盘的缩略图文件（`thumb-512.bin`、`thumb-128.bin`），直至总占用不超过上限或已无可回收缩略图；回收 MUST NOT 删除条目目录、原图（`original.bin`）、MIME 记录（`mime.txt`）或写入中断留下的临时文件。

淘汰顺序 MUST 确定且可重复：详情档（512px）先于列表档（128px）；同一档位内按文件占用从大到小排序，占用相同则按内容哈希字典序。达到上限时 MUST 立即停止，MUST NOT 删除多余缩略图。单个缩略图删除失败 MUST NOT 使整次回收失败：MUST 以结构化日志记录失败并继续处理其余候选；即使因此未能达标，也 MUST NOT 转而删除原图。

#### Scenario: 缩略图把缓存推过容量上限后被回收

- **WHEN** 被引用条目原图与 MIME 记录的总占用低于上限，但生成 128px 与 512px 缩略图后总占用超过上限，并执行封面缓存回收
- **THEN** 回收成功返回，回收后的总占用不超过上限，全部被引用原图仍可读，且至少一档缩略图文件已被删除

#### Scenario: 详情档优先于列表档被淘汰

- **WHEN** 总占用超过上限，且只删除 512px 缩略图即可回到上限内
- **THEN** 512px 缩略图被删除、128px 缩略图仍保留并可读取，回收后的总占用不超过上限

#### Scenario: 达到上限即停止淘汰

- **WHEN** 缓存中有多个条目的缩略图，且删除其中一部分即可回到上限内
- **THEN** 只删除排序靠前且足以达标的文件，其余未被删除的缩略图仍保持原有字节与可读性

#### Scenario: 临时文件与原图不被容量回收误删

- **WHEN** 被引用条目中同时存在原图、MIME 记录、正式缩略图与写入中断留下的 `*.tmp` 文件，且缓存超过上限
- **THEN** 回收只可能删除正式缩略图文件，原图、MIME 记录与临时文件保持原状，原图仍可通过原图档位读取

#### Scenario: 单个缩略图删除失败仍继续回收

- **WHEN** 排序靠前的缩略图因文件系统错误无法删除，且后续候选仍可回收
- **THEN** 回收成功返回并记录该失败，后续候选按既定顺序继续被淘汰，原图保持可读

### Requirement: 容量规则不得破坏引用完整性

仍被歌曲、歌单或艺人封面引用的缓存条目，其原图与 MIME 记录 MUST NOT 因容量超限被删除。未被任何引用覆盖的缓存条目 MUST 继续按既有语义整目录删除；无法解析或格式不合法的引用 key MUST NOT 影响引用集合，也 MUST NOT 导致额外的文件系统删除。容量回收 MUST 在引用条目清理之后执行，且 MUST NOT 让「被引用」这一判定因某条目缺少缩略图而改变。

#### Scenario: 超限时被引用原图保持可读

- **WHEN** 多个被引用条目的总占用超过上限，且其中包含大体积原图
- **THEN** 回收后每一个被引用条目的原图字节与回收前完全一致，按原图档位读取成功

#### Scenario: 未引用条目仍被整目录清理

- **WHEN** 缓存中同时存在被引用条目与未引用条目，且总占用超过上限
- **THEN** 未引用条目的整个目录（含其原图与缩略图）被删除，被引用条目仅按容量规则淘汰缩略图

#### Scenario: 畸形引用 key 不改变回收结果

- **WHEN** 引用集合中包含无法解析的 key 或格式不合法的资产 key，并执行回收
- **THEN** 回收仍以合法的内容哈希引用为准，畸形 key 不产生额外删除，且不使回收返回错误

### Requirement: 原图自身超限时必须保留缩略图并如实报告

若删除全部可回收缩略图后仍无法使总占用回到上限内（即被引用原图与 MIME 记录本身已超限），回收 MUST NOT 删除任何缩略图，MUST 成功返回，并 MUST 以结构化日志说明「被引用原图占用已超上限、容量不可达标」。连续多次回收 MUST 产生相同结果，MUST NOT 出现每次启动都清空缩略图却仍超限的反复删除。

#### Scenario: 原图占用本身已超上限

- **WHEN** 被引用条目的原图与 MIME 记录之和已大于容量上限，且条目下存在两档缩略图
- **THEN** 回收成功返回，原图与两档缩略图全部保留且字节不变，日志记录不可达标的原因

#### Scenario: 连续回收不反复清空缩略图

- **WHEN** 在原图已超限的缓存上连续执行两次回收，期间不生成新文件
- **THEN** 两次回收后的文件集合与总占用完全相同，第二次回收不删除任何缩略图

### Requirement: 被淘汰的缩略图必须能按需重建

被容量回收删除的缩略图，在下次请求对应档位时 MUST 从保留的原图重新生成、原子落盘并在后续请求中复用；重建 MUST NOT 改变封面协议档位、内容寻址、不可变缓存语义或缩略图尺寸上限。同一条目同一档位的并发首访 MUST 合并为一次解码与缩放；生成失败 MUST NOT 留下可被读取的半成品缩略图，且 MUST NOT 破坏原图读取。

#### Scenario: 淘汰后再次请求重建并复用

- **WHEN** 某档缩略图被容量回收删除后，界面再次请求该档位
- **THEN** 返回符合该档位尺寸上限的 JPEG 缩略图，磁盘上重新出现对应文件，后续同档请求直接复用且不重复解码

#### Scenario: 并发重建仍只解码一次

- **WHEN** 多个调用方在同一条目被淘汰的档位上并发首访
- **THEN** 只发生一次解码与缩放，所有调用方得到相同字节，不产生重复临时文件

#### Scenario: 重建失败不产生可读半成品

- **WHEN** 原图不可解码或缩略图写入在重建过程中失败
- **THEN** 不存在可被读取的正式缩略图文件，原图仍可通过原图档位读取，后续请求可以重试
