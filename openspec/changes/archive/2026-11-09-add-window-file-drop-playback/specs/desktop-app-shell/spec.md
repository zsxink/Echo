# Spec Delta

## ADDED Requirements

### Requirement: 窗口级文件投放必须提供进入与离开反馈

系统 SHALL 在受支持的音频文件拖入主窗口范围时显示覆盖整个窗口的「松手即播放」投放反馈层，在拖拽离开窗口范围或取消时立即移除该反馈层；反馈 MUST NOT 只依赖光标样式。投放反馈层 MUST 具有可读名称，MUST 不拦截指针事件——macOS overlay 标题栏拖拽条、Windows 自绘窗口按钮与既有浮层的命中区域 MUST 保持可用；反馈层 MUST NOT 改变沉浸式播放器、歌词专注阅读等既有覆盖层的层级或 Escape 逐层退出语义。在 `prefers-reduced-motion` 下系统 MUST 去除反馈层的动效但保留状态变化。反馈层视觉材质 MUST 复用音效浮层所用的克制浮层语言，不得引入第二套浮层样式。

#### Scenario: 拖入受支持音频出现反馈
- **WHEN** 用户从系统文件管理器把一个或多个受支持音频文件拖入 Echo 主窗口范围
- **THEN** 覆盖整个窗口的「松手即播放」反馈层出现，带有可读名称，且不只表现为光标变化

#### Scenario: 拖离或取消后反馈消失
- **WHEN** 用户在未松手的情况下把文件拖离窗口范围，或取消本次拖拽
- **THEN** 投放反馈层立即消失，当前播放状态、队列与资料库内容均不发生变化

#### Scenario: 反馈层不遮挡窗口控件与拖拽条
- **WHEN** 投放反馈层可见时用户操作顶部标题栏拖拽条、Windows 自绘最小化/最大化/关闭按钮或已打开的浮层
- **THEN** 这些控件仍按既有行为响应，反馈层不拦截指针事件

#### Scenario: 沉浸模式与既有浮层下投放
- **WHEN** 沉浸式播放器或歌词专注阅读处于展开状态，且播放队列面板或音效浮层已打开时拖入音频
- **THEN** 投放反馈按同一规则出现与消失，既有覆盖层层级不变，Escape 仍按既定优先级逐层退出

#### Scenario: 减少动画设置下保留状态变化
- **WHEN** 系统启用 `prefers-reduced-motion` 后拖入并拖离音频
- **THEN** 反馈层无过渡动效，但出现与消失两个状态变化仍完整可见且可读

### Requirement: 松手投放必须立即播放且只接受受支持的单个音频文件

系统 SHALL 在用户松手投放后立即播放过滤后按拖放顺序排列的第 1 个文件，MUST NOT 要求确认弹窗或再次点击播放键；播放语义 MUST 与系统文件管理器双击打开完全一致，并复用同一文件打开通道：活动资料库内的文件 MUST 使用其既有稳定 UUID，资料库外文件 MUST 建立当前会话临时播放项。扩展名过滤口径 MUST 与 Core 支持矩阵严格一致。文件夹 MUST 被拒绝并提示逐个拖入文件，MUST NOT 递归扫描、取目录顶层音频或视为添加扫描目录；非音频文件 MUST 被拒绝并给出明确可读反馈，MUST NOT 静默无反应。一次投放同时含受支持与被拒绝项时，系统 MUST 按拖放顺序播放受支持项并对每个被拒绝项给出可读原因。投放 MUST NOT 引入文件系统、shell 或对话框权限族。资料库根目录不可用或只读时，资料库外文件的临时播放 MUST 仍可发声。

#### Scenario: 单文件松手即播
- **WHEN** 用户把一个资料库外的受支持音频文件拖入窗口松手
- **THEN** 系统不显示确认弹窗、不等待额外播放操作，立即创建临时播放项并开始播放

#### Scenario: 与双击打开同语义
- **WHEN** 用户投放的文件位于当前活动资料库内，或位于非活动的旧资料库根目录
- **THEN** 库内文件以其既有 UUID 播放且不创建临时项；旧根文件按活动根隔离规则作为当前会话临时项播放，与双击打开该路径的结果一致

#### Scenario: 非音频文件可读拒绝
- **WHEN** 用户投放扩展名不在 Core 支持矩阵内的文件
- **THEN** 系统明确提示该文件不受支持，不创建播放项、不改变当前队列与播放状态

#### Scenario: 文件夹可读拒绝
- **WHEN** 用户投放一个文件夹
- **THEN** 系统明确提示只接受单个音频文件，不递归扫描、不取顶层音频、不把目录登记为扫描根目录，也不改变当前播放状态

#### Scenario: 混合投放部分拒绝
- **WHEN** 一次投放包含受支持音频、非音频文件与文件夹
- **THEN** 受支持音频按其在拖放序列中的相对顺序进入播放，每个被拒绝项分别给出可读原因，被拒绝项不进入队列

#### Scenario: 不扩权限面
- **WHEN** 检查 WebView capability 权限清单在实现投放前后
- **THEN** 清单仍只包含显式 command/event 与最小 window 权限，未引入文件系统、shell 或对话框权限族

#### Scenario: 资料库只读或不可用时仍可播
- **WHEN** 当前资料库根目录不可写或已标记为不可用，用户投放一个资料库外音频
- **THEN** 系统仍以临时播放项发声，不触发写入门，也不改变资料库内容

### Requirement: 投放路径与到达时机必须与文件打开通道一致

系统 SHALL 把投放得到的路径作为**已解码的绝对路径**交给既有文件打开通道；前端 MUST NOT 对其做二次 URL 解码，文件名中合法存在的 `%20` 字面量、中文与空格 MUST 原样保留。前端文件打开监听器尚未就绪时到达的投放请求 MUST 排队或明确拒绝，MUST NOT 被静默吞掉；就绪后 MUST 按到达顺序补发。macOS、Windows、Linux 上投放的捕获、反馈、过滤与播放结果 MUST 一致。

#### Scenario: 特殊字符文件名不被二次解码
- **WHEN** 投放的文件名合法包含 `%20` 字面量、中文或空格
- **THEN** 显示名取路径末段原样呈现，播放加载的是同一绝对路径，不出现解码后的错误路径

#### Scenario: 监听器未就绪时到达的投放
- **WHEN** 应用冷启动或前端加载期间发生文件投放，此时文件打开事件监听器尚未注册
- **THEN** 投放路径按到达顺序暂存，监听器就绪后补发并播放；无法暂存时给出明确失败反馈，不静默丢弃

#### Scenario: 三平台行为一致
- **WHEN** 在 macOS、Windows、Linux 上分别投放同一个多文件集合
- **THEN** 三者的反馈层出现/消失、过滤结果、队列顺序与从第 1 首开始播放的行为一致，且都拿到可用的本地绝对路径
