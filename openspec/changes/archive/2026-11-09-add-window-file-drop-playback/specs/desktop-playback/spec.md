# Spec Delta

## MODIFIED Requirements

### Requirement: 临时播放项边界

系统 SHALL 支持系统文件管理器直接打开当前活动资料库外的音频作为当前会话临时播放项，但临时项不得写入 SQLite、歌单、播放统计或同步队列；只有当前活动资料库中的文件 SHALL 解析为其稳定 UUID。已保留但非活动旧根中的文件必须遵循 `safe-file-ingestion` 的活动根判定，按临时项处理，不得使用旧根 UUID 绕过隔离或静默切换资料库。用户显式将当前临时项导入成功或命中重复歌曲后，系统 MUST 将当前队列 entry 转换为导入结果对应的资料库 `SongId`，从此允许该项使用资料库歌曲能力；转换不得新建第二个队列 entry。

一次外部打开或投放传入 N 个路径时，系统 MUST 按输入顺序在**同一条**队列中建立恰好 N 个 queue entry，MUST NOT 逐个重建队列，也不得只保留最后一个；活动资料库内的路径 MUST 使用其稳定 UUID，库外路径 MUST 建立临时项，二者可混合且保持输入顺序。该操作 MUST 替换当前队列、手动「下一首播放」优先区与随机轮记录，并从第 1 个 entry 开始播放；这与单文件系统打开的既有行为一致，MUST NOT 引入追加到队尾、「下一首播放」或可切回的临时队列等新语义。队列中的临时项仍 MUST NOT 进入持久化会话或播放统计。

#### Scenario: 打开资料库外文件

- **WHEN** 用户从系统文件管理器打开资料库外的受支持音频
- **THEN** 系统创建仅存在于当前会话的临时播放项并播放，可展示内嵌信息与同名 `.lrc`，但退出会话后不持久化

#### Scenario: 临时项执行持久化操作

- **WHEN** 用户尝试将临时项加入歌单、记录播放统计或加入同步队列
- **THEN** 系统拒绝该操作并说明临时项限制，资料库内容不发生改变

#### Scenario: 临时项导入后转换为库内歌曲

- **WHEN** 用户导入当前正在播放的临时项，且导入成功或检测到资料库已有相同内容
- **THEN** 系统用结果中的 `SongId` 替换当前临时 queue entry，保留 queue entry identity、原播放位置以及导入前的播放/暂停状态；之后播放栏显示库内歌曲并允许收藏、入队和其他资料库操作

#### Scenario: 临时项导入失败不改变播放身份

- **WHEN** 当前临时项导入因不支持、资料库不可用或其他错误未产生可用 `SongId`
- **THEN** 系统保留原临时 queue entry 和播放状态，不创建虚假的库内歌曲或持久化关系，并向用户显示失败/跳过结果

#### Scenario: 一次打开或投放多个文件按序成一条队列

- **WHEN** 一次系统打开或窗口投放传入按 `A、B、C` 顺序排列的 N 个受支持音频路径
- **THEN** 系统建立恰好 N 个 queue entry，顺序为 `A、B、C`，从第 1 个 `A` 开始播放，不出现逐个重建队列或只剩最后一个文件的情况

#### Scenario: 库内与库外混合保持输入顺序

- **WHEN** 一次打开或投放中既有活动资料库内文件、也有资料库外文件
- **THEN** 库内路径以既有 UUID 入队、库外路径以临时项入队，二者在队列中的位置仍严格遵循输入顺序，且每个 entry 身份类型正确

#### Scenario: 多文件打开替换当前队列与随机轮

- **WHEN** 用户正在听一条包含普通待播项、手动「下一首播放」优先区与随机轮记录的队列，随后一次投放多个文件
- **THEN** 系统按单文件打开的既有语义替换整条队列、清空优先区与随机轮记录，新队列只含本次投放的文件并从第 1 首播放，不追加到旧队列

#### Scenario: 系统打开多个文件同样不再丢失

- **WHEN** 用户从系统文件管理器一次选中并双击打开多个资料库外音频
- **THEN** 系统与窗口投放走同一批量语义，N 个文件全部入队并按顺序播放，不再只播放最后一个
