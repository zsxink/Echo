## Context

见 `proposal.md` 及两份增量规格。当前桌面播放会话已经能持久化队列和当前 entry，并通过 `PlaybackRestoreDisposition` 区分可恢复、暂不可用和应丢弃的歌曲；歌曲领域对象已有稳定且不随后续修改变化的 `added_at`。当前缺口是：恢复后当前项被丢弃或首次导入完成时，没有统一的“无当前项 → 选择最新可用歌曲”的过渡。

系统还必须保持现有分层：资料库候选查询属于 Core/服务边界，队列和“暂停加载”属于桌面播放层，React 只负责呈现状态；Core 不依赖播放器或 UI。

## Goals / Non-Goals

**Goals:**

- 统一处理冷启动恢复、资料库重建完成、外部删除当前歌曲和首曲导入后的初始歌曲选择。
- 只从当前活动资料库中选择 `Available` 歌曲，并按 `added_at` 降序和既有稳定 tie-break 得到唯一候选。
- 通过现有暂停态队列/当前项机制建立可见的底部播放栏状态，不触发自动播放、播放统计或用户播放历史。
- 保留有效会话的队列、当前歌曲、模式、音量、静音和位置恢复语义；空库保持真正空状态。
- 为 Core 选择逻辑、桌面服务编排、队列状态和导入/恢复回归测试建立可验证边界。

**Non-Goals:**

- 不新增 `added_at`、播放会话或同步载荷字段，不修改 SQLite 迁移。
- 不改变已有队列导航、随机轮次、播放历史、删除事务或 blocked 项的持久化语义。
- 不让“最新导入”改变用户已存在且有效的当前项，也不把导入行为改成播放行为。

## Decisions

### D1: 复用歌曲入库时间选择候选，不引入新的“启动歌曲”状态

候选由当前活动根目录中 `SongAvailability::Available` 的歌曲组成，使用 `added_at DESC` 与现有确定性排序规则选择第一项。这样可以覆盖重装/新设备恢复和外部删除两条路径，并与“最近添加”产品事实一致。

备选方案是新增本机偏好记录“最后导入歌曲”或把选择写入播放会话；两者会造成跨设备/重建语义分叉，且在删除、恢复和重复打开时需要额外失效处理，因此不采用。

### D2: 在桌面服务边界集中判定“是否需要兜底”，Core 只提供可复用的候选查询

Core 负责按活动资料库和可用性返回最新歌曲的稳定 ID，不能读取播放会话或调用播放器。桌面运行时服务先完成现有恢复裁决：有效 current 保留，blocked 继续按既有语义处理，被丢弃或不存在 current 才请求候选；导入完成后仅在会话没有 current 时请求同一候选。

这使用“策略/判定与执行分离”的边界：Core 提供纯资料库事实，桌面服务决定会话是否缺少当前项，播放器协调器执行队列投影和暂停加载。

### D3: 通过现有暂停态播放上下文建立当前项

兜底选择必须创建一个包含候选歌曲的最小播放上下文，并走现有的 paused load/prime 路径，使 queue entry ID、当前项置顶、封面/元数据投影和持久化保存保持一致。不得直接拼装 UI 播放栏 DTO，也不得调用会向 mpv 发出 play 的路径。

若已有会话设置存在，建立该初始上下文时继承 mode、volume、muted；position 只对真正恢复的原歌曲有意义，新的兜底歌曲从未播放位置开始且保持暂停。首次导入同样只创建当前项，不清空有效现有队列。

### D4: 导入与恢复使用显式幂等守卫

初始选择操作在提交成功、资料库可用且 `current == None` 时才执行。重复的扫描/恢复/导入事件在已有 current 后不得替换歌曲；空库或导入失败不改变空状态。外部删除导致当前项无效时，先按既有删除/恢复裁决移除失效引用，再执行一次候选选择，避免把失效 entry 留在队列中。

### D5: 兼容旧播放会话和旧资料库记录

不修改播放会话版本或 `added_at` 数据格式。没有有效 current 的旧会话同样走候选选择；旧歌曲记录若按既有兼容规则得到 `added_at = 0`，仍可作为候选并由现有稳定 tie-break 决定顺序。无法确定活动根或没有可用歌曲时安全返回空状态。

## Risks / Trade-offs

- [启动时会显示一首尚未播放的歌曲，用户可能误以为应用自动播放] → 播放状态明确保持 paused，测试断言播放器没有 play 调用，界面沿用选中/待播放视觉。
- [多个歌曲 `added_at` 相同导致候选不稳定] → 复用资料库既有确定性 tie-break，并在 Core 查询测试中锁定结果。
- [恢复过程中的扫描/导入事件与播放初始化竞态] → 以会话当前项的幂等守卫作为提交边界；重复事件只读已存在状态，不覆盖用户操作。
- [所有歌曲都不可用或活动根不可用] → 候选查询只返回可播放歌曲；无结果时保留空/blocked 的既有反馈，不创建虚假队列项。

## Migration Plan

- 无数据库、播放会话或可携带资料格式迁移。
- 先实现 Core 候选查询与单元测试，再接入桌面恢复/导入编排和暂停队列测试，最后运行 workspace 的格式化、lint、类型检查、Rust/桌面测试与现有验收套件。
- 回滚只需移除初始候选选择编排；现有会话和资料库格式仍可由旧代码读取。
