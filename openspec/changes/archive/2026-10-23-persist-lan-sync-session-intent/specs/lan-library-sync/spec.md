# Spec Delta

## MODIFIED Requirements

### Requirement: 显式启用与可信设备加入

系统 MUST 默认关闭发现、监听和同步通信；用户明确启用后才可发现或手动连接局域网主设备。绑定身份不代表启用意图。系统 MUST 为每个资料库持久保存会话意图：`enabled` 表示用户启用且会话在正常退出时仍运行，`stopped` 表示停止服务但保留配对，`paused` 表示暂停。只有意图为 `enabled` 且该资料库存在有效绑定时，启动流程才可恢复其会话；无绑定、`stopped` 或 `paused` 时不得产生发现、监听、广播或连接流量。显式停止、暂停和解除同步 MUST 原子地更新意图并取消正在执行或等待中的启动恢复。正常进程退出 MUST 保留退出前的意图，区分用户主动停止/暂停和进程退出清理。

发现结果 MUST NOT 授予信任。配对 MUST 允许从设备输入主机局域网 IP 和主机直接显示的六位短期验证码；验证码有效后，设备通过一次性配对连接交换主机 TLS 证书和按资料库隔离的独立设备凭据，并固定该证书用于后续加密连接。验证码 MUST 单次使用、有效十分钟并由主机自动刷新；主机 MUST 在验证码验证成功后自动完成授权，不要求主机逐台审批。主设备 MUST 能立即撤销设备访问。

macOS 发布包 MUST 对最终 `.app` bundle 生成代码签名，签名标识 MUST 与 `CFBundleIdentifier` 一致；bundle MUST 保留 `NSLocalNetworkUsageDescription` 与所需 `NSBonjourServices` 声明，使本地网络权限归属于发布应用。
macOS ad-hoc 发布包 MUST 禁用 hardened runtime，确保系统可加载包内随应用分发的 ad-hoc `libmpv.dylib`。

#### Scenario: 同步关闭时离线运行
- **WHEN** 用户未启用局域网同步而启动 Echo 或编辑本地音乐库
- **THEN** 没有发现/监听/连接流量，全部本地能力正常工作，变更可保存在本机等待未来启用

#### Scenario: 主机显式停止后重启
- **WHEN** 主设备用户停止主机服务并重启 Echo
- **THEN** 配对关系保留，持久意图为 `stopped`，服务保持关闭且无监听或 Bonjour 广播，用户可手动重新启动

#### Scenario: 从设备暂停后重启
- **WHEN** 从设备用户暂停同步并重启 Echo
- **THEN** 持久意图为 `paused`，不连接或同步，用户可手动恢复

#### Scenario: 正常退出时恢复仍启用的会话
- **WHEN** 已绑定资料库的会话处于 `enabled`，用户正常退出 Echo
- **THEN** 退出清理停止当前工作但保留 `enabled` 意图；下次启动仅恢复该资料库的会话

#### Scenario: 无绑定时不自动恢复
- **WHEN** 资料库没有有效同步绑定或安全凭据
- **THEN** 启动不尝试网络会话、不启动自动恢复重试，意图显示为关闭或未配置

#### Scenario: 自动恢复失败与用户取消
- **WHEN** 启动恢复失败，随后用户停止、暂停、解除同步或切换资料库
- **THEN** 恢复重试有限且可取消，用户操作生效后不再启动或重启旧会话；失败状态可见且不持续静默重试

#### Scenario: macOS 发布包的局域网权限身份
- **WHEN** 用户从 macOS DMG 安装并运行 Echo
- **THEN** 安装包中的 `.app` 具有与 `CFBundleIdentifier` 一致的 bundle 签名标识，并包含局域网用途说明和 Echo Bonjour 服务声明；本地网络权限适用于该发布应用

#### Scenario: 手动输入地址和验证码加入
- **WHEN** 新设备输入主机可达的局域网 IP 和仍有效的六位验证码
- **THEN** 主机自动完成配对，返回 TLS 身份材料和该设备独立凭据；新设备保存证书 pin 后连接并开始同步，不需要复制邀请文本或主机审批

#### Scenario: 错误、过期或已使用验证码
- **WHEN** 输入错误、过期或已使用的验证码
- **THEN** 配对失败，不授予库读取或写入权限，不覆盖原绑定或资料库；成功配对后，后续连接必须验证已交换并固定的主机证书

#### Scenario: 配对请求因其他原因失败
- **WHEN** 配对请求因主机限流、主机安全存储不可用、网络/TLS 故障、主机拒绝或响应不兼容而失败
- **THEN** 界面 SHALL 显示与失败类别相符的提示，不得将这些原因误报为验证码错误；日志和界面不得暴露验证码、bearer 凭据或私钥

#### Scenario: 已绑定资料库加入另一主机
- **WHEN** 用户尝试用已绑定到其他同步身份的本地资料库加入新主机
- **THEN** 配对授权成功后系统自动撤销并清理原同步身份，再将资料库绑定到新主机；原本地音乐与目录数据保留至新主机快照验证完成，不要求用户手动解除原绑定

#### Scenario: 同步传输失败分类
- **WHEN** 配对完成后的同步因主机不可达、主机拒绝或响应不兼容而失败
- **THEN** 界面分别说明连接、主机拒绝或协议类别，不得将远端请求错误统一显示为内部 worker 故障

#### Scenario: 同步停滞与并发操作错误分类
- **WHEN** 同步因来源 mutation 前驱未确认而无法推进，或远端媒体发布尚未就绪
- **THEN** 界面 MUST 说明对应的阻塞原因，不得误报为另一项操作正在运行；真正的手动并发和取消仍使用忙碌/取消状态，并记录用于定位队列停滞的 mutation 与游标信息

#### Scenario: 配对响应丢失后重试
- **WHEN** 主设备已持久化某设备的授权与凭据，但首次配对响应在该设备保存凭据前丢失，用户再次使用有效验证码让同一设备身份加入
- **THEN** 主设备 MUST 返回该设备当前仍有效的同一凭据，使重试可完成；不得将该设备误报为重复设备、撤销已有凭据或在仍有效的请求失败时移除其活动认证

#### Scenario: 撤销与跨库访问
- **WHEN** 已撤销设备继续请求同步，或设备请求未授权资料库的对象/资源
- **THEN** 所有此类请求被拒绝，在途会话终止，其他设备不受影响，已下载的本地副本不会被远程擦除

### Requirement: 同一应用内的资料库同步上下文隔离

系统 MUST 为同一应用配置文件中的每个本地资料库保存独立的同步绑定、设备凭据引用、持久会话意图、待确认变更、设备游标、提交序列和恢复检查点。切换活动资料库 MUST 在用户确认实际切换后停止旧库会话并恢复新库自己的上下文；取消目录选择 MUST 保持完全 no-op。激活成功后，只有新库绑定有效且其意图为 `enabled` 时才能恢复新库会话；`stopped` 或 `paused` 时保持关闭或暂停。切换失败 MUST 保留旧库和原会话可用性，或明确报告可恢复状态，不得静默留下旧库停止。切换不得覆盖、清空或混合其他资料库的身份、设备、变更队列和提交历史。

#### Scenario: 切换到另一资料库
- **WHEN** 用户确认切换到同一应用内另一可写资料库
- **THEN** 旧库会话停止，新库绑定、凭据、队列、游标、检查点和会话意图被独立恢复；新库仅在意图为 `enabled` 时启动会话

#### Scenario: 取消资料库选择
- **WHEN** 用户打开目录选择器后取消
- **THEN** 活动资料库、同步会话、网络监听、自动恢复重试、缓存和同步状态均保持不变

#### Scenario: 资料库切换失败
- **WHEN** 目录候选扫描或激活因错误、阻塞或只读状态失败
- **THEN** 原资料库仍然活动，原同步会话恢复到切换前状态，或界面明确报告同步已停止及可用恢复操作

#### Scenario: 为另一资料库启动同步
- **WHEN** 用户切换到同一应用内另一可写资料库，并首次将其设为主库或加入主库
- **THEN** 系统为该本地资料库创建独立同步上下文，不因另一资料库已有绑定而拒绝启动，也不复用另一资料库的设备授权或提交历史

#### Scenario: 切回已绑定资料库
- **WHEN** 用户切回已有同步绑定的本地资料库
- **THEN** 系统恢复该库原有身份、设备、待确认变更、游标、提交链及检查点；其他资料库的同步状态保持不变

#### Scenario: 库切换期间本地修改
- **WHEN** 用户在某资料库未运行同步时继续本地编辑，之后再次启动该库同步
- **THEN** 新修改进入该库自己的队列并沿其原有前驱链确认，不被其他资料库的队列或游标阻塞

#### Scenario: 切回已启用资料库
- **WHEN** 用户切换回同一应用中曾绑定且持久意图为 `enabled` 的资料库
- **THEN** 系统恢复该库原有身份、设备、待确认变更、游标、提交链及检查点并启动会话；其他资料库的同步状态保持不变

### Requirement: 校验传输与故障恢复

系统 MUST 按内容哈希传输音频与用户资源，支持大文件断点续传、暂停、重试和资源去重。主确认依赖完整有效资源；接收端只有在全文件长度/哈希校验及安全发布完成后才可播放。非法路径、越界符号链接、资源超限、跨库哈希读取、磁盘满、权限失效、文件外部变化 MUST 明确失败并保留既有有效内容。文件操作与对象应用 MUST 可在崩溃后恢复且不重复副作用。

传输缓存清理 MUST 按绑定和资源引用范围执行，不得删除仍被未确认变更、活跃快照、未完成发布或恢复检查点引用的唯一有效资源。停止、暂停、正常退出、解除绑定、epoch 变化和资料库切换 MUST 各自执行与其语义一致的缓存及进程内状态清理；普通停止、暂停和退出 MUST 保留恢复所需的持久账本、发布 journal 与安全检查点。解除绑定及旧绑定淘汰时，清理失败 MUST 保留可持久重试的清理意图。缓存校验发现损坏时 MUST 清除损坏副本并允许按权威声明重新传输，不得让单个陈旧检查点永久阻塞同步。不同绑定的缓存不得未经当前绑定的完整声明和校验而复用。

#### Scenario: 附属机写回内嵌信息后同步回主机
- **WHEN** 主机导入歌曲且附属机已同步，附属机写回内嵌封面、歌词或专辑并生成新音频哈希
- **THEN** 新资源作为本机待发版本上传并确认，不在上传前向主机请求本机已有且完整校验的新哈希；保留歌曲 UUID、待发链和关联，主机及附属机最终得到校验一致的新文件，重复同步与重启不丢失变更或制造回声

#### Scenario: 资源缺失错误不误报配对失败
- **WHEN** 同步主机返回 `resource_not_found`
- **THEN** 界面显示媒体资源暂不可用及重试提示，不归因为配对关系；待确认内容保留，资源未完成时不显示已同步

#### Scenario: 大文件断线续传
- **WHEN** 文件传输一半断网或应用重启
- **THEN** 已校验块可复用，恢复后继续传输，完成的全文件 BLAKE3 与声明相同，重复请求不产生额外歌曲

#### Scenario: 文件变化或校验失败
- **WHEN** 传输源文件变化、下载哈希不符，或目标文件已被外部程序修改
- **THEN** 该版本不发布，旧内容和外部修改被保留并报告错误/冲突，系统不会将错误文件标记为可用

#### Scenario: 空间权限与路径攻击
- **WHEN** 接收遇到空间不足、只读根目录、目录逃逸、符号链接越界或超限资源
- **THEN** 拒绝不安全发布，不破坏原媒体或已提交对象，显示可重试或需用户处理的原因，不提供任意文件读取能力

#### Scenario: 正在播放的文件不能替换
- **WHEN** 平台拒绝替换当前正在播放的媒体
- **THEN** 保持播放并将新版本发布挂起，文件可安全替换后恢复，不提前报告已同步

#### Scenario: 对象水位与媒体完成分离
- **WHEN** 元数据已应用到目标水位但尚有媒体待下载
- **THEN** 状态仍为同步中，已就绪音乐可播放，不因元数据游标推进而错误报告完整同步

#### Scenario: 停止或暂停后重新同步
- **WHEN** 用户停止或暂停会话，之后在相同绑定上再次启动
- **THEN** 临时传输状态和进程内会话状态已按引用关系清理或保留；有效检查点可安全续传，损坏或未完成资源可重建，不出现永久资源校验或 publication 阻塞

#### Scenario: 解除绑定时缓存清理失败
- **WHEN** 用户解除同步，但绑定分区或关联缓存暂时无法删除
- **THEN** 解绑结果保持一致且清理任务持久可重试；后续启动或会话维护最终移除该绑定的孤立缓存，不删除本地音乐资料

#### Scenario: 绑定或 epoch 变化
- **WHEN** 资料库重新配对、切换主机或建立新 epoch
- **THEN** 旧绑定缓存被隔离并可回收，新会话不会未经声明及完整校验复用旧绑定字节

#### Scenario: 损坏传输检查点自愈
- **WHEN** 完成资源的缓存 blob 或检查点缺失、损坏或彼此不匹配
- **THEN** 系统识别缓存无效，移除该资源的无效缓存状态并重新下载校验，不将可恢复的缓存不一致报告为永久绑定冲突

#### Scenario: 退出和资料库切换保护发布恢复
- **WHEN** 应用退出或活动资料库切换时存在未完成资源发布或被引用的传输资源
- **THEN** 临时文件按可恢复规则处理，未完成 journal 与仍被引用的资源保持可恢复，且不会把孤立缓存带入另一资料库
