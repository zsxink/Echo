# Proposal

## Why

用户需要在局域网内让多台 Echo 设备共享整个音乐库，同时在任意设备上添加音乐、收藏、维护歌单和离线修改。采用一台主设备、多台从设备的拓扑，由主设备汇聚与裁决变更，提供可恢复的双向同步，落实 ROADMAP 的二期目标。

## What Changes

- 为每份资料库配置唯一主设备；其他设备配对后作为从设备加入，主设备与从设备均可本地编辑，从设备之间通过主设备交换数据。
- 同步音频、同名歌词、用户封面、歌词/元数据覆盖层、歌曲对象、收藏、歌单、成员顺序、按设备累计的播放统计和墓碑；同步完整资料库，不提供选歌同步或流式播放。
- 提供局域网发现、手动地址连接、安全配对、设备撤销和按资料库授权。
- 首次加入采用主库克隆；后续采用可分页的增量日志与按内容哈希传输文件，支持断网重试、断点续传、幂等应用和进度反馈。
- 从设备离线修改进入本机队列，主设备恢复可达后统一确认并向其他从设备传播；明确并发修改、删除与文件冲突规则。
- 保留现有 10 秒撤销删除：窗口内仅形成本机删除意图，终结后才发布同步墓碑；重复歌单成员使用按类型的身份映射，保证去重后的删除及重新添加可收敛。
- 设置增加“局域网同步”，应用工具区展示同步状态与手动同步入口；保持本地浏览和播放可离线使用。
- **在线传播加速（长轮询）**：`/v1/commits` 增加有界长轮询——从设备可携带 `wait_ms`（≤30 秒）请求提交页，主机在没有新提交时保持该请求并按 500ms 内部间隔复查已发布水位，出现新提交或等待预算耗尽时立即响应。从设备同步循环在轮次之间以长轮询等待主机新提交，本地 outbox 写入、取消、停止仍按现有语义立即唤醒；主机不保持请求（旧版本或降级）时从设备自动退回原有轮询等待，不形成紧密循环。主机角色行为不变；原「60 秒轮询」兜底改为「长轮询 + 约 25 秒安全轮次」。非目标：不新增反向推送通道、不引入 UDP/mDNS 唤醒提示层、不改裁决/冲突/快照/资源传输规则、不做跨网段或公网传播。
- **BREAKING（规格边界）**：解除当前规格“不得有网络依赖/同步入口”的一期限制，改为默认关闭、用户明确启用后允许局域网通信；保留无账号、本地优先和最小 WebView 权限。
- 非目标：Android/iOS 客户端、S3/WebDAV、公网发现/中继、自动选主/故障转移、合并不同资料库、同步本机偏好或播放会话、构建新的歌曲编辑功能。

## Capabilities

### New Capabilities

- `lan-library-sync`：主从拓扑、设备信任、完整首次同步、增量双向同步、裁决、文件传输与恢复、进度和跨平台验收。

### Modified Capabilities

- `sync-foundation`：离线基础升级为可被显式启用的同步引擎消费；扩展可重试事件身份、接收来源、确认与版本边界，避免回传循环。
- `desktop-app-shell`：允许局域网同步设置与入口，保持既有导航、品牌区操作、键盘访问和离线启动。

## Impact

- Core domain/application 增加同步值对象、裁决器、会话状态机与事务端口；SQLite 增加顺序迁移，filesystem 复用控制面、BLAKE3、安全路径和 operation journal。不得直接复用产生本地 outbox 的写入路径应用远端对象。
- 建议增加 `echo-sync` 基础设施 crate，封装 HTTPS 服务端/客户端和发现，依赖 Core 端口；桌面平台负责生命周期、密钥存储、网络权限和装配。React 仅经生成的类型化 IPC 操作。
- 候选依赖为 Tokio、Axum、Reqwest、Rustls、mDNS-SD 和系统安全存储适配；实施前验证 MSRV、许可证与三平台构建兼容，锁定版本。RustSec 修复后的依赖将 workspace MSRV 提升到 Rust 1.88。
- 涉及 portable JSON 版本、设备绑定、日志/游标恢复和数据库升级；旧资料库保留 UUID 并完成基线引导，旧程序不能写入新同步格式。
- 主备份恢复通过显式恢复入口强制更换 epoch；独立发布检查点与从设备保存的日志摘要用于检测回退/分叉。整机及所有检查点共同回退时不能承诺自动检测，必须按备份恢复流程重新建立信任。
- PRODUCT/DESIGN/CODE_STANDARDS 中二期仍限定 S3/WebDAV 的条款需随实施统一到 ROADMAP 的局域网优先路线；更新界面术语/原型、一期无同步 scope guard、架构门禁及场景登记。遵守 CODE_STANDARDS §3–§9，保留既有播放器和离线能力回归验证。
- 长轮询影响面：`echo-sync` protocol 增加 `MAX_COMMIT_WAIT_MS` 限制常量，server `pull_commits` 支持 `wait_ms` 保持与内部复查，client `pull_commits` 增加等待参数并按请求覆盖超时（客户端默认 15s 小于保持时长）；`echo-app`（src-tauri）`SyncProvisioner` 增加 `watch_host_commits`（默认返回不支持，测试替身行为不变），同步循环对从设备角色在轮次间改用长轮询等待，主机角色与重试退避路径保持原逻辑；`NativeSyncProvisioner` 以自注册的本地唤醒通道 + current-thread 执行器实现，含「主机不保持即降级」的能力探测。兼容性：`wait_ms` 为可选查询参数，旧主机忽略未知参数并立即返回，从设备据此降级；无数据库迁移、无 DTO 破坏、无配对/凭证变化。「空闲同步额外平均 CPU 低于单核 1%」的既有要求保持不变且预期改善（从设备全轮次从每 5 秒一次降到约每 25 秒一次，轮次之间只保持一条连接）。

本变更实现局域网配对与本地优先同步。加入主机时保留本机 Echo 资料库及媒体，将本地对象纳入同步队列，再把主机快照合并到本机；身份变更、退出和重新加入不得自动清理本地数据。
