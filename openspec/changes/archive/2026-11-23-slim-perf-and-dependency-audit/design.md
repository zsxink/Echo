## Context

现有 core task shard 在上传 task 12.5 的 benchmark 后执行三个重型性能场景。依赖审计在通过本地政策检查后，在线再次运行全部 cargo-deny 检查。目标是减量而非删除门禁。

## Goals / Non-Goals

- 按完整的 PR diff 识别已审核的纯样式/文档改动；不确定时保留性能覆盖。
- 去掉重复检查，保持在线与离线职责、失败判定、每日/手动扫描。
- 不变更任何产品分层、架构接口、数据、平台测试、benchmark 或既有 workflow 级文档忽略表。

## Decisions

- 分类器是 CI 基础设施的路径判定，无业务层或新依赖。只信任 PR 事件提供的两端提交 SHA，并用 Git 三点 diff 计算完整变更（关闭 rename 探测）；只为显式白名单的修改生成跳过值。空 diff、无法比较、未知状态或其他路径一律执行。workflow 未得到明确的跳过结果也执行，main 上每次触发的 CI 无条件执行性能场景。
- 保持 job 和其他 step 无条件，保留 cache reader 形态；结构检查固定分类器调用、Git checkout 深度、发布跳过值的连线与完整性能命令。用 Git 临时仓库测试 diff 与保守回退，而非在测试中重写分类器逻辑。
- 本地政策继续阻断，在线只把 advisory 命令结果交给现有网络错误处理，另保留 cargo-audit、pnpm、许可清单和忽略项流程。CLI 调用记录用替身验证；不引入层级或数据迁移。

## Risks / Trade-offs

白名单会有误判成本，因此只允许已审计的明确路径；变更工具、测试、native 代码、依赖或未知类型仍执行。其他 job 可能仍决定整条关键路径，所以不把单项节省当作每次 PR 的端到端节省。
