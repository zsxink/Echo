# Spec Delta

## Purpose

为本地曲库提供可关闭的逐曲响度归一化：从媒体内嵌标签派生增益参数，在桌面播放链上以受保护的平滑增益抹平曲目间响度差异，同时保持 Core 与播放器分离、不改动音频文件、不宣称 true-peak 或动态响度测量能力。

## ADDED Requirements

### Requirement: 内嵌响度标签的提取与来源判定

系统 SHALL 在扫描与导入本地音频时读取 ReplayGain 2.0 的 track/album gain 与 track/album peak（覆盖 FLAC、MP3、APE、MP4/iTunes freeform 及 Vorbis Comment 容器），并 SHALL 读取 Opus/Vorbis 的 R128 track/album gain，把两类来源统一换算为 dB 表示的逐曲参数与来源标识。系统 SHALL 在同时存在两类标签时优先采用 ReplayGain 2.0，在同一来源下按用户选择的 track/album 模式取值。系统 MUST NOT 猜测未定义或私有编码：iTunNORM、OpusHead output gain 及其他无法按公开语义换算的字段 MUST 按「无标签」处理并给出可诊断说明，不得当作增益使用。

非法、非有限、超出合理范围的 gain/peak 值 MUST 作为非致命解析告警丢弃，不得阻断歌曲记录、封面、歌词或播放；缺少某一项（例如只有 gain 没有 peak、只有 album 没有 track）时 SHALL 保留可用项并按边界规则处理，不得把缺失值静默当作 0 dB 峰值或 0 dB 增益。

#### Scenario: 常见 ReplayGain 标签
- **WHEN** 扫描含 `REPLAYGAIN_TRACK_GAIN` / `REPLAYGAIN_TRACK_PEAK` / `REPLAYGAIN_ALBUM_GAIN` / `REPLAYGAIN_ALBUM_PEAK` 的 FLAC、MP3、APE、MP4/iTunes freeform 或 Vorbis Comment 文件
- **THEN** 歌曲记录携带四项参数的 dB / 振幅数值及来源标识 ReplayGain 2.0，文件不被修改

#### Scenario: R128 标签
- **WHEN** 扫描含 `R128_TRACK_GAIN` / `R128_ALBUM_GAIN` 的 Opus 或 Vorbis 文件
- **THEN** 定点数值被换算为 dB 增益并标记来源 R128，该类标签按不含 peak 信息处理

#### Scenario: 两类标签并存
- **WHEN** 同一文件同时含 ReplayGain 2.0 与 R128 标签
- **THEN** 采用 ReplayGain 2.0 的参数，并在诊断中记录被忽略的来源，不混用两来源的 gain 与 peak

#### Scenario: 私有编码不猜测
- **WHEN** 文件只含 iTunNORM，或 Opus 文件的增益只写在 OpusHead output gain 中
- **THEN** 该曲按无标签处理、不应用归一化增益，并给出「不支持的响度标签」诊断，不产生错误增益

#### Scenario: 标签损坏或部分缺失
- **WHEN** gain 文本不可解析、为 NaN/Inf、超出合理范围，或只有 album gain 而无 track gain
- **THEN** 丢弃非法项、保留可用项，歌曲仍可扫描、显示与播放，并产生不影响入库的非致命告警

### Requirement: 逐曲响度参数的持久化与隔离

系统 SHALL 把扫描/导入时解析出的逐曲响度参数作为**资料库元数据**保存在本机查询投影中，供播放时按歌曲标识查询；系统 MUST NOT 修改音频文件本体，MUST NOT 覆盖或清除用户元数据覆盖层。数据库升级后已存在的歌曲行 SHALL 保持为「无标签」直到下一次扫描或导入重新解析，不得在升级时批量重读媒体或改变歌曲 UUID、路径、收藏、歌单与播放统计。外部程序改动文件标签后，下一次扫描 SHALL 以重新解析结果更新该曲参数。

逐曲响度参数 MUST NOT 进入资料库 `echo/` 的可携带记录、outbox 或局域网同步载荷，也不发起网络请求；不同设备 SHALL 通过各自扫描同一媒体字节得出该参数。资料库外的临时播放项 MUST NOT 写入歌曲表、歌单、统计或同步队列，且 MUST NOT 应用响度归一化。

#### Scenario: 首次扫描写入
- **WHEN** 新曲被扫描且含有效响度标签
- **THEN** 播放该曲时可查询到该曲的 gain/peak 与来源，音频文件字节与覆盖层保持不变

#### Scenario: 旧库升级
- **WHEN** 已有资料库执行新增列迁移后首次启动，未重新扫描
- **THEN** 旧歌曲行显示无标签、播放行为与升级前一致，UUID/路径/收藏/歌单/统计不变，且不触发全库重读

#### Scenario: 外部改标签后重扫
- **WHEN** 外部工具改写文件的响度标签后用户触发重新扫描
- **THEN** 该曲参数更新为新解析值，其他字段与关联关系不变

#### Scenario: 临时播放项与同步边界
- **WHEN** 断网状态下播放资料库外临时文件，或查看局域网同步载荷
- **THEN** 临时项不应用归一化、不写任何资料库记录；同步载荷中不含逐曲响度参数，也没有网络请求

### Requirement: 归一化增益的纯规则计算

系统 SHALL 只用「逐曲标签 + 用户偏好 + 当前音效保护预算」这一组显式输入，确定性地计算逐曲增益，不读取播放位置、时间、系统音量或解码后的音频样本。ReplayGain 2.0 与 R128 MUST 对齐到同一个目标参考（默认 -18 LUFS），R128 标签 SHALL 按其 -23 LUFS 参考加上 +5 dB 来源对齐量；用户 preamp SHALL 在对齐之后叠加，取值范围 MUST 限制在 -12 dB 至 +12 dB、步进 0.5 dB，非法值 MUST 被拒绝而不是静默钳制。

系统 SHALL 按 peak 钳制以避免稳态削波：存在有效 peak 时，归一化增益 MUST NOT 超过 `-20·log10(peak) - 1 dB`；不存在 peak（R128）时 MUST 由统一提升上限 +6 dB 约束，并由末端 sample-peak limiter 承接残余风险。系统 SHALL 把归一化增益与 EQ/空间的有效前置增益**相加**得到合并前置增益，MUST NOT 用归一化值覆盖或抬高 EQ 自身算出的保护衰减；合并值 MUST 为有限数、落在 -60 dB 至 +6 dB 之间，末端不可关闭的 sample-peak limiter（-1 dBFS）承接残余风险。系统 MUST NOT 把 limiter 当作常规增益预算，也不宣称 true-peak 合规。归一化增益 MUST 为有限数并落在 -24 dB 至 +6 dB 之间；相同输入 MUST 产生完全相同的输出。

系统 MUST NOT 声称测量了节目响度、达到 BS.1770/EBU R128 合规或 true-peak 合规；-18 LUFS 只是标签来源对齐约定，不是对解码音频的测量结论。

#### Scenario: track 与 album 模式
- **WHEN** 用户切换 track / album 模式并播放同一专辑内两首标签不同的曲目
- **THEN** 每首曲目按所选模式取对应 gain 与 peak，两首曲目得到各自可复现的增益

#### Scenario: 来源对齐与用户 preamp
- **WHEN** 曲库含 ReplayGain 2.0 与 R128 两种来源的曲目，用户把 preamp 设为 +3 dB
- **THEN** 两类标签先对齐到同一参考再叠加 +3 dB，得到的增益符合公式且可复现

#### Scenario: 按 peak 钳制
- **WHEN** 标签要求 +9 dB 提升，而 track peak 为 0.89
- **THEN** 归一化增益被钳制在 `-20·log10(0.89) - 1 dB` 以内，不被 limiter 当作常规保护手段

#### Scenario: 无 peak 的 R128 曲目
- **WHEN** 只有 R128 gain 且请求超过 +6 dB 的提升
- **THEN** 增益被限制在 +6 dB，且记录「无 peak 信息，由 limiter 承担 sample-peak 保护」的口径

#### Scenario: 与音效保护预算合并
- **WHEN** 启用高提升 EQ 预设的同时开启归一化，且归一化要求正增益
- **THEN** 合并前置增益等于 EQ 有效前置增益与归一化增益之和且不超过 +6 dB，EQ 自身的保护衰减未被覆盖，末端 limiter 仍在链路末位，输出为有限值

#### Scenario: 无标签与非法偏好
- **WHEN** 曲目无有效标签，或偏好 preamp 为 NaN / 超出 -12..+12 dB / 非 0.5 dB 步进
- **THEN** 前者返回 0 dB 且显示无标签，后者拒绝请求并保留上一次合法偏好，不产生非有限增益

### Requirement: 归一化增益的应用与平滑过渡

系统 SHALL 把逐曲归一化增益并入桌面播放层既有的共享前置增益节点，不新增滤镜种类、不改变既有 EQ/空间处理的参数语义、不改写用户音量与静音状态；末端 sample-peak limiter MUST 保持在链路末位且不可关闭。音效处于旁路状态时，系统 SHALL 仍能安装仅含增益与保护的最小链路，使归一化独立可用；两者都关闭时 MUST 完全旁路，不遗留滤镜节点。

切歌、换曲、播放环境重建或开关切换导致归一化增益变化时，系统 SHALL 在首个可听样本前完成目标增益计算，并通过短斜坡从旧增益过渡到新增益，MUST NOT 出现硬切爆音或把上一首曲目的增益带到新曲目。音效关闭/开启、预设切换、seek、暂停/继续与静音 MUST 保持既有语义，不因归一化而改变传输控制、播放计数与队列行为。

#### Scenario: 切歌时增益变化
- **WHEN** 连续播放两首归一化增益分别为 -6 dB 与 +3 dB 的曲目
- **THEN** 第二首首个输出样本使用其自身增益，两次增益之间为平滑过渡，无硬切与前一首增益残留

#### Scenario: 音效关闭时仍可归一化
- **WHEN** 用户关闭所有 EQ / 空间预设但开启归一化
- **THEN** 归一化增益仍然生效，链路只含格式转换、前置增益与末端保护，音效浮层不显示任何预设为「已生效」

#### Scenario: 归一化和音效同时启用
- **WHEN** 用户开启一个 EQ 预设并开启归一化
- **THEN** 预设仍按原有规则确认并显示「已生效」，归一化作为独立增益层显式叠加，不占用预设名额

#### Scenario: 关闭归一化
- **WHEN** 用户在播放中关闭归一化开关
- **THEN** 增益平滑回到 0 dB，EQ / 空间处理保持用户原有选择与状态，音量滑块与静音状态不变

#### Scenario: 播放环境重建
- **WHEN** 切换输出设备、采样率变化或音频链重建
- **THEN** 归一化增益按新环境重新计算并在确认后应用，不出现旧环境的假生效，不改变时长、seek、歌词与队列语义

### Requirement: 归一化偏好与界面

系统 SHALL 提供默认关闭的归一化开关，以及 track/album 模式与 preamp 偏好；偏好 MUST 作为版本化的本机桌面偏好原子保存，正常退出刷新最终状态，重启后恢复「请求」而不是「已生效」状态，且不自动开始发声。缺少、损坏、未来版本或非法偏好 MUST 回落为关闭、保留原数据给出恢复提示，且不影响其他有效偏好。

系统 SHALL 在音效浮层的独立区域（不属于 EQ / 空间预设列表）呈现开关、模式、preamp 与当前曲目状态：含标签时显示标签来源与生效增益，无标签或标签不支持时明确显示「无标签 / 不归一化」，增益被钳制时说明原因；所有标签页、播放栏与后台窗口 MUST 从同一份偏好状态渲染，不出现互相矛盾的开关值。系统 MUST NOT 在界面文案中把归一化描述为提升音质、恢复动态或适配设备。

#### Scenario: 默认关闭
- **WHEN** 用户首次启动或从未设置过归一化偏好
- **THEN** 开关为关闭，播放行为与 P0 一致，不出现额外的增益节点

#### Scenario: 开启并调整
- **WHEN** 用户开启归一化、选择 album 模式并把 preamp 调到 +3 dB
- **THEN** 保存后的偏好在浮层与后台窗口一致，当前曲目状态显示来源与生效增益

#### Scenario: 重启恢复
- **WHEN** 用户保持开启状态并正常重启应用
- **THEN** 开关恢复为开启，实际生效须等待播放环境确认，不自动播放、不显示未确认的「已生效」

#### Scenario: 偏好损坏
- **WHEN** 偏好文件缺失该槽位、JSON 损坏、版本超前或 preamp 非法
- **THEN** 归一化回落关闭并给出恢复提示，原数据不被覆盖，音效曲线与窗口状态仍可正常使用

#### Scenario: 无标签与钳制提示
- **WHEN** 播放无标签曲目，或增益因 peak / 上限被钳制
- **THEN** 界面明确说明「无标签不归一化」或钳制原因，不谎报目标增益已完全应用

### Requirement: 失败降级与播放不中断

系统 SHALL 在下列情况把归一化增益降级为 0 dB 并继续基础播放：逐曲参数查询失败、参数缺失或损坏、原生滤镜命令能力不可用、音频环境不支持、增益应用失败且无法确认回滚。降级 MUST 以明确状态和诊断呈现，MUST NOT 把未应用的请求显示为已生效；播放 MUST NOT 因归一化失败而进入错误态、跳过曲目或触发自动播放。

系统 MUST NOT 因归一化产生网络请求、同步 outbox 记录、资料库 `echo/` 写入或导入暂存；系统 MUST NOT 因归一化修改音量、静音、播放计数与会话恢复语义。

#### Scenario: 查询失败
- **WHEN** 播放时按歌曲标识查询逐曲参数失败或返回损坏值
- **THEN** 该曲按 0 dB 播放并显示降级原因，其他曲目与队列行为不受影响

#### Scenario: 原生能力不可用
- **WHEN** 当前分发库无法向既有前置增益节点下发运行时参数
- **THEN** 归一化安全旁路、EQ 状态按既有规则处理，不谎报生效，不重建输入链来绕过连续性约束

#### Scenario: 无音轨或断网
- **WHEN** 无音轨、暂停或断网时切换归一化开关
- **THEN** 不加载文件、不自动播放、不发起网络请求，下次播放首个样本前应用最新偏好

### Requirement: 归一化能力的验收口径

系统 SHALL 以纯函数单元测试覆盖来源换算、track/album 取值、peak 钳制、无 peak 上限、整链预算合并、非法输入与确定性，并以回归测试证明归一化关闭时 P0 音效的前置增益、状态机、快照与旁路行为完全不变。系统 SHALL 在 macOS 实际分发运行库上以持续 PCM 捕获验证增益命令确实改变输出、最小链不含 EQ/空间节点、压力素材下输出不超过 0 dBFS；命令返回值或 UI 回执 MUST NOT 作为生效证据。Windows / Linux 的真机捕获在本 change 中延后，MUST NOT 从 macOS 结论继承；这两个平台的发布证据仍是后续门槛，缺证时 MUST 标记该平台待验证且不得用于发布宣称。

切歌过渡平滑度、实时更新延迟、underrun、设备重建、中间浮点链非有限值与 true-peak 不属于 PCM AO（整数 PCM16、非实时）可证明的范围，MUST NOT 由本次捕获宣称。系统 MUST NOT 宣称 true-peak 合规、BS.1770/EBU R128 合规或具备运行时响度测量；对外文案 MUST 只说明 sample-peak 保护与「读取已有标签」的事实。

#### Scenario: 纯规则与回归
- **WHEN** 运行归一化增益与音效链路的自动化测试
- **THEN** 增益公式、边界、降级与 P0 回归断言全部通过，且不存在非有限增益或旧环境假生效

#### Scenario: macOS 原生证据与延后平台
- **WHEN** 复核含归一化能力的 macOS 版本
- **THEN** 报告提供运行库/分发清单/素材哈希、增益变化前后 PCM 捕获与压力输出记录，并由独立重跑逐项一致；Windows / Linux 明确列为延后、不从 macOS 继承，且报告保持 `gate_passed=false`

#### Scenario: 文案不越界
- **WHEN** 用户查看归一化开关说明或发布说明
- **THEN** 文案只描述读取内嵌标签与 sample-peak 保护，不出现「true-peak 合规」「动态响度归一化」「提升音质」等无依据表述
