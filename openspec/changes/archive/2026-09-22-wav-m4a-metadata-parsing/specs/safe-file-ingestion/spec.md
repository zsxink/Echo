## MODIFIED Requirements

### Requirement: 多选导入与默认目标命名

系统 MUST 提供一次选择多个本地音频文件的导入操作，并逐文件处理。每个文件解析标签后，目标目录 MUST 使用 `media/歌手/歌手 - 歌曲名.原扩展名`；缺少歌手或歌曲名时 MUST 使用可见且确定性的兜底名称（分别为“未知艺人”和“未命名歌曲”），路径组件和文件名 MUST 清理平台禁止字符、控制字符和保留名称，同时保留可辨识性。

`.m4a` 与 `.wav` MUST 与其它一期格式一样可作为导入源：解析其标签后按同一命名与兜底规则生成目标。无标签的 `.wav` MUST 使用「未知艺人」/「未命名歌曲」兜底，不得因缺少标签而跳过导入或崩溃。

#### Scenario: 多选文件成功导入
- **WHEN** 用户选择多个支持格式的外部音频并确认导入
- **THEN** 系统分别解析、复制并返回每个文件的成功、跳过或失败结果，单个文件失败不回滚其他已成功文件

#### Scenario: 标签缺失和非法字符
- **WHEN** 音频缺少歌手/歌曲名或标签包含 `/`, `\\`, 控制字符、平台保留名或过长路径组件
- **THEN** 系统按兜底规则和字符清理规则生成 `media/` 下的目标路径，截断时仍保留扩展名和可区分的稳定后缀，且不覆盖任何既有文件

#### Scenario: 无标签 wav 导入
- **WHEN** 用户导入一个无内嵌标签的 `.wav`
- **THEN** 系统按「未知艺人」/「未命名歌曲」兜底生成 `media/未知艺人/未知艺人 - 未命名歌曲.wav` 目标，成功建立歌曲记录并返回成功结果，不因缺少标签而失败

## ADDED Requirements

### Requirement: 导入选择过滤器与支持矩阵一致

系统文件选择对话框的扩展名过滤器 MUST 与 Core 支持矩阵 `SUPPORTED_EXTENSIONS` 严格一致：对 `.wav`、`.m4a` 及所有一期支持格式可选中，对不在矩阵内的扩展名（如 `aac`、`aiff`）不得列入可选过滤器，避免用户选中后在导入阶段才被拒绝。

#### Scenario: 过滤器列出且仅列出支持格式
- **WHEN** 用户打开“导入音频”文件选择对话框
- **THEN** 系统仅按 Core 支持矩阵列出可选的音频扩展名；`.wav` 与 `.m4a` 可选，矩阵外的扩展名不在过滤列表中
