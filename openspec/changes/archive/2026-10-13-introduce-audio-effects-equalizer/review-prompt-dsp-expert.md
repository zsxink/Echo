## 0. 立场与硬规则

1. **只读复核**：不修改仓库任何文件、不跑会写盘的命令。产出是结论，不是补丁。
2. **rc=0 / "命令返回成功" / "官方文档里有这个选项" 都不等于生效。**
   本仓库已多次踩坑：`af set` rc=0 但日志有 `Disabling filter x because it has failed`
   （滤镜因缺 `aresample` 配置失败）；`AVFilter.process_command` 为空时 mpv 仍返回 0
   （`AVERROR(ENOSYS)` 被 `f_lavfi.c` 的 `>=0` 判据掩盖）。
   ⇒ 任何"能力已具备"的断言，必须给出**运行时 configured 状态**或 **PCM 输出测量**作为判据。
3. **规格里的每个数值都要能回答**：哪个 HEAD、什么命令重跑出来、误差多少。
   回答不了的数值一律标记为"未验证的宣称"。
4. 不要因为"设计文档已经讨论过风险"就放过。**风险被识别 ≠ 风险被度量。**
5. 结论先行。每个问题给：`严重度 / 位置（文件:行）/ 判据 / 影响 / 建议`。
   禁止"建议进一步研究"这种无判据句。

## 2. DSP 正确性复核（核心，逐条给判据）

### 2.1 RBJ peaking 数学
- 核验 `A=10^(g/40)`、`w=2πfc/Fs`、`alpha=sin(w)/(2√2)`（= `sin(w)/(2Q)`, Q=√2）与
  b0/b1/b2/a0/a1/a2 除以 a0 的推导是否自洽；`mix=1`、`normalize=false`、`precision=f64`、
  `block_size=0` 的组合是否会引入电平或精度副作用。
- 明确区分三种带宽定义：RBJ peaking 的"bandwidth"、带通 −3 dB 带宽、倍频程/octave。
  判定文档"不得宣传成每段严格一倍频程或 ISO/IEC 合规"这句是否**与实现一致**——
  若实现其实按 octave 排布了中心频率，表述与实现是否矛盾。
- 频率栅格：文档用 Fs=48000、DC..Nyquist **32769 个等距点** + 局部极大值细化。
  指出等距线性栅格在低频区分辨率过剩、高频区（约 1 Hz 间隔 vs Q=√2 的带宽）是否足够，
  并判断"栅格 + 细化"能否真正给出 |H|max 的上界，而非仅近似。

### 2.2 级联与增益预算
- 10 段相邻中心频率为 2× 间隔、Q=√2 ⇒ 相邻 peaking 显著重叠。
  核验"每段独立 ±12 dB"与"整链最大增益 G"的语义是否一致；
  指出 "+12 dB @1 kHz 且 +12 dB @2 kHz"这类组合在级联后的真实峰值，
  并判断文档的 G 计算（product of H_i）是否已正确覆盖该叠加。
- **G 由频域幅值推出 ⇒ 只对稳态信号成立。** 白噪声/稳态正弦满足 |y|≤max|H|·|x|，
  但 biquad 冲激响应的振铃、L1 范数可使瞬态峰值超过频域上界。
  判定文档是否把"频域估计 ⇒ 任意瞬态安全"这一推理漏洞封住
  （其结论是"末端 limiter 必不可少"，检查该结论是否被清楚标注为工程必需而非可选）。
- `safe = -max(0, G)`、Auto 取 `safe + 0.5 dB`、中性全零特例 0、手动 `min(request, safe)`。
  从**播放器（而非母带）**视角评估这 0.5 dB 的取舍：
  对比"preamp 精确补偿 + limiter 仅作安全网"的常见做法，指出 0.5 dB 的**可闻代价**
  （相对其他播放器的响度差）与**收益**（limiter 介入更少），
  并核对 PRD/design 是否记录了等响度 A/B 的实测结论，而非只有推算。
- 检查 `G` 是否被用于**压制用户合法意图**：安全值可低于 −12 dB 时，
  预设/用户曲线的实际落地增益与 UI 显示是否一致（是否有静默衰减）。

### 2.3 频段有效性边界 `fc <= 0.45*Fs`
- 逐一列出 Fs = 22050 / 44100 / 48000 / 96000 下哪几段退化为 identity。
- 核验实现是否真的**跳过该段系数**（而不是"增益为 0 的 peaking"），
  以及**响应图是否同步显示该段为 0 dB**（图与实际不一致 = 界面撒谎）。
- 关键盲点：矩阵测试用的是 48 kHz 输出设备 + 各采样率素材，
  但**从未测过"源采样率 ≠ 输出采样率"**（例如 96 kHz 源 → 48 kHz 设备）。
  ⇒ 追问：mpv filter graph 实际工作在哪个采样率？`0.45*Fs` 用的是源 Fs 还是输出 Fs？
  若从未测量，必须标为**未验证的高风险项**，而不是"四采样率已覆盖"。

### 2.4 FFmpeg `alimiter` 参数与延迟
- `limit=0.891250938`（−1 dBFS）、`attack=5 ms`、`release=50 ms`、
  `level_in/out=1`、`asc=false`、`level=false`、`latency=true`。
  逐项判断：auto-level 是否已确实关闭（否则会破坏 preamp 预算）、
  `asc`（自动真峰）关闭后是否只剩 sample-peak 保护、`latency=true` 引入的
  look-ahead 延迟**由谁补偿**。
- 攻击/释放时间常数是否与"保护 0.5 dB 稳态超限"的目标自洽：
  5 ms attack 对低频/鼓点瞬态的实际行为、50 ms release 是否会造成抽吸（pumping）。
  设计称其为"候选初值、恰为 FFmpeg 默认"——请核对 FFmpeg 文档中的默认值，
  并指出"沿用默认值"不是工程论证。
- **真峰值（dBTP / inter-sample peak）从未测量**，仅测 s16 整数 PCM 的 sample peak。
  评估：−1 dBFS sample-peak 上限在 44.1/48 kHz 重采样、DAC 重建、后级处理后还剩多少余量？
  明确判定"宣称 sample-peak、不宣称 true-peak"是否足够诚实，或是否应在 Gate 中加入 dBTP 诊断项。

### 2.5 `extrastereo` 空间化
- 核验 `M=(L+R)/2, S=(L-R)/2, L'=M+1.25S, R'=M−1.25S` 与
  `extrastereo=m=1.25:c=false` 的实际行为是否一致。
  **`c`（center coefficient）设为 false/非默认是否导致中央信号（人声/贝斯）下沉？**
  这是 mono 兼容性的经典陷阱：要求给出以源码或实测为依据的判据，
  而不是接受"逐样本最坏放大界 1.25（1.938 dB）"这句结论。
- 单声道输入：探针显示 mono 仍为 mono、空间链被跳过。评估这是否意味着
  **单声道歌曲完全得不到该特性**却无任何 UI 提示（可及性/一致性）。
- `process_command` 缺失 ⇒ width 只能安装期生效、运行时调整无效（已在 R1 承认）。
  判定：既然运行时不可改，"width=1.25" 事实上是**写死的全局常量**。
  那么 design 中围绕"width 是可调参数"的表述、PRD 的可配置性承诺、
  以及"不暴露空间编辑"的边界是否自洽？是否应降级为固定处理并从规格中移除该维度？

### 2.6 平滑、参数原地更新与状态机
- 30 ms 斜坡、actor 下一轮立即开始、latest-intent 覆盖、类型切换允许重配置。
  DSP 视角追问：
  (a) 对 **biquad 系数**做线性增益斜坡 vs 对**滤波器状态**做交叉淡化，
  哪种才是无 click 的正确做法？当前做法是否会在系数跳变时产生瞬态？
  (b) 拖动时每帧一次 `af-command` 是否会在链上排队积压（命令洪水），
  实际是否由 latest-intent 合并后仍触发 N 次 reconfig？
- 首样本屏障：文档称"音效首样本屏障实际暂停后端"（R8）。评估：
  一个 30 ms 的斜坡若发生在暂停态，恢复播放时**起点是否落在斜坡中段** ⇒ 音量突跳。
  检查是否有关于"屏障期间淡入斜坡起点对齐"的说明或实测。
- 采样率变化 / 曲目切换 / EQ↔空间切换时，链重建与参数重下发的顺序是否被证明正确
  （文档要求"等 libmpv 报告重配置后再发具名命令"——检查是否真的观测了该事件，
  还是仅按超时/顺序假设）。

### 2.7 测量方法学本身
- 响应测量只用 **997 Hz** 打 1 kHz 段，误差 −0.004 dB。
  判定：这能证明什么、不能证明什么？
  尤其：design 承诺的"原生低电平扫频/脉冲响应与计算最大误差 ≤ 0.25 dB"
  **在已取得证据中并不存在**（扫频素材只用于 limiter 压力点，未用于响应测量）——
  请核实并把这判为**验收标准未被测量**，而不是"已通过"。
- `ao=pcm --capture-only` 捕获的是 **s16**，而 CoreAudio 协商的是 **s32**。
  量化误差对本测量的影响量级；为何不直接在 s32 域测量。
- 矩阵报告 24/24 `probe-only`、`gate_passed=false`、最大峰值 −0.99985 dBFS。
  核对该数值与 `limit=0.891250938` 的理论预期是否自洽
  （0.89125 → −1.0 dBFS；实测 −0.99985 dBFS 说明什么剩余余量？）。
- **对照组缺失**：噪声/脉冲/反相素材的输出峰值"低于单音"——
  请判断这是限幅器行为的正常结果，还是**反相素材本应是限幅最狠的用例**而被解释掉了。
  双声道反相（`L=−R`）在 `extrastereo` + 独立声道 EQ 下的行为，是否被正确设计为最坏用例？
