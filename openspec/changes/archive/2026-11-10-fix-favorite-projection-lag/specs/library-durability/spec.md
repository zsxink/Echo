# Spec Delta

## Purpose

修正 LD-01 对「SQLite 投影可在后台滞后」的许可范围：把该许可收窄到**非单次点击关键路径**的本地编辑，并明确**收藏这类用户直接感知的高频小写入**必须在返回前完成读模型投影，使收藏一次点击即在列表、喜欢视图与收藏计数中可见。

## MODIFIED Requirements

### Requirement: LD-01 本地音乐库权威提交

系统 MUST 将音乐库目录中的已提交资料定义为用户数据的唯一持久事实来源，SQLite 仅作为可重建投影。所有来源的歌曲、喜欢、歌单、成员、覆盖层、逐设备统计、类型化墓碑、必要别名与用户资源变更 MUST 先可靠提交到本地音乐库，再提交其业务数据库投影。交互式本地编辑在目录提交确认后 MUST 可立即返回已保存状态；**除收藏这类用户单次点击即可感知的写入外**，SQLite 投影可在后台滞后，SQLite 写锁或投影失败不得阻塞已保存确认。系统 MUST 区分未保存、已保存但待投影和已完成；SQLite 提交成功不能替代音乐库保存成功。格式、权限、空间或刷盘失败 MUST 可见，且不得继续接受仅写数据库的用户变更。

**收藏这类用户单次点击即可感知的写入 MUST 在返回已保存前完成其 SQLite 读模型投影**，使返回后立即读取的歌曲列表、喜欢视图与收藏计数已经是该次写入的权威结果，不得仍呈现写入前的旧值。此类写入的投影失败 MUST 仍按「已保存待投影」报告并保留稳定操作身份：目录提交已经发生，系统 MUST NOT 把它误报为未保存，MUST NOT 静默丢弃，也 MUST NOT 为同一意图创建第二个对象。

同步投影 MUST 只覆盖本次写入对应的增量提交（自当前投影水位起按目录链顺序幂等追赶），MUST NOT 因一次收藏而重放整库历史。

#### Scenario: 本地写入失败
- **WHEN** 音乐库控制面不可写或持久化失败，而 SQLite 仍可写
- **THEN** 用户变更不以普通成功返回，SQLite 不产生独占的新业务事实，原已提交资料保留，用户获得可重试或需处理的原因

#### Scenario: 目录已提交而投影失败
- **WHEN** 本地音乐库已提交完整变更，SQLite 投影随后失败
- **THEN** 系统明确返回已保存待投影及稳定操作身份，保留变更并可重试/重建视图，不能把该变更误报为未保存或创建第二个对象

#### Scenario: SQLite 投影滞后时连续本地编辑
- **WHEN** 第一条歌单编辑、导入或其它非收藏的本地编辑已可靠提交到目录而 SQLite 仍落后，用户立即发起第二条操作
- **THEN** 第二条操作从有序权威状态读取第一条已保存事实并分配正确版本；前台不等待 SQLite 追平，投影 worker 按目录序号提交完整业务行与同一事务内的连续水位，重启后可从该水位重放

#### Scenario: 收藏写入返回后立即回读已是新值

- **WHEN** 用户对一首歌曲执行收藏，目录提交确认后系统返回已保存
- **THEN** 返回后立即读取该歌曲所在列表、喜欢视图与收藏计数，三者均已是收藏后的值，不得仍呈现收藏前的旧值

#### Scenario: 收藏的投影失败仍报告为已保存待投影

- **WHEN** 收藏的目录提交已成功，但随后的 SQLite 投影失败
- **THEN** 系统返回已保存待投影及稳定操作身份，收藏意图保留且可重试重建，不得误报为未保存，也不得为同一意图创建第二个收藏事实

#### Scenario: 收藏写入只追平增量投影

- **WHEN** 音乐库目录已有若干历史提交、SQLite 投影水位落后若干条，用户执行一次收藏
- **THEN** 该次写入只投影自当前水位起的增量提交，不重放整库历史，且收藏写入本身按收藏场景的同步投影规则完成
