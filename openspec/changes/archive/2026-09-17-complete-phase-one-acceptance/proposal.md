## Why

一期的“歌曲可以播放”主路径已经通过人工验收，但完整的日常使用闭环尚未成立。代码审计和回归测试确认了歌单无法创建、播放队列的当前项顺序与回退历史不符合预期、资料库视图筛选失真，以及两个桌面 Rust 回归失败；这些问题会让用户在建立和持续使用曲库时得到失败、静默空态或错误的结果。

本变更把一期剩余的可观察行为补齐为可验收的契约，并补上端到端及回归验证，使“导入/浏览/搜索/播放/建歌单/重启继续使用”成为可靠闭环，而不扩大到二期同步或批量功能。

## What Changes

- 修复歌单创建使用活动资料库根 ID 的命令链；创建成功后刷新导航并打开新歌单。歌单加载、移除成员和入队等异步操作只在服务端成功后反馈成功，失败必须保留界面状态并说明可恢复错误。
- 固化队列展示和传输语义：无论列表循环、随机或单曲循环，当前播放项始终位于 UI 队列首位；后续项按对应模式展示，清空待播只影响首项之后的项目。
- 将“上一首”所需的播放历史改为按实际播放时间保存、最多保留三天、可跨重启恢复的独立记录；过期、被删除或不可用的记录不能导致回退失败或改变待播顺序。
- 修复恢复会话中 blocked 项的保留、标识与重试路径，使 UI 不把它们伪装为可正常播放项目；同时保证会话内队列状态和快照顺序一致。
- 修复资料库查询在活动根目录切换后的失效、在“喜欢的音乐”和“最近添加”视图的搜索叠加，以及非“全部歌曲”视图错误暴露全库排序控制的问题；从分页视图开始播放时建立完整、确定性的当前视图上下文。
- 修复并覆盖当前的桌面播放器加载状态与诊断日志副作用回归；将已发现的流程加入可重复执行的验收矩阵。

## Capabilities

### New Capabilities

- `phase-one-acceptance`: 一期跨功能日常流程的端到端验收门槛与回归基线。

### Modified Capabilities

- `desktop-playback`: 明确当前项置顶的队列投影、三天可恢复的播放历史、blocked 恢复状态以及完整视图播放上下文。
- `playlist-management`: 明确活动资料库内创建歌单的根 ID 绑定和异步失败反馈。
- `library-experience`: 明确搜索与每个资料库视图的叠加、根目录切换失效与非全库视图排序边界。

## Impact

- 前端：`apps/desktop/src/app/App.tsx`、歌单与曲库 hooks/视图、`QueuePanel`、播放器 store 与相关组件测试。
- 桌面运行时：Tauri playlist command、`runtime/player.rs`、`player/queue.rs`、`player/session.rs`、`player/coordinator.rs`、actor/diagnostics 测试。
- IPC：播放器快照和播放上下文可能需要增加队列展示顺序、blocked 状态及历史恢复所需字段；保持 WebView 不暴露绝对路径。
- 验证：Rust/React 单元测试、真实桥接或 native 场景、现有 traceability/manifest 对账；不增加网络、同步或批量操作依赖。
