# Spec Delta

## ADDED Requirements

### Requirement: 已归档门禁与本地临时产物的清理

验证治理中标记为归档（archived）的 task gate，其脚本资产 MUST 与归档状态保持一致：当某 task 的归档状态表明其断言已由其他检查承载，且该 task 的验证命令不再被任何实际执行入口引用时，对应脚本 MUST 从交付工作树中移除。脚本若仍被结构门禁、注入治理证明或其他实际执行入口作为消费者引用，则 MUST 保留，并 MUST 在治理清单中记录消费者与保留理由；归档状态不得成为删除仍有消费者的脚本的依据。

归档状态、治理清单条目与持续集成配置中的说明 MUST 对同一 task 给出一致描述，MUST NOT 留下指向已移除脚本的悬空路径。治理资产的清理 MUST NOT 改变持续集成实际执行的检查集合、平台覆盖或断言强度；仍在执行或仍被委托的检查 MUST NOT 因归档清理而消失。

本地临时产物（构建输出、工具生成的临时配置、一次性草稿与日志）MUST NOT 作为交付资产登记或计入检查覆盖。被版本控制跟踪的验收资产 MUST NOT 在本地清理中删除。清理结果 MUST 可由可复跑的引用检查与治理门禁证明：待移除资产确无执行引用、保留例外确有消费者、清单与配置无悬空路径。

#### Scenario: 归档且无执行引用的脚本被移除

- **WHEN** 某 task 标记为 archived，其验证命令不被持续集成、治理 runner 或注入治理证明中的任何执行入口引用
- **THEN** 该 task 对应的门禁脚本从交付工作树移除，且实际执行的检查集合保持不变

#### Scenario: 归档但仍有消费者的脚本被保留

- **WHEN** 某 task 标记为 archived，但其门禁脚本仍被结构门禁或注入治理证明作为防回归消费者引用
- **THEN** 该脚本保留，治理清单记录其消费者与保留理由，不因归档状态被删除

#### Scenario: 清单或配置指向已移除脚本

- **WHEN** 某脚本已移除，而治理清单的验证命令或持续集成配置的说明仍引用该路径
- **THEN** 引用检查或治理门禁失败并指出该悬空路径，而不是让清单静默保留死条目

#### Scenario: 清理误删仍执行的检查

- **WHEN** 一次归档清理移除了仍被持续集成执行、或仍被其他检查委托的门禁脚本
- **THEN** 治理门禁因检查集合变化而失败，并指出缺失的检查

#### Scenario: 本地临时产物被当作交付资产

- **WHEN** 构建输出、工具临时文件或一次性草稿被登记为验收资产或计入门禁覆盖
- **THEN** 该资产被判定为未生效并列出处置清单，不计入检查覆盖

#### Scenario: 本地清理删除被版本控制的验收资产

- **WHEN** 本地清理操作删除了被版本控制跟踪的验收资产
- **THEN** 该删除被视为越界，资产必须恢复，且清理范围只限于被忽略的本地产物

#### Scenario: 清理结果无法复跑证明

- **WHEN** 归档清理完成后，无法用可复跑检查证明待移除资产无执行引用、保留例外有消费者或清单无悬空路径
- **THEN** 该清理不被视为完成，治理验证失败并指出未证明的项
