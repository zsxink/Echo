## MODIFIED Requirements

### Requirement: 扫描、监听与手动重扫

系统 MUST 扫描 `media/` 及其子目录中的一期支持音频格式，解析每个文件并建立或更新记录；运行期间 MUST 监听新增、删除、移动和修改，并在设置页提供可重复执行的手动重新扫描入口。扫描 MUST 忽略资料库根目录中 `media/` 以外的所有内容，包括 `echo/`（及 `echo/tmp/`）；扫描结果 MUST 可报告已发现、已更新、已删除、跳过和失败的数量及错误原因。手动扫描进行期间，入口 MUST 禁止重复触发并明确显示进行中状态；扫描成功后，已挂载的歌曲列表、导航计数、封面和当前歌曲歌词 MUST 能读取本次扫描提交的权威结果。

#### Scenario: 首次扫描发现支持文件

- **WHEN** 用户确认具有 `media/` 的根目录并触发首次扫描
- **THEN** 系统仅递归发现 `media/` 下的支持格式文件，逐文件解析并持久化歌曲记录，扫描完成后可在曲库检索这些歌曲

#### Scenario: 忽略不支持文件

- **WHEN** 根目录包含图片、文档或未列入一期格式矩阵的文件
- **THEN** 系统不创建歌曲记录，不移动或修改该文件，并在扫描结果中将其作为跳过项而非失败歌曲

#### Scenario: 忽略控制面目录

- **WHEN** 根目录包含 `echo/`（包括 `echo/tmp/`）及其任何内容
- **THEN** 系统不将控制面或暂存内容创建为歌曲记录，也不移动或修改其文件

#### Scenario: 不兼容旧资料库布局

- **WHEN** 用户选择的目录只包含旧布局的根目录艺人文件夹且不存在可扫描的 `media/`
- **THEN** 系统明确要求用户建立新的资料库或重新导入媒体，不扫描旧布局、不迁移歌曲 UUID 且不创建旧路径歌曲记录

#### Scenario: 监听外部新增和修改

- **WHEN** 资料库运行中新增支持音频、删除音频、移动音频或修改音频内容
- **THEN** 系统在监听事件稳定后更新对应记录和搜索索引；事件丢失或无法确定变化时，用户可通过设置页的手动重扫得到同样的最终状态

#### Scenario: 从设置页手动重新扫描

- **WHEN** 用户在已配置资料库的设置页点击“重新扫描”
- **THEN** 系统重新检查活动资料库，按钮进入进行中状态并禁止重复点击；扫描完成后歌曲列表、导航计数、封面和当前歌曲歌词反映本次扫描提交的结果，扫描失败时保留既有内容并显示可重试提示

#### Scenario: 没有活动资料库时不能重扫

- **WHEN** 当前没有活动资料库，或资料库扫描已在进行中
- **THEN** 设置页的“重新扫描”入口处于禁用状态，不发起新的扫描请求
