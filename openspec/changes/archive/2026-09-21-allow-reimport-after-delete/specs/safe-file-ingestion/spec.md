## MODIFIED Requirements

### Requirement: BLAKE3 去重与重名编号

系统 MUST 使用全文件 BLAKE3 判断重复内容。目标位置或资料库中已有相同哈希时 MUST 不复制、不新建歌曲 UUID，并返回已存在记录；目标文件名相同但内容不同 MUST 依次使用 ` (2)`, ` (3)` 等编号，直至找到同时不存在或内容相同的安全目标，绝不覆盖既有文件。资料库中 `availability` 非 `Available` 的歌曲记录 MUST 不参与本次导入的内容持有者或目标路径占用快照。

#### Scenario: 内容重复

- **WHEN** 导入文件的 BLAKE3 与资料库中一首 `Available` 歌曲相同
- **THEN** 系统跳过音频和相应副本的重复写入，不创建第二条歌曲记录，并告知用户已有歌曲位置/UUID

#### Scenario: 已删除歌曲允许重新导入

- **WHEN** 导入文件的 BLAKE3 只与资料库中 `PendingDelete`、`Missing` 或其他非 `Available` 歌曲记录相同，且其目标路径已不再存在
- **THEN** 系统不得返回重复导入，且 MUST 将该文件作为新歌曲导入；旧的不可用记录及其关联保持不变，直到既有删除恢复/最终化流程处理它

#### Scenario: 不可用记录不占用旧目标路径

- **WHEN** 非 `Available` 歌曲仍保留旧的相对路径，但用户重新导入相同内容
- **THEN** 该旧路径不因歌曲记录本身被视为占用，导入按当前文件系统中的实际占用情况选择安全目标，绝不覆盖现有文件

#### Scenario: 同名不同内容

- **WHEN** 目标已有同名音频但 BLAKE3 不同
- **THEN** 系统生成带最小可用编号的目标名，保留原文件不变，并将新文件作为新歌曲导入
