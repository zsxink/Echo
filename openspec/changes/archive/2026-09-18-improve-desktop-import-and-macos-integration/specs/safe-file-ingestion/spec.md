## ADDED Requirements

### Requirement: 受控并发批量导入与非阻塞反馈
系统 SHALL 对同一批次中互不依赖的文件使用有界多线程导入；当批次至少包含两个文件时，系统 MUST 允许至少两个文件的复制、哈希或元数据解析工作在不同 worker 线程真实重叠，同时保持既有每文件原子发布、去重和操作日志语义。导入入口 MUST 直接打开原生多选文件选择器；导入执行期间入口显示“导入中…”，不得以进度对话框阻断资料库界面。

反馈分流 MUST 唯一确定：已导入、内容重复、重名后成功及无需处理的正常跳过属于非失败结果，以 toast 汇总；文件损坏、不支持、权限错误、复制/解析/发布失败及资料库不可用属于失败结果，以详情对话框逐项显示原因。混合批次同时显示非失败结果汇总 toast 和仅包含失败项目的详情对话框；全失败批次只显示失败详情对话框。

#### Scenario: 大批量并发导入
- **WHEN** 用户选择多个可独立导入的音频文件
- **THEN** 系统以受控 worker 数处理它们，至少两个文件的重型处理阶段可同时处于执行中，界面仍可响应，且每个文件仍返回唯一结果

#### Scenario: 无失败结果完成
- **WHEN** 批次仅包含已导入、内容重复、重名后成功或无需处理的正常跳过项
- **THEN** 导入按钮恢复可用并显示汇总 toast，不出现导入结果对话框

#### Scenario: 批次包含失败
- **WHEN** 批次同时包含非失败结果以及文件损坏、不支持、权限错误、处理失败或资料库不可用结果
- **THEN** 非失败项保持已提交并由 toast 汇总，系统另行显示仅包含失败文件及原因的详情对话框

#### Scenario: 全部项目失败
- **WHEN** 批次中的所有项目均属于失败结果
- **THEN** 系统只显示失败详情对话框，不显示虚假的成功或重复 toast

#### Scenario: 多线程重叠可验证
- **WHEN** 测试用两个文件在复制、哈希或解析阶段等待同一同步屏障
- **THEN** 两个任务均能在屏障释放前进入该阶段，证明实现不是单 worker 串行处理
