# Echo 0.1.0 一期产品需求文档（PRD）

> 文档状态：待评审  
> 目标版本：0.1.0  
> 目标平台：macOS、Windows、Linux  
> 产品阶段：一期——完整桌面版播放器  
> 更新日期：2026-08-28

## 1. 产品摘要

Echo 0.1.0 是一个无需账号、无需网络、以用户本地音乐文件为中心的桌面音乐播放器。它必须完成从“选择或导入音乐”到“长期管理、检索、播放和建立歌单”的完整闭环，并安全地处理用户文件、应用崩溃、目录失联和跨平台差异。

0.1.0 同时包含现有路线图中的 Phase 0 工程地基与 Phase 1 全部桌面能力。它不是同步版的预览，也不是只有静态界面的播放器外壳。

## 2. 背景与问题

目标用户已经拥有自己的本地音乐文件，但常见播放器要么依赖账号和流媒体目录，要么只负责播放、不负责稳定索引、歌词、歌单和文件变更。Echo 要解决以下问题：

1. 用户可以保留自己的目录和文件所有权，播放器不会在扫描时擅自移动或改写文件。
2. 文件被外部程序改名、移动或修改后，收藏和歌单不应因为路径变化而失效。
3. 从下载目录加入音乐时，不应覆盖同名文件，也不应因中途失败留下半份文件或幽灵记录。
4. 日常的搜索、排序、收藏、队列、歌词和歌单体验必须离线且高效。
5. 桌面窗口关闭后，用户可以按平台习惯决定退出或继续后台播放。

## 3. 目标与成功定义

### 3.1 产品目标

- 在三大桌面系统交付可独立日常使用的本地音乐播放器。
- 以稳定 UUID 连接歌曲、收藏、歌单和播放队列，路径只用于定位文件。
- 对扫描、导入、删除和文件失联提供明确、可恢复、绝不静默覆盖的行为。
- 复刻现有原型的高效曲库与沉浸播放体验，同时移除不属于一期的交互。
- 建立可被二期同步、三期 Android、四期 iOS 复用的 Rust Core 和数据边界。

### 3.2 一期完成标志

在 macOS、Windows、Linux 任一支持环境中，用户均可完成：

`首次启动 → 选择资料库 → 扫描或导入 → 搜索/排序 → 播放 → 收藏/建立歌单 → 关闭并重启 → 恢复资料库与播放上下文`

整个流程不依赖账号或网络；资料库外文件可由系统双击临时播放且不污染资料库。

### 3.3 发布级成功指标

- 三个平台均通过核心端到端验收矩阵，不存在平台阻断级缺陷。
- 扫描、导入、删除的故障注入测试均不产生被覆盖的用户文件、重复 UUID 或数据库/文件路径永久不一致。
- 50,000 首已索引曲库中，常用搜索查询在参考设备上的本地 p95 响应不高于 200 ms，列表滚动不因全量 DOM 渲染产生持续卡顿。
- 核心领域规则单元测试覆盖率不低于 90%；格式、lint、类型检查、测试和三平台构建全部通过。
- 应用运行期间不发起业务网络请求；0.1.0 不需要登录、云端凭据或遥测授权。

## 4. 用户与核心场景

### 4.1 目标用户

- 拥有自建 MP3/FLAC 等音乐目录的个人用户。
- 在工作、居家或整理音乐时，需要快速搜索、播放和维护歌单的桌面用户。
- 看重离线、隐私、文件所有权和跨平台一致性的用户。

### 4.2 核心用户故事

- 作为首次用户，我希望选择一个音乐目录并看到扫描进度，以便确认 Echo 正在建立曲库。
- 作为长期用户，我希望在 Finder/Explorer 中改名或移动文件后，Echo 仍保留歌曲的收藏、播放次数和歌单关系。
- 作为整理音乐的用户，我希望从下载目录导入多首音乐而不覆盖任何已有文件。
- 作为听歌用户，我希望按歌名、艺人或专辑快速搜索，并按最近添加、歌名、艺人或播放次数排序。
- 作为歌单用户，我希望创建、重命名和删除歌单，并把歌曲加入或移出歌单。
- 作为沉浸聆听用户，我希望看到封面、黑胶动效和随进度定位的歌词，也能在无歌词时得到明确反馈。
- 作为桌面用户，我希望用媒体键、托盘/菜单栏和快捷键控制播放，并选择关窗后是否继续运行。
- 作为临时试听用户，我希望双击资料库外的音频即可播放，但它不会自动进入我的资料库或统计。

| 收藏与歌单 | 收藏切换、歌单 CRUD、歌曲成员管理、追加顺序 |
| 播放 | mpv、队列、上一首/下一首、播放/暂停、seek、音量、三种模式 |

| 质量 | 离线、无静默覆盖、可访问、三平台路径与权限测试 |

### 5.2 明确不包含

- S3、WebDAV 或其他远端同步；同步按钮、状态、配置和模拟进度均不出现为可操作功能。
- 全选和任何批量操作；原型中的全选控件不进入一期界面。
- Android、iOS、账号、流媒体目录、推荐、社交和业务遥测。
- 自定义导入目录或文件名模板、按实际目录浏览的目录树视图。
- 歌曲元数据编辑、“仅保存到 Echo”的覆盖层编辑 UI、写回文件和应用内移动歌曲。
- 歌单手动排序、歌单之间拖拽排序和自定义歌单封面上传。
- 均衡器、音效、跨设备队列、播放历史详情、智能歌单。

### 5.3 原型冲突处理

项目事实优先级为：本变更已批准规格 > `docs/ROADMAP.md` / `docs/PRODUCT.md` > `docs/DESIGN.md` > 界面原型演示逻辑。原型中的模拟同步、全选、歌单拖拽排序和自定义歌单封面只作为视觉探索，不构成 0.1.0 需求。

## 6. 统一术语

| 术语 | 定义 |
|---|---|
| 资料库 | Echo 在 SQLite 中维护的歌曲、收藏、歌单、统计和索引集合。 |
| 资料库根目录 | 用户选择的本地音乐文件根路径；0.1.0 同时只有一个活动根目录。 |
| 歌单 | 用户持久化创建的歌曲集合，保存歌曲 UUID，歌曲按追加顺序展示。 |
| 播放队列 | 当前桌面设备的播放上下文和待播顺序，不等同于歌单。 |
| 临时播放项 | 资料库外文件对应的内存播放项，不写入资料库、歌单或统计。 |
| 常驻播放栏 | 主窗口底部始终可达的当前歌曲、进度和播放控制区域。 |
| 沉浸式播放器 | 展示封面/黑胶、歌曲信息和歌词的展开模式。 |

## 7. 关键产品决策

### 7.1 支持格式

0.1.0 保证扫描、导入和系统文件关联支持：

- MP3：`.mp3`
- FLAC：`.flac`
- MP4 音频：`.m4a`，以及经探测确认含可播放音轨的 `.mp4`
- Ogg/Opus：`.ogg`、`.opus`
- WAV：`.wav`

扩展名只是候选过滤条件，文件内容仍须探测；伪装扩展名、损坏文件和无音轨 MP4 必须报告为单文件失败，不能中止整批扫描或导入。0.1.0 不承诺其他格式，即使本机 mpv 能偶然播放。

### 7.2 活动资料库根目录

- 首次启动引导用户选择目录，也允许稍后在设置中选择。
- 同一时刻只有一个活动根目录。切换目录不会移动或删除旧目录中的文件。
- Echo 保留旧根目录的逻辑记录；重新选择同一路径时复用原逻辑根和歌曲身份。主界面只展示活动根目录的歌曲。
- 新目录首次扫描成功前不丢弃当前可用视图；切换失败时继续使用原活动根目录。
- 切换前必须先让旧根进入静默点：进行中的导入和已进入 10 秒撤销期的删除会阻止切换并给出可继续操作；扫描可取消，watcher 先冻结并在切换完成后重绑定。提交切换时停止旧根当前播放、清除旧根播放上下文并提示用户，不允许后台继续消费非活动根文件。
- “首次扫描成功”是指候选目录完整枚举结束、扫描未取消、没有根级权限/路径边界/数据库错误，且所有单文件错误均已汇总；空目录可以成功，根级失败不能替换旧活动根。

### 7.3 歌曲身份与重关联

- 歌单、收藏、播放队列和播放统计以歌曲 UUID 为身份，不以绝对路径为身份。
- 相同活动根和相同相对路径优先关联已有记录；路径消失且新路径 BLAKE3 相同时，更新路径并保留 UUID。
- 一个活动资料库内相同 BLAKE3 内容只保留一条歌曲记录。
- 仅在哈希无法确认且旧记录缺失时，才使用标准化的艺人、专辑、标题和时长作为弱匹配候选；弱匹配不得自动合并两个同时存在的不同文件。

### 7.4 元数据与歌词优先级

- 标题缺失时使用不含扩展名的文件名；艺人缺失时显示“未知艺人”；专辑缺失时显示“未知专辑”。
- 封面优先使用音频内嵌封面；缺失时显示主题化占位图，不在一期联网抓图。
- 歌词展示优先级：未来保留的 Echo 覆盖层 > 内嵌歌词 > 同目录同基础文件名 `.lrc`。
- 对同一来源同时存在同步歌词和纯文本歌词时，优先同步歌词；无法解析的歌词显示明确错误并允许继续播放。

### 7.5 播放计数

- 资料库歌曲一次加载会话中，累计真实播放时间达到 `min(30 秒, 歌曲时长的 50%)` 时计一次播放。
- 暂停期间不累计；seek 到阈值之后不会立即计数；同一次加载会话最多计一次。
- 重新从头主动播放可形成新的加载会话；临时播放项永不计数。

### 7.6 删除语义

- “删除歌曲”是用户明确授权的文件操作，不等同于扫描发现文件缺失。
- 用户确认后，音频与同名 `.lrc` 先进入资料库内的可恢复暂存区，歌曲从可见曲库、歌单成员和待播队列移除，并提供 10 秒“撤销”。
- 撤销恢复原路径、UUID、收藏、统计和歌单关系；超过撤销窗口后由系统集成将文件移入系统废纸篓/回收站并完成本地记录清理。
- 文件进入系统回收站前任一步失败时保留或恢复原文件与数据库关系；系统回收站成功是不可逆点，此后数据库清理失败必须幂等前滚完成并给出可重试错误，绝不伪造文件仍在原位。
- 若应用重启时暂存文件已消失但无法取得可验证的系统回收站成功证据，状态必须保持“结果未知”：不得清理 UUID、收藏、统计或歌单关系，暂停该资料库的写操作并提供人工确认/恢复指引。单凭路径不存在不能推断回收站成功。
- 扫描发现文件被外部删除时只标记缺失，不显示虚假的“已移入回收站”或自动创建二期同步墓碑。
- 删除当前播放歌曲时，桌面端必须先停止或推进到下一可用队列项并等待播放器确认释放文件句柄，再开始暂存；同一歌曲的其他重复队列项一并移除。若释放失败，删除不开始且数据库/文件保持原状。

### 7.7 播放队列与恢复

- 从某个视图播放歌曲时，以该视图当前过滤和排序结果建立播放上下文，从所选歌曲开始。
- “下一首播放”插入当前项之后；“清空队列”只清空待播项，不中断正在播放的歌曲。
- 顺序播放在队尾停止；随机播放在当前上下文未完整轮播前避免重复；单曲循环持续当前歌曲。
- 本机持久化资料库 UUID 队列、当前歌曲、位置、音量和播放模式；重启后恢复上下文但不自动发声。
- 恢复时把外部缺失或根目录暂不可用的队列项保留为 blocked，并跳到下一可用项；只丢弃 Echo 已永久删除或不属于活动根目录的项并提示。临时播放项不持久化。

### 7.8 关窗与后台运行

- macOS 默认关闭主窗口但保持后台运行；Windows/Linux 默认关闭主窗口即退出。
- 设置允许用户切换“退出应用”或“保持在后台运行”，选择仅保存在本机。
- 保持后台时播放继续，菜单栏/系统托盘提供当前歌曲、播放/暂停、上一首、下一首、显示主窗口和退出。
- 从托盘/菜单栏选择“退出”始终完整退出，不受关窗偏好影响。

## 8. 主要用户流程

### 8.1 首次启动与扫描

1. 展示空资料库与“选择音乐文件夹”主操作，不强制登录或联网。
2. 用户选择可读目录后，Echo 验证权限并设为活动根目录。
3. 界面立即展示扫描状态：发现文件数、已处理数、失败数和可取消/重试入口。
4. 已成功解析的歌曲可增量出现；扫描、哈希和标签解析不得阻塞 UI 或播放。
5. 完成后展示歌曲总数和失败摘要；单个坏文件不使整个扫描失败。

### 8.2 导入音乐

1. 用户点击“导入”，多选支持格式文件。
2. Echo 逐文件解析、计算哈希并显示批次进度。
3. 目标为 `歌手/歌手 - 歌曲名.扩展名`；非法文件名字符被安全替换，缺失标签使用兜底。
4. 相同内容跳过并指向已有歌曲；同名不同内容追加 ` (2)`、` (3)`；绝不覆盖。
5. 同目录同基础名 `.lrc` 一并复制并匹配最终目标基础名。
6. 批次结束展示成功、重复跳过和失败明细；一个文件失败不回滚其他已成功文件。

### 8.3 搜索、排序与播放

1. 用户进入全部歌曲、最近添加、喜欢的音乐或某歌单。
   “最近添加”固定为按添加时间降序的最近 100 首可用歌曲。
2. 搜索在当前视图内按标题、艺人、专辑进行不区分大小写的包含匹配。
3. 全部歌曲支持最近添加、歌曲名称、艺人、播放次数，均可升序/降序；相同主键使用标题、艺人、UUID 保证稳定顺序。
4. 播放歌曲后常驻播放栏更新，播放上下文采用当前过滤/排序结果。
5. 用户可收藏、设为下一首、加入歌单、查看只读详情或打开所在目录。

### 8.4 歌单管理

1. 用户新建 1–40 个用户感知字符（Unicode grapheme cluster）的歌单；去除首尾空白后不能为空，同名按 Unicode 标准化和不区分大小写判重。
2. 用户从歌曲操作菜单选择一个或多个歌单；重复添加同一歌曲为幂等操作，不产生重复成员。
3. 歌曲按首次加入顺序展示；移除后再次加入会追加到末尾。
4. 重命名保持歌单 UUID 和成员；删除歌单只删除歌单关系，不删除歌曲文件、收藏或播放统计。

### 8.5 系统双击临时播放

1. Echo 注册保证格式的文件关联并作为单实例应用接收打开请求。
2. 若文件属于活动资料库，解析为现有 UUID 并按资料库歌曲播放。
3. 若文件属于已保留但非活动的旧资料库，作为临时项播放并提示用户可显式切换资料库；不得直接使用旧根 UUID、统计或覆盖层，也不得静默切根。
4. 若文件不属于任何已绑定资料库，同样创建临时播放项，解析可得封面、标签、歌词和同名 `.lrc` 后播放。
5. 临时项不能加入歌单、收藏或统计，不能持久化到重启后的队列；用户可显式点击“导入到资料库”进入正常导入流程。

## 9. 信息架构与界面要求

### 9.1 主窗口

- 左侧侧边导航栏：品牌区、资料库导航（全部歌曲、最近添加、喜欢的音乐）、歌单导航、设置。
- 顶部栏：当前位置、全局搜索、导入。
- 资料库工作区：标题/数量、排序、虚拟化歌曲表、加载/空/搜索空/错误/不可用状态。
- 底部常驻播放栏：播放进度条、当前播放区、传输控制区、音频与队列区。
- 同步入口与全选控件在一期不渲染，避免不可操作占位。

### 9.2 歌曲表与详情

- 行展示序号/播放态、封面、歌曲名、艺人、专辑、时长和单曲操作。
- 最近添加和播放次数可用于排序，不要求作为默认列长期展示。
- 详情为只读：标题、艺人、专辑、时长、格式、码率/采样率（可得时）、文件大小、加入日期、播放次数、歌词/封面来源和相对路径。
- 不在一期提供标题、艺人、封面或歌词编辑控件。

### 9.3 沉浸式播放器与歌词

- 当前歌曲可展开为黑胶/封面、歌曲信息和歌词区域；播放/暂停与 reduced-motion 状态决定动画。
- 有时间戳歌词时，当前行跟随实际播放位置，用户 seek 后重新定位。
- 用户手动滚动歌词后暂停自动居中 5 秒；再次 seek 或点击“回到当前歌词”立即恢复跟随。
- 纯文本歌词允许阅读但不伪造逐行时间同步；无歌词时显示空状态和“打开所在目录”入口。
- 桌面宽屏允许歌词专注阅读；窄屏使用全屏沉浸布局，不遮挡关键传输控制。

### 9.4 主题与响应式

- 珊瑚玫红为默认主题，另提供深钴蓝、松石绿；主题只改变强调色和主要操作色，收藏红色语义独立。
- 主题、窗口尺寸/位置和窄屏侧边栏状态按合理范围保存；异常窗口位置回落到当前显示器可见区域。
- 宽度不超过 760px 时侧边栏改为遮罩抽屉，点击遮罩或 Escape 关闭；表格可隐藏次要列但必须保留歌曲识别与播放入口。

### 9.5 浮层与键盘

- Escape 按最上层优先级关闭：确认/命名对话框 → 设置 → 歌曲菜单/排序/队列 → 歌词专注 → 沉浸式播放器 → 窄屏侧边栏。
- 对话框打开时焦点被约束在对话框内，关闭后回到触发控件；菜单支持上下方向键、Home、End、Enter 和 Escape。
- 全局快捷键：`Cmd/Ctrl+F` 聚焦搜索、`Cmd/Ctrl+O` 打开导入、`Cmd/Ctrl+,` 打开设置、Space 播放/暂停（输入框和对话框内除外）。
- 进度条聚焦时左右键按 5 秒 seek，音量条聚焦时上下/左右键按 5% 调节；系统媒体键控制播放/暂停、上一首和下一首。

## 10. 状态与错误体验

| 状态 | 用户可见行为 |
|---|---|
| 未选择资料库 | 展示产品说明、选择文件夹主操作和可选的临时文件打开入口。 |
| 首次/手动扫描 | 展示非阻塞进度、成功数、失败数和取消/重试；已解析歌曲可浏览。 |
| 资料库不可用 | 保留索引和歌单，醒目标记不可用；禁用扫描、导入和相关播放，提供重新授权/重新定位。 |
| 单文件解析失败 | 保留其他成功结果，在摘要中展示文件名和可理解原因；不记录完整绝对路径到普通日志。 |
| 搜索无结果 | 显示“没有找到匹配的音乐”和清除搜索操作。 |
| 播放文件缺失/损坏 | 标记当前项不可播放，提示原因并按队列策略跳到下一可播放项；不无限循环错误项。 |
| 队列为空 | 正在播放的歌曲可继续；面板显示空状态和“浏览曲库”。 |
| 导入部分成功 | 汇总成功、重复、失败；允许只重试失败项。 |
| 操作恢复中 | 启动时优先恢复未完成导入/删除；完成前对涉及路径显示恢复状态，禁止并发冲突操作。 |

## 11. 数据、隐私与安全

- SQLite 位于应用数据目录，保存本地索引、相对路径、收藏、歌单、统计和偏好引用；音频和 `.lrc` 保持在用户资料库。
- 绝不把完整资料库、凭据或用户音频发送到网络；0.1.0 不初始化同步连接器。
- 普通日志默认记录操作 ID、错误分类和相对路径散列，不记录不必要的完整绝对路径、歌词或标签内容。
- 所有文件写操作必须限定在用户显式选择的源文件、活动资料库及受控暂存目录；路径规范化后必须阻止穿越根目录和符号链接逃逸。
- 导入和删除的数据库/文件系统跨资源操作使用可恢复状态，重试必须幂等。

## 12. 非功能需求

### 12.1 性能

- 扫描、哈希、标签解析和封面处理在受控后台任务执行，UI 输入处理不被长时间阻塞。
- 已建立索引的 50,000 首曲库搜索 p95 ≤ 200 ms；切换基础视图到首屏可交互 p95 ≤ 500 ms（参考设备：4 核 CPU、8 GB RAM、本地 SSD）。
- 歌曲表使用窗口化/虚拟列表，DOM 行数与视口规模相关，不与总曲库线性增长。
- 封面生成缩略图并缓存；列表不直接解码原始大图，缓存有容量上限和清理策略。

### 12.2 可靠性

- 应用或系统在导入/删除任一步骤崩溃后，下一次启动必须能继续或回滚，不留下覆盖文件或不可解释的重复记录。
- 扫描、监听事件和手动重扫具备幂等性；重复事件不创建重复歌曲。
- SQLite 开启外键、WAL 和合适的完整性检查；迁移失败时保留原数据库并给出恢复指引。
- 后台任务可取消、可结束、可回传错误；退出时不遗留无法追踪的进程或数据库锁。

### 12.3 可访问性

- 关键流程可仅用键盘完成；可交互元素有名称、焦点可见、状态通过语义属性表达。
- 正文、控件和关键状态满足 WCAG 2.2 AA 对比度；不只依靠颜色表达收藏、播放、失败或选中。
- 遵循系统 reduced-motion，关闭非必要黑胶、波形和过渡动画，但不削弱状态信息。
- Toast 使用礼貌播报；确认删除等阻断操作使用 alert dialog；错误不会因自动消失而无法读取。

### 12.4 跨平台兼容

- 路径测试覆盖 `/` 与 `\`、大小写敏感/不敏感文件系统、Unicode 组合字符、长路径、只读目录、权限撤销和可移动磁盘断开。
- 系统回收站、文件关联、打开所在目录、媒体键和托盘行为由平台适配层实现并通过各平台人工冒烟。
- 0.1.0 UI 默认提供简体中文；所有用户文案集中管理，避免阻碍后续国际化。

发布基线为：macOS 12+（Apple Silicon 与 Intel 通用包）、Windows 10 22H2/Windows 11 x64、Ubuntu 22.04 LTS 或同等 glibc 2.35+ 的 x86_64 Linux。macOS 首版采用开发者签名与 notarization 的非 App Store 分发；Linux 首版提供 AppImage 与 deb。Windows ARM64、Linux ARM64、Mac App Store、Snap 与 Flatpak 不在 0.1.0 承诺范围。

## 13. 验收矩阵

| 编号 | 验收路径 | 通过条件 |
|---|---|---|
| A1 | 空库首次启动 | 可选目录，扫描进度/错误清楚，无网络和账号要求。 |
| A2 | 10,000 首混合曲库扫描 | UI 可操作、支持格式入库、坏文件隔离、重扫无重复。 |
| A3 | 外部改名/移动 | BLAKE3 重关联后 UUID、收藏、统计、歌单关系不变。 |
| A4 | 多文件安全导入 | 默认命名正确；相同内容跳过；重名编号；崩溃恢复无覆盖。 |
| A5 | 资料库失联/恢复 | 保留索引并禁用危险操作；重新授权后恢复扫描和播放。 |
| A6 | 搜索/排序/收藏 | 三字段包含搜索、四主键双方向排序、收藏视图实时一致。 |
| A7 | 歌单 CRUD | 名称校验、成员幂等、追加顺序、删除歌单不删歌曲。 |
| A8 | 播放与队列 | 三模式、seek、音量、错误跳过、清空待播、重启恢复不自动播。 |
| A9 | 歌词与沉浸模式 | LRC 同步、seek 重定位、纯文本/无歌词、专注和 reduced-motion 正确。 |
| A10 | 系统双击文件 | 库内复用 UUID；库外临时播放且不入库、不统计、不持久化。 |
| A11 | 删除与撤销 | 暂存、10 秒撤销、系统回收站、失败恢复和关系一致性正确。 |
| A12 | 关窗与托盘 | 默认符合平台习惯；偏好生效；后台控制和显式退出正确。 |
| A13 | 无障碍与窄屏 | 键盘闭环、焦点恢复、Escape 优先级、760px 侧栏和关键控件可用。 |
| A14 | 范围保护 | 不出现可操作同步、全选批量、手动歌单排序或歌曲编辑入口。 |

## 14. 发布与回退

- 先完成 Core 与迁移契约，再接入桌面系统能力和 UI；三平台构建从工程初始化阶段持续运行，而不是发布前补做。
- 内部发布按“只读扫描 → 导入与恢复 → 播放 → 管理与系统集成 → 候选版”逐级开放。
- 0.1.0 首个公开数据库 schema 必须可由后续顺序迁移升级；禁止发布后改写既有 migration。
- 若候选版发现文件写入风险，保留扫描/播放只读能力并关闭导入/删除入口，不能以已知覆盖风险发布。
