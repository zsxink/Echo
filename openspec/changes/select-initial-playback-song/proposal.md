## Why

启动时如果没有可恢复的当前歌曲，底部播放栏会保持空状态，即使资料库已经有可播放歌曲，用户也无法立即辨认当前的待播放对象。首次导入、重装后重新打开资料库，以及上次播放歌曲被外部删除，都是同一个产品缺口：系统需要基于资料库中最新的入库事实建立一个暂停的初始播放项，而不是自动播放或继续引用失效歌曲。

## What Changes

- 当资料库为空时继续展示真正的空播放状态，不虚构歌曲或队列项。
- 当用户导入第一首歌曲时，自动将该歌曲设为当前选中/待播放项；不自动开始播放。
- 当应用在本机没有可恢复的有效当前歌曲，但重新打开或重建一个已有资料库时，按 `added_at` 选择最新导入的可用歌曲作为当前选中/待播放项。
- 当已恢复的上次播放歌曲已被 Echo 外部删除时，清理失效当前项，并选择最新导入的可用歌曲作为当前选中/待播放项。
- 初始选择应建立非空播放队列投影并更新常驻播放栏，但不得改变用户已有的播放设置或自动发声。
- 保留有效播放会话的既有恢复行为；本变更不重新设计播放队列导航、播放历史或资料库删除语义。

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `desktop-playback`: 补充无有效当前歌曲时的初始播放项选择、首曲导入后的选中状态与失效恢复行为。
- `library-experience`: 补充首次导入后资料库与常驻播放栏之间的非空选中状态衔接。

## Impact

- 影响桌面播放会话初始化、资料库重建/启动恢复以及导入完成后的 UI 状态同步。
- 复用现有歌曲 `added_at`（最近添加）排序与稳定歌曲 UUID；不新增 SQLite 字段、资料库对象字段或同步协议。
- 可能涉及 `crates/echo-desktop` 的播放会话/队列适配、`crates/echo-core` 的候选歌曲查询，以及桌面 React 导入完成后的状态刷新；Core 仍不依赖 UI 或播放器。
- 验证需覆盖空资料库、首次导入、重装/新设备重开资料库、外部删除当前歌曲、不可用歌曲过滤和“不自动播放”约束，并遵守 `openspec/CODE_STANDARDS.md`。
