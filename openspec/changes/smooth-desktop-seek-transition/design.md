## Context

`echo-desktop` 的播放 actor 将 Seek 立即转成 libmpv 的 `seek <pos> absolute`，只对加载中的定位保留最后一个目标。暂停/继续和停止写 `pause`，换曲走 `loadfile replace`；音效预放变化是独立环节，不是定位淡变。现有烟测使用 `ao=null`，只验证命令和状态，不能验证音频。

固定库为仓库随附的 libmpv 0.36.0 / FFmpeg 6.0，macOS dylib SHA256 为 `536cc29610c2cb105671fa92a5dfac00a483f534899c5f5884b1cd55ca4d855d`。437 Hz、48 kHz、16-bit、25% 满量程正弦源的最大相邻采样差为 469。五次定位到 62.431 s 均有执行及恢复日志；PCM 最大差为 11,298 / 14,908 / 637 / 12,933 / 7,185。对已知断点离线施加对称 10 ms 渐变后为 466–468，证明测量方法和增益过渡方向，而不是运行时修复。当前执行环境没有可用 CoreAudio 输出；非实时 PCM 写入不可替代真实输出时序。

## Goals / Non-Goals

**Goals:** 同一桌面播放会话中，从每个已有入口触发的播放中定位得到统一保护；保留状态权威、配置、故障恢复和加载代际语义。命令处理不因淡变睡眠或忙等。

**Non-Goals:** 不为暂停、停止及切歌独立增加淡变，不做无缝交叉淡变，不改拖动交互，不改变音轨 DSP、归一化、输出设备设置、协议、持久化或移动端。

## Decisions

1. **桌面 actor 中用有限状态机编排。** 通过现有 Backend 端口增补最小内部能力，libmpv 细节留在适配器。显式阶段为 Idle、FadeOut、AwaitRestart、FadeIn，由单调时钟驱动；初始试验每侧约 10 ms，按真实运行证据调整。优先复用已有原生增益机制，不自写 PCM DSP。将用户增益和瞬时过渡视为两个逻辑轴。如果底层只能用共享音量属性，适配器须合成有效增益并隔离自身属性回执，不让回执污染权威用户音量。不得借用用户 mute 或音效预放节点作为过渡开关。首选先验证 libmpv 0.36.0 在原生 ReplayGain 关闭时的独立软增益入口（`replaygain-fallback`，常态 0 dB，须确认不会与 Echo 的归一化、平台版本或用户配置冲突）。若不可用，评估常驻具名单独增益节点；不能在每次定位时重建音效图。任选方案均须验证运行时命令确实驱动输出，不从 API 接受推断。
2. **先压低，再定位，再等待确认。** libmpv v0.36.0 的输出可能先于 `PLAYBACK_RESTART` 启动，因此不能等事件到了才压低；提交 seek 前须已申请低增益。用寻址事件与恢复事件顺序、当前加载代际和在途序号保护；最多一个在途定位，不能仅凭任何一个无关联重启事件提前淡入。命令接受只允许提交权威目标位置，不等于已经可释放保护。
3. **全程有界。** 最新目标替换尚未提交的定位，在途期间保留最多一个最新目标；恢复确认后可保持低增益继续到最后目标。失败、等待超时、用户暂停/停止、加载代际变化与结束都取消旧状态，按最新用户设置尝试归还增益；适配器要检查实际写入，不得把失败当作恢复成功。支持一次或有界重试，记录降级，不能永久把播放器留在衰减状态。暂停/静音状态定位无需引入自动恢复。
4. **证据分层。** Mock 后端测试排序、异常与时钟边界；带生产事件和增益实施的实时数字采集比较单次和快速定位，记录候选库与设备。对照必须包括未修基线及正常连续音，不只验证命令接受。普通离线 PCM 抽样和离线 taper 只能作诊断正对照。没有可用设备时标注原生验收未完成，不以此声称听感修复。

## Risks / Trade-offs

- mpv 的软音量增益并非逐采样更新，已入设备缓冲的数据未必受新增益控制。实时采集若仍出现异常跳变，需要调整原生保护方式，不以属性回执代替音频证据。
- 淡变和等待带来定位延迟；规则只留最后目标、限制超时，不积压拖动。公开音量与底层有效增益分离，降低系统媒体控件和多入口同步回归风险。
- 不升级 libmpv、不新增第三方依赖。真正无法提供保护的后端需显式安全降级。
