## Why

Echo 的桌面端已有本地导入、后台运行和文件关联的产品基础，但当前打包身份、导入吞吐与反馈、时间记录，以及 macOS 菜单栏控制尚未达到可日常使用的标准。此次变更使这些既有流程在大量音乐导入、后台播放和从 Finder 打开单个文件时保持快速、准确且不打扰用户。

## What Changes

- 将所有打包和原生可见应用身份统一为精确的 `Echo`（大写 E）。
- 完成一个紧凑的 macOS 菜单栏状态控件：“上一首、播放/暂停、下一首、Echo 黑色品牌图标”按此顺序全部常驻于菜单栏本身，控件内部划分四个互不重叠的点击区域，不再使用四个分散状态项、下拉菜单或弹出控制面；传输控制与唯一桌面播放会话保持同步，点击 Echo 图标只会打开或聚焦唯一主窗口。
- 将多文件导入改为有界多线程处理，确保至少两个文件的复制、哈希或解析阶段可以真实重叠；导入按钮直接打开系统文件选择器，并在执行期间显示“导入中…”，不再显示进度对话框。
- 将导入完成反馈收敛为明确分流：成功、重复、重名后成功及正常跳过通过非阻塞 toast 汇总；无法导入的项目才进入失败详情对话框；混合批次同时保留成功汇总和失败详情。
- 审计并复用现有导入、收藏、歌单创建及歌曲加入歌单的时间字段，保证写入真实系统时间、重复操作不错误重置，并在需要呈现时按当前系统时区转换；不重复新增同义时间字段。
- 将所有 Finder/文件管理器双击打开请求建立为仅含被打开歌曲的一项播放队列：立即播放且不触发导入；资料库内文件可复用既有歌曲身份，资料库外文件保持会话临时项。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `desktop-app-shell`: 统一桌面身份，并明确 macOS 菜单栏常驻的横向传输控制、Echo 品牌图标及主窗口单例行为。
- `desktop-playback`: 所有系统文件打开请求必须替换为只含被打开歌曲的一项队列。
- `safe-file-ingestion`: 定义可证明的有界多线程导入与唯一的批次反馈分流。
- `local-library`: 审计并保证现有歌曲导入时间是真实且稳定的事实来源，并按当前系统时区呈现。
- `library-experience`: 审计并保证收藏时间来自真实提交时刻，重复操作语义正确。
- `playlist-management`: 审计歌单创建时间与成员加入时间，同时保持追加顺序与去重语义。

## Impact

- 桌面 Tauri 配置、macOS 打包元数据和原生菜单栏控件；桌面播放器事件、命令桥接与单例主窗口生命周期。
- `echo-core` 的导入用例、现有 SQLite 时间字段及读写语义、歌曲/收藏/歌单记录和可测试时钟边界；预计不需要新增时间字段或迁移。
- React 导入入口、toast/失败详情、类型化 IPC 生成物与 E2E mock。
- 受影响实现必须遵守 `openspec/CODE_STANDARDS.md` 的分层、迁移、受控阻塞任务、类型化 IPC 与验证要求；不引入流媒体、账户、同步策略或外部文件自动导入。
