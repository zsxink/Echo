# Spec Delta

## Purpose

让用户在局域网中以一台主设备、多台从设备共享整个 Echo 音乐库。所有设备均保有独立本地副本并能离线使用，主设备统一确认变更，保证双向传播、明确冲突、可信访问和故障后可恢复，同时保持平台播放器与共享业务核心分离。

## ADDED Requirements

### Requirement: 单主多从的完整资料库同步

系统 MUST 允许用户将活动资料库设为主库，或作为从设备加入唯一主库。主从设备均 MUST 能修改本地资料库；跨设备交换 MUST 经唯一主设备确认，从设备不得自行成为第二主设备。同步 MUST 覆盖音频、侧车歌词、用户封面和覆盖资源、歌曲、收藏、歌单、成员及顺序、入库时刻、播放统计和墓碑。SQLite、本机路径、凭据、缓存、偏好、播放会话及暂存文件 MUST NOT 作为共享资料传播。

#### Scenario: 从设备之间经主设备传播
- **WHEN** 从 A 导入音乐并建立收藏和歌单，主设备与从 B/C 同处可达局域网
- **THEN** 主设备确认后 B/C 获得相同逻辑 UUID、收藏与歌单引用及校验后的媒体，A 收到主规范结果，后续再次同步不产生重复对象

#### Scenario: 主设备自身修改
- **WHEN** 用户在主设备修改资料库
- **THEN** 修改使用与从设备相同的确认规则并向全部已授权从设备传播，没有绕过裁决的特殊写入路径

#### Scenario: 共享内容边界
- **WHEN** 用户检查完整同步传输内容
- **THEN** 内容包含全部存活共享对象及用户资源，不包含 SQLite、绝对路径、私钥/凭据、主题/EQ/队列等本机状态、临时播放项或 echo/tmp

### Requirement: 显式启用与可信设备加入

系统 MUST 默认关闭发现、监听和同步通信；用户明确启用后才可发现或手动连接局域网主设备。发现结果 MUST NOT 授予信任。配对 MUST 允许从设备输入主机局域网 IP 和主机直接显示的六位短期验证码；验证码有效后，设备通过一次性配对连接交换主机 TLS 证书和按资料库隔离的独立设备凭据，并固定该证书用于后续加密连接。验证码 MUST 单次使用、有效十分钟并由主机自动刷新；主机 MUST 在验证码验证成功后自动完成授权，不要求主机逐台审批。主设备 MUST 能立即撤销设备访问。

#### Scenario: 同步关闭时离线运行
- **WHEN** 用户未启用局域网同步而启动 Echo 或编辑本地音乐库
- **THEN** 没有发现/监听/连接流量，全部本地能力正常工作，变更可保存在本机等待未来启用

#### Scenario: 手动输入地址和验证码加入
- **WHEN** 新设备输入主机可达的局域网 IP 和仍有效的六位验证码
- **THEN** 主机自动完成配对，返回 TLS 身份材料和该设备独立凭据；新设备保存证书 pin 后连接并开始同步，不需要复制邀请文本或主机审批

#### Scenario: 错误、过期或已使用验证码
- **WHEN** 输入错误、过期或已使用的验证码
- **THEN** 配对失败，不授予库读取或写入权限，不覆盖原绑定或资料库；成功配对后，后续连接必须验证已交换并固定的主机证书

#### Scenario: 配对请求因其他原因失败
- **WHEN** 配对请求因主机限流、主机安全存储不可用、网络/TLS 故障、主机拒绝或响应不兼容而失败
- **THEN** 界面 SHALL 显示与失败类别相符的提示，不得将这些原因误报为验证码错误；日志和界面不得暴露验证码、bearer 凭据或私钥

#### Scenario: 已绑定资料库加入另一主机
- **WHEN** 用户尝试用已绑定到其他同步身份的本地资料库加入新主机
- **THEN** 配对授权成功后系统自动撤销并清理原同步身份，再将资料库绑定到新主机；原本地音乐与目录数据保留至新主机快照验证完成，不要求用户手动解除原绑定

#### Scenario: 同步传输失败分类
- **WHEN** 配对完成后的同步因主机不可达、主机拒绝或响应不兼容而失败
- **THEN** 界面分别说明连接、主机拒绝或协议类别，不得将远端请求错误统一显示为内部 worker 故障

#### Scenario: 同步停滞与并发操作错误分类
- **WHEN** 同步因来源 mutation 前驱未确认而无法推进，或远端媒体发布尚未就绪
- **THEN** 界面 MUST 说明对应的阻塞原因，不得误报为另一项操作正在运行；真正的手动并发和取消仍使用忙碌/取消状态，并记录用于定位队列停滞的 mutation 与游标信息

#### Scenario: 配对响应丢失后重试
- **WHEN** 主设备已持久化某设备的授权与凭据，但首次配对响应在该设备保存凭据前丢失，用户再次使用有效验证码让同一设备身份加入
- **THEN** 主设备 MUST 返回该设备当前仍有效的同一凭据，使重试可完成；不得将该设备误报为重复设备、撤销已有凭据或在仍有效的请求失败时移除其活动认证

#### Scenario: 撤销与跨库访问
- **WHEN** 已撤销设备继续请求同步，或设备请求未授权资料库的对象/资源
- **THEN** 所有此类请求被拒绝，在途会话终止，其他设备不受影响，已下载的本地副本不会被远程擦除

### Requirement: 首次加入本地优先合并

系统 MUST 用固定一致性水位的版本化对象快照建立首次副本，再追赶该水位之后的增量。目标目录 MUST 绑定主 library_id 并保留原对象 UUID，不能按本机目录生成另一份库身份。系统 MUST 接受已由 Echo 管理且包含歌曲的本地资料库；配对时 MUST 保留本地逻辑目录、portable 记录和媒体文件，将本机对象先写入 durable outbox，再把主机快照合并到本地。身份变更、退出、重新加入和快照失败 MUST NOT 清空本地数据或移动媒体。冲突 MUST 进入既有对象冲突解决流程，不得静默丢弃本地对象。新主机资源发布仍须遵守已有文件的哈希/冲突保护；对于未登记的非 Echo 文件，不得自动清除或覆盖。首次构建完成前 MUST 禁止编辑但允许浏览及播放已就绪媒体，完成仅在追平本次目标水位及其存活资源全部就绪后成立。

#### Scenario: 新设备完整恢复
- **WHEN** 从设备选择空目录加入主库
- **THEN** 获得相同 UUID、收藏、歌单和成员顺序、入库时刻及播放统计，全部媒体校验落盘后可离线播放，不依赖源设备绝对路径

#### Scenario: 已有歌曲的本机资料库加入主机
- **WHEN** 用户明确让包含歌曲的 Echo 资料库加入主机，且目标主机快照完整通过验证
- **THEN** 本机目录数据仍然保留；本地对象进入待同步队列，主机对象合并到本地，任何本地记录或媒体文件都不会因配对而被清理

#### Scenario: 首次同步期间主库新增歌曲
- **WHEN** 首次快照生成后主设备继续导入或编辑
- **THEN** 从设备先获得固定快照再应用之后的变更，不漏记录、不混用快照分页、不重复分配 UUID

#### Scenario: 未登记的非 Echo 文件
- **WHEN** 用户选择包含其他文件或不同资料库的未登记目标目录
- **THEN** 系统不得自动删除/覆盖这些文件或合并不同资料库；原本机资料库保持可用

#### Scenario: 首次快照失败或取消
- **WHEN** 已有歌曲的本机资料库正在加入主机，但快照验证失败或用户取消
- **THEN** 本机原有逻辑目录数据保持可用，未产生半应用的主机目录

#### Scenario: 对象先于媒体到达
- **WHEN** 从设备已有歌曲资料和歌单成员而文件尚未完成下载
- **THEN** 歌曲标记为不可用，保留所有关联，媒体校验完成后恢复可用，不创建第二首歌曲

### Requirement: 离线修改与增量幂等确认

系统 MUST 持久化本地待确认变更及稳定事件身份，主设备按库内递增确认序列裁决并记录结果。相同事件重试 MUST 返回同一结果，相同身份不同内容 MUST 被拒绝。每个从设备 MUST 独立记录已应用水位；远端应用不得产生回传新事件，来源设备也 MUST 应用主规范结果。下载主状态 MUST NOT 擦除更晚的未确认本地修改。

#### Scenario: 主设备离线
- **WHEN** 主设备关机、睡眠或网络不可达，从设备继续添加音乐、收藏或编辑歌单
- **THEN** 本地变更可读取且持久化排队，已落盘歌曲可播放，界面说明等待主设备，重连后传播到主设备和其他从设备

#### Scenario: 确认响应丢失
- **WHEN** 主设备持久化事件结果后连接断开，从设备重复提交同一事件
- **THEN** 主设备返回原结果，只存在一次业务效果和确认记录，不重复增加播放统计或歌单成员

#### Scenario: 本地连续编辑与回拉
- **WHEN** 从设备对同对象连续离线编辑，并在提交过程中收到主设备较新状态
- **THEN** 本地顺序和前驱关系保留，更晚本地候选不会被下载快照抹掉，每条提交得到明确结果并最终与主规范状态收敛

#### Scenario: 接收不制造回环
- **WHEN** A 的变更经主传播给 A/B/C 且系统监听到同步产生的本机文件事件
- **THEN** 各设备只应用主结果，不生成等价的新上传变更，空闲时待确认队列收敛为空

#### Scenario: 迟到确认与拒绝前驱
- **WHEN** 从设备已应用较新版本后收到旧事件ACK，或本地变更前驱被主拒绝
- **THEN** 旧ACK只终结匹配待确认事件，不回退当前对象或游标；因对象或作者校验失败而终态拒绝的、顺序正确的事件同时推进主端来源游标，使其后继仍可确认；旧版本已保存拒绝结果但漏推进游标时，主可依据后继携带的直接前驱 ID 补齐单步缺口；真正缺失前驱的事件保持可重试，不导致永久阻塞或丢弃候选

#### Scenario: 控制面发布未完成
- **WHEN** 主已提交确认事务但控制面或资源安全发布尚未完成
- **THEN** 首次或重复提交均不提前返回完成确认，快照/增量不暴露未发布结果，恢复后从连续可见水位继续

### Requirement: 可解释的冲突与删除裁决

系统 MUST 将本地 revision 与主确认版本分离，以主确认顺序裁决存活对象的最后确认写入，不依赖墙钟。不同对象独立合并；同对象基线过期时 MUST 保存冲突双方内容和用户资源供查看/恢复。收藏 MUST 与歌曲元数据独立，播放统计 MUST 按设备单调计数合并，歌单成员 MUST 保持确定的追加顺序和既有不重复歌曲约束。成员去重 MUST 持久化 typed alias 并随结果、日志及快照传递，原子重映射从端可见身份和未发送候选，已发送事件正文不得改变。墓碑 MUST 按对象类型与 UUID 识别；主确认的最终歌曲删除 MUST 终结该 UUID，清理其可见关联，陈旧修改不得复活。现有 10 秒撤销窗口 MUST 保留，窗口内删除仅为本机意图，不得作为最终墓碑或共享隐藏状态传播；撤销与逻辑终结 MUST 原子竞争唯一终态，只有窗口结束且逻辑终结提交后才生成稳定删除事件，物理废纸篓清理由 journal 独立恢复。

#### Scenario: 同对象并发修改
- **WHEN** A/B 基于相同已确认版本修改同一歌单名称，两个事件依次由主确认
- **THEN** 后确认名称在所有设备生效，系统记录基线冲突、双方名称与确认次序，用户可将普通输家值恢复成新的修改

#### Scenario: 收藏标签统计互不覆盖
- **WHEN** 设备分别修改同一歌曲标签、切换收藏，并各自产生播放次数
- **THEN** 标签不会覆盖收藏或统计，统计为逐设备累计桶合并之和，重试和重复下载不会增加计数

#### Scenario: 删除后旧设备重连
- **WHEN** 主已确认歌曲删除，离线设备提交该 UUID 的旧编辑或成员关联
- **THEN** 歌曲不复活，旧编辑得到明确拒绝/冲突结果，悬空关联不出现在有效歌单中；显式重新导入采用新 UUID

#### Scenario: 对象种类区分
- **WHEN** 收藏、覆盖层与歌曲记录共用同一歌曲 UUID，系统收到其中一种对象的删除
- **THEN** 删除按对象类型生效，不误删其他类型；歌曲级删除另按明确级联规则执行

#### Scenario: 撤销窗口内删除并撤销
- **WHEN** 主或从设备删除歌曲，1 秒后在有效撤销窗口内撤销，期间运行同步或生成快照
- **THEN** 本机恢复原 UUID、收藏、统计及成员，主没有确认该意图的最终墓碑；快照/增量仍提供最后有效对象和受控暂存资源，不生成删除后复活事件

#### Scenario: 删除窗口内重启与终结竞争
- **WHEN** 应用在撤销窗口内重启，或撤销请求与窗口结束后的逻辑终结竞争，终结 ACK 又丢失
- **THEN** journal 先恢复唯一操作状态；未终结且窗口有效时可撤销，已终结时只能新 UUID 重新导入；最终删除只生成一个稳定 mutation，重试不重复级联，窗口内意图不进入历史基线

#### Scenario: 删除意图遇到远端最终删除
- **WHEN** 本机仍持有可撤销意图时收到主已确认的该歌曲最终墓碑
- **THEN** 更新确认基线并终结原 UUID，保留本机暂存资料供显式新 UUID 恢复，本机撤销不能复活远端已终结对象

#### Scenario: 未确认导入后最终删除
- **WHEN** 从设备离线导入歌曲后删除并超过撤销窗口，或导入 ACK 丢失后进行最终删除
- **THEN** 物理清理不能移除未确认/已发送事件或活跃快照等持久引用需要的唯一资源副本；重连先上传/确认导入前驱，再确认删除，事件身份不变且最终各端歌曲隐藏，崩溃恢复后引用约束仍有效

#### Scenario: 重复成员去重后删除
- **WHEN** A/B 对同歌单同歌曲分别追加成员 X/Y，主保留 X 并映射 Y，B 删除 Y，包括尚未收到添加 ACK 时已排队的删除
- **THEN** 主按成员映射删除 X，所有设备只保留同一删除事实；去重与映射可在重启/快照后恢复，已发送事件重试正文保持不变

#### Scenario: 成员重新添加遇到旧删除
- **WHEN** 规范成员 X 已删除，同歌重新添加为 Z，旧 alias Y 的删除随后重试或迟到
- **THEN** Y 仍映射到 X 的墓碑，不删除 Z；Z 使用新 UUID 和新追加次序，各端成员身份和顺序一致

#### Scenario: 重复内容与文件名冲突
- **WHEN** 多设备同时导入相同内容或同路径不同内容
- **THEN** 相同内容收敛为主确认的歌曲身份且所有引用一致，不同内容保留安全独立目标路径，任何已有无关文件不会被覆写

#### Scenario: 别名后续编辑与重导入
- **WHEN** 相同内容导入已经形成UUID映射，随后原UUID提交编辑/删除或用户重新导入已删除歌曲
- **THEN** 旧UUID按映射正确处理依赖及墓碑，已删除的规范UUID不能吸收新导入，新UUID不会被旧别名复活或删除

#### Scenario: 单机媒体缺失
- **WHEN** 某设备音频被外部删除或所在卷暂时断开
- **THEN** 只改变该设备本机可用状态，不传播用户删除，其他持有完整媒体的设备保持可播放

### Requirement: 校验传输与故障恢复

系统 MUST 按内容哈希传输音频与用户资源，支持大文件断点续传、暂停、重试和资源去重。主确认依赖完整有效资源；接收端只有在全文件长度/哈希校验及安全发布完成后才可播放。非法路径、越界符号链接、资源超限、跨库哈希读取、磁盘满、权限失效、文件外部变化 MUST 明确失败并保留既有有效内容。文件操作与对象应用 MUST 可在崩溃后恢复且不重复副作用。

#### Scenario: 大文件断线续传
- **WHEN** 文件传输一半断网或应用重启
- **THEN** 已校验块可复用，恢复后继续传输，完成的全文件 BLAKE3 与声明相同，重复请求不产生额外歌曲

#### Scenario: 文件变化或校验失败
- **WHEN** 传输源文件变化、下载哈希不符，或目标文件已被外部程序修改
- **THEN** 该版本不发布，旧内容和外部修改被保留并报告错误/冲突，系统不会将错误文件标记为可用

#### Scenario: 空间权限与路径攻击
- **WHEN** 接收遇到空间不足、只读根目录、目录逃逸、符号链接越界或超限资源
- **THEN** 拒绝不安全发布，不破坏原媒体或已提交对象，显示可重试或需用户处理的原因，不提供任意文件读取能力

#### Scenario: 正在播放的文件不能替换
- **WHEN** 平台拒绝替换当前正在播放的媒体
- **THEN** 保持播放并将新版本发布挂起，文件可安全替换后恢复，不提前报告已同步

#### Scenario: 对象水位与媒体完成分离
- **WHEN** 元数据已应用到目标水位但尚有媒体待下载
- **THEN** 状态仍为同步中，已就绪音乐可播放，不因元数据游标推进而错误报告完整同步

### Requirement: 协议兼容和账本恢复边界

系统 MUST 在传输前验证协议、资料库格式、主身份和 epoch。历史库升级 MUST 保留 UUID、数据和未确认变更；不兼容客户端不得写入。续传检查点 MUST 包含已应用序列与日志摘要并与对象投影同事务持久化，日志摘要链和快照水位摘要 MUST 可校验；旧 epoch、不存在的游标或同序列不同摘要 MUST NOT 被视为正常续传。主 MUST 在开放服务前核对独立于资料库/账本备份的安全存储发布检查点，只有控制面/journal、独立检查点和 published 水位均持久化后才可对外暴露确认结果。显式主备份恢复 MUST 总是更换 epoch；账本丢失、不可恢复的检查点不一致或从设备检测到分叉时 MUST 阻止旧会话续传，重新建立信任及基线，保留各端尚未确认内容供显式恢复。墓碑与已确认结果在首版 MUST NOT 自动过期导致重复提交或复活。整机及全部独立检查点共同回退不在自动检测承诺内，恢复流程 MUST 要求用户经显式入口建立新 epoch。

#### Scenario: 历史库启用同步
- **WHEN** 当前版本读取并升级历史可携带资料库后启用主服务
- **THEN** 原 UUID、收藏、歌单、统计和入库时刻不丢失，形成一致初始基线，历史 outbox 不作为旧编辑覆盖该基线

#### Scenario: 旧客户端或错误主身份
- **WHEN** 客户端格式不兼容或连接身份/epoch 不符
- **THEN** 拒绝增量写入，保留本地副本与待确认变更，说明升级或重新配对需求

#### Scenario: 主设备旧备份恢复
- **WHEN** 用户经恢复入口恢复主备份，无论备份账本完整或仅对象可恢复
- **THEN** 服务停止并保留恢复资料，主建立新 epoch，从设备不能误用旧游标，未确认内容保留且明确提示重新配对/完整对账与恢复边界

#### Scenario: 对象与账本共同回退
- **WHEN** 主对象和账本被替换为相同旧备份，而独立发布检查点仍指向较新序列或不同摘要
- **THEN** 主在监听前拒绝继续旧 epoch，不覆写检查点或复用已发布序列，要求显式恢复；缺失/不可读检查点同样先阻止服务

#### Scenario: 发布检查点崩溃窗口
- **WHEN** 独立检查点已持久化但 published 标记前崩溃，或安全存储写入失败
- **THEN** 未完成完整发布时不对外 ACK 或暴露快照/增量；重启核对相同账本和 journal 后补齐 published，正常崩溃不要求换 epoch，写入失败暂停发布且可重试

#### Scenario: 同序列日志分叉
- **WHEN** 从端保留的序列摘要与主同序列摘要不符，或从端序列高于主可见水位
- **THEN** 该会话停止提交和拉取应用并保留本地副本/候选，不返回已追平或空增量成功，提示主恢复新 epoch；快照水位与增量摘要链均不可跳过验证

### Requirement: 同一应用内的资料库同步上下文隔离

系统 MUST 为同一应用配置文件中的每个本地资料库保存独立的同步绑定、设备凭据引用、待确认变更、设备游标、提交序列和恢复检查点。切换活动资料库 MUST 停止旧库同步服务并恢复新库自己的上下文；未绑定的新库可以建立新的主或加入其他主。切换不得覆盖、清空或混合其他资料库的身份、设备、变更队列和提交历史。

#### Scenario: 为另一资料库启动同步
- **WHEN** 用户切换到同一应用内另一可写资料库，并首次将其设为主库或加入主库
- **THEN** 系统为该本地资料库创建独立同步上下文，不因另一资料库已有绑定而拒绝启动，也不复用另一资料库的设备授权或提交历史

#### Scenario: 切回已绑定资料库
- **WHEN** 用户切回已有同步绑定的本地资料库
- **THEN** 系统恢复该库原有身份、设备、待确认变更、游标、提交链及检查点；其他资料库的同步状态保持不变

#### Scenario: 库切换期间本地修改
- **WHEN** 用户在某资料库未运行同步时继续本地编辑，之后再次启动该库同步
- **THEN** 新修改进入该库自己的队列并沿其原有前驱链确认，不被其他资料库的队列或游标阻塞

### Requirement: 状态可访问且不打断本地使用

系统 MUST 通过类型化边界显示角色、主连接状态、上传/下载进度、待确认数、暂停/重试及冲突入口，区分关闭、首次建立、已同步、离线和错误。只有达到本次目标对象水位、资源完整且没有待确认变更或阻塞错误才可显示已同步。关闭窗口遵循本机偏好，后台可继续同步，显式退出 MUST 停止服务并持久化进度。网络权限拒绝 MUST NOT 阻止本地浏览和播放。

#### Scenario: 暂停与重试
- **WHEN** 用户暂停同步或处理网络错误后重试
- **THEN** 已提交内容不回滚，本地编辑继续排队，恢复从已持久化进度开始；提示说明实际完成状态

#### Scenario: 后台与退出
- **WHEN** 用户按既有偏好关闭主窗口或显式退出
- **THEN** 后台模式保持服务，退出结束监听与可追踪任务；重启保留绑定和进度且不自动播放

#### Scenario: 三平台权限失败
- **WHEN** macOS/Windows/Linux 拒绝局域网权限或防火墙阻断
- **THEN** 显示同步原因及下一步，本地资料库和播放器仍能使用，WebView 不获得直接网络或文件访问权限

### Requirement: 共享核心边界和发布证据

系统 MUST 由共享业务核心执行身份、冲突与恢复规则，平台/UI不得复制领域裁决或直读 SQLite。生产边界 MUST 遵守工程规范 §3–§6、§8–§9：向内依赖、传输与平台能力通过端口接入、类型化可版本化协议、顺序迁移及可追踪后台生命周期。交付 MUST 包含格式/静态检查/测试/构建、协议与迁移契约、主加两从传播和三平台原生验证证据。

#### Scenario: 自动与原生验证
- **WHEN** 本能力准备交付
- **THEN** cargo fmt/clippy/test、前端 format/lint/typecheck/test/build、IPC/架构门禁与 openspec strict validate 通过；主加两从并发、断线、重试、删除、冲突及三平台安装包权限/监听/播放回归均有可重复证据，未知项不得宣称已验证
